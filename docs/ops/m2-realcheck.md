# M2 실기 확인 (묶음 4 · 묶음 5 · M2-17)

사람이 기기를 비워 줄 때 한 번에 돌릴 것과, 사람이 직접 볼 것. 대상은 M2-13 · M2-14 · M2-15(묶음 4), M2-16 · M2-18 · M2-19 · M2-20(묶음 5), M2-17 이다. 측정이 무엇을 어떻게 재는지는 `CONTRIBUTING.md` 「성능 기준선」 의 「git 시나리오」 절이 정본이다 — 이 문서는 그 절차를 한 번 돌리는 운영 메모이고, M2 의 실기 확인이 끝나면 지운다.

## 1. 측정 — 한 명령

### 돌리기 전에

1. **화면이 잠기지 않았는지** 본다: `ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked` 가 `<false/>` 이거나 아무것도 안 나와야 한다. 잠겨 있으면 하네스가 시작하지 않는다.
2. **「화면 보호기 시작」 을 「안 함」 이나 1시간 이상으로** 둔다(시스템 설정 → 잠금 화면). 하네스가 측정 동안 `caffeinate` 로 디스플레이 · 시스템 잠자기는 막지만, 화면 보호기 뒤의 잠금까지 막는지는 확인하지 않았다.
3. 측정 중에는 **기기를 쓰지 않는다.** 프로젝트 창이 회마다 한 번 앞에 뜨고 2분 반쯤 머문다 — 그 창을 다른 창으로 가리거나 다른 Space 로 옮기면 그 회는 제외된다(`hidden`).
4. 저장소가 준비됐는지 본다(없거나 옛 픽스처면 태스크가 지우고 다시 만든다, 저장소마다 20~60초): 두 저장소(`target/perf-git/graph` · `no-graph`) 각각에서 `git -C <저장소> rev-parse --verify perf-checkout` 와 `git -C <저장소> cat-file -e main:perf/typing.rs` 가 성공해야 한다. 묶음 4 때 만든 저장소에는 `perf/typing.rs` · `perf/many` 가 없어 다시 만들어진다.

### 명령

```bash
mise run perf-git
```

- 하는 일: release 번들(`target/release/bundle/macos/Pitwall.app`)을 만들고 → 저장소 둘(commit-graph 있음 · 없음) × (준비 1 + 측정 5)회. 회마다 임시 `PITWALL_*_DIR` 로 앱을 띄우고 pid 로 끈다 — 사람의 설정 · 데이터 · 다른 Pitwall 은 건드리지 않는다. 회 안의 차례: ⌘9 Git 로그 → 10만 행 스크롤 → 1만 줄 diff → 체크아웃 → Git 로그 접기 → 트리에서 `perf/typing.rs` 열기 → 한 줄 고쳐 거터 표시 → 30초 타이핑(넣은 글자는 지운다, 저장하지 않는다) → 하네스가 `perf/many` 의 파일 1만 개를 고침 → ⌘0 커밋 목록 스크롤 → 하네스가 `git add` 한 파일이 스테이징됨으로. 회가 끝나면 하네스가 `perf/many` 를 되돌리고 `main` 으로 돌려놓는다(저장소는 `target/perf-git/` 의 합성 저장소뿐이다).
- 걸리는 시간: 번들 빌드(코드가 바뀌었으면 5~10분, 그대로면 1~2분) + 저장소를 다시 만들면 1~2분 + 측정 약 28~32분(회마다 2분 반쯤). **모두 합쳐 35~45분.**
- 앱이 앞으로 뜨는 횟수: **12번**(프로젝트 창, 저장소 2 × 6회). 웰컴 창은 뜨지 않는다.
- 키 입력: **OS 키 입력을 보내지 않는다.** ⌘9 · ⌘0 · 더블클릭 · ⌃⌥⇧↑ 은 웹뷰 안에서 만든 이벤트이고, 타이핑은 에디터에 `view.dispatch` 로 넣는다. 체크아웃 · 파일 고치기 · `git add` 는 하네스가 저장소에서 한다. 측정 도중 화면이 잠겨도 잠금 화면에 글자가 들어가지 않는다. 잠긴 회는 WebKit 이 프레임을 미뤄 시나리오가 멈추므로 420초 시간 제한에 걸려 **실패 회**로 적히고(잠금이 그 안에 풀리면 끝까지 가되 제외로), 하네스는 그 회의 앱을 pid 로 끄고 다음 회로 간다.
- 잠자기: 하네스가 `caffeinate -d -i -m -w <하네스 pid>` 를 띄운다 — 하네스와 함께 끝나고, 다른 프로세스는 건드리지 않는다.
- 앱 고르기 · 끄기: 하네스가 띄운 pid 와 그 책임 프로세스 묶음으로만 고르고, AppKit 종료 → SIGTERM → SIGKILL 순으로 그 pid 만 끈다(`AGENTS.md` 「데스크톱 앱은 이름이 아니라 pid 로 고르고 끈다」). 이름(`pitwall`)으로 고르거나 `pkill` 하지 않는다. Ctrl+C 로 멈춰도 진행 중인 회의 앱을 끄고 끝난다.
- 실패한 회: 멈춤(420초) · 단계 실패 · Git 로그 행 수가 저장소 커밋 수(100,003)와 다름이면 그 회를 실패로 적고 다음 회로 간다. 회가 끝날 때마다 요약을 다시 쓰므로 Ctrl+C 나 되돌릴 수 없는 실패(저장소를 되돌리지 못함 · 앱을 치우지 못함)로 멈춰도 그때까지의 요약이 남는다(머리에 `Stopped early` 와 까닭).
- 짧게 먼저 볼 때: `mise run perf-git -- --runs 1 --warmup 0`(앞에 2번 뜬다, 번들 · 저장소가 준비돼 있으면 6분 안). **5~8 단계(거터 · 타이핑 · 커밋 목록 · git add)는 이번에 처음 실기로 돈다** — 헤드리스 스모크가 그 단계를 돌지 않으므로(가짜 Host 에 그 상태가 없다) 긴 측정 전에 이것부터 돌려 끝까지 가는지 본다. 단계가 실패하면 하네스가 그 단계 이름(`gutter` · `typing` · `commit list` · `stage`)과 까닭을 적고 그 회를 끝낸다.

### 끝나면

- 결과: 마지막 줄의 `target/perf/<시각>/summary.md` · `result.json`. 표의 Result 열이 `within target` / `over target` 이다. 판정(측정 회의 중앙값, 타이핑 막힘만 모든 회의 최댓값): ⌘9 → 첫 행 ≤ 500 ms(둘 다 — 결정 M2-D10), fling 프레임 ≤ 16.7 ms 몫 ≥ 0.95, 1만 줄 diff ≤ 200 ms, 체크아웃 → 상태바 ≤ 500 ms(이상 묶음 4), 한 줄 편집 → 거터 수정 표시 ≤ 100 ms, 30초 타이핑 중 가장 긴 메인 스레드 막힘이 **모든 회에서** ≤ 50 ms — 한 회라도 넘으면 `over target`(M2-17), 커밋 목록 fling 프레임 ≤ 16.7 ms 몫 ≥ 0.95, `git add` → 스테이징됨 ≤ 500 ms(M2-16). M2-18 · M2-19 · M2-20 의 완료 기준에는 수치가 없어 재지 않는다.
- 정리 확인: `pgrep -fl 'bundle/macos/Pitwall.app'` 가 비어야 한다. 종료 코드 0 이 아니면 오류 문장에 남은 프로세스 · 소켓이 붙는다.
- 보고에 적을 것: 명령, 기기(요약 머리의 hardware 줄), 커밋, 저장소별 표, 제외된 회와 그 이유, 실패한 회(「Failed run」 표)와 그 까닭.
- 함께 재면 좋은 것(M2-22): `mise run perf -- --project target/perf-git/graph` — 콜드 스타트 · 유휴 메모리를 10만 커밋 저장소 프로젝트로(앞에 6번 뜬다, 3분쯤). 결과의 `settings.project` 가 어느 프로젝트의 것인지 적는다.

### M2-22 한 번에 — `mise run perf-m2`

위 `perf-git` 와 `perf --project target/perf-git/graph` 를 차례로 돌리고 결과를 보고서 폴더로 복사한다(앱을 띄우기 직전마다 화면 잠금을 보고 잠겼으면 그 단계를 시작하지 않는다, OS 키 입력 없음).

| 단계 | 명령 | 걸리는 시간 | 앱이 앞으로 뜨는 횟수 |
| --- | --- | --- | --- |
| 1. 짧게 한 번 | `mise run perf-m2 -- --short` (둘 다 `--runs 1 --warmup 0`) | 번들 빌드(1~10분, 이후 단계는 캐시) + 6분쯤 + 1분쯤 | 2 + 1 = **3번** |
| 2. 전체 | `mise run perf-m2` | 번들 빌드 + `perf-git` 약 30분 + `perf --project` 3분쯤 → **35~45분** | 12 + 6 = **18번** |

- 1 이 끝까지 돌고(**종료 코드 0** — 3 은 유효한 회가 적다는 뜻이라 통과가 아니다, 요약에 실패 회 없음) 2 로 간다. 1 은 특히 5~8 단계(거터 · 타이핑 · 커밋 목록 · git add)가 실기에서 처음 도는지 보는 용도다.
- 결과: 각 단계의 `target/perf/m2-git[-short]-<날짜>-<시각>/` · `m2-graph-project[-short]-<날짜>-<시각>/` 에 `result.json` · `summary.md` 가 남고, 스크립트가 `docs/superpowers/reports/<날짜>-m2-perf-git[-short]-<시각>.json|.summary.md` 와 `…-graph-project[-short]-<시각>.json|.summary.md` 로 복사한다 — 시각(HHMMSS)이 붙어 같은 날 다시 돌려도 앞 결과를 덮지 않는다(같은 이름이 있으면 복사를 거부하고 1 로 끝난다). 종료 코드: 0 — 둘 다 0. **3 — 어느 단계든 유효한 회가 적었다**(결과는 복사하고 알린다, 스크립트도 3 으로 끝난다). 그 밖 — 실패한 단계 이름과 그 코드로 멈춘다(뒤 단계는 돌지 않는다).
- 보고서에 옮기는 법: `docs/superpowers/reports/2026-10-30-m2-perf-report.md` §3 의 「실기 대기」 칸을 복사된 `summary.md` 의 중앙값으로 채우고 증가분(M1 기준선 대비)을 계산한다. 목표를 넘은 항목은 §6 에 대응 행을 더한다. 복사된 json · summary 는 보고서와 함께 커밋한다.
- 이름으로 앱을 끄지 않는다 — 하네스가 pid 로 끈다. 끝나면 `pgrep -fl 'bundle/macos/Pitwall.app'` 가 비어야 한다.

## 2. 사람이 직접 볼 것 (한 장)

앱은 `mise run dev`(이 워크트리)로 띄운다. 화면 · 입력기 · 실제 외부 도구를 보는 항목이라 자동으로 재지 않는다. 각 줄: **누른다 → 보여야 한다.** 다르면 그 줄 번호와 본 것을 적는다.

**대상 저장소: 모든 행은 아래 준비 블록이 임시 폴더에 만드는 저장소, 또는 측정용 합성 저장소(`target/perf-git/graph`, 읽기만)에서 한다 — 사람의 저장소를 프로젝트로 열지 않고, 사람의 원격에 쓰지 않는다.** 예외는 「선택」 이라 적힌 19b · 20 뿐이다(사람이 고른 버리는 브랜치 하나 · 인증 확인용 fetch). 「어디서」 칸의 `[연습 원격]` · `[연습]` · `[머지]` · `[히스토리]` 는 아래 준비 블록, `[합성]` 은 `target/perf-git/graph` 다.

| # | 어디서 | 누른다 | 보여야 한다 |
| --- | --- | --- | --- |
| 1 | 웰컴 창 `[연습 원격]` | 프로젝트 행 우클릭 → 「다음에서 열기」 | 「다음에서 열기」 팝업(상단 검색 팝업). 이 OS 에서 쓸 수 있는 도구만, 기본 도구에 「기본」 표시, 설정이 틀린 도구는 이유와 함께 흐리게. 하나를 고르면 그 도구가 프로젝트 폴더로 뜬다 |

| 11 | Git 로그 `[연습 원격]`(준비가 `f1.txt` 에 커밋 안 한 변경을 남긴다) | 커밋 행 우클릭 → Reset ▸ | 하위 메뉴에 soft · mixed · keep · hard. hard 는 늘, mixed · keep 은 잃을 변경이 있을 때만 확인을 묻고, 끝나면 알림에 [되돌리기] |

연습 원격 `[연습 원격]`(1 ~ 7 · 9 · 11 · 12 · 19) — 임시 폴더에 로컬 bare 원격(`file://`)과 그 클론을 만든다. 클론을 프로젝트로 연다:

```bash
base=$(mktemp -d) && git init -q --bare -b main "$base/origin.git"
git clone -q "file://$base/origin.git" "$base/work" 2>/dev/null && cd "$base/work"
for i in 1 2 3; do printf '%s\n' "$i" > "f$i.txt" && git add "f$i.txt" && git commit -qm "commit $i"; done
git push -q -u origin main
git switch -qc feature && printf 'feature\n' > feat.txt && git add feat.txt && git commit -qm feature && git push -q -u origin feature
git switch -q main && git branch -qD feature    # 6: 원격에만 있는 브랜치
git commit -q --allow-empty -m ahead            # 5: ↑1
printf 'uncommitted\n' >> f1.txt                # 11: hard 가 잃을 변경
echo "$base/work"
```

확인이 끝나면 `rm -rf "$base"`.

머지 도구 준비 `[머지]`(13 · 14) — 충돌 난 저장소를 임시 폴더에 만들어 프로젝트로 연다:

```bash
d=$(mktemp -d)/conflict && git init -q -b main "$d" && cd "$d"
printf '하나\n둘\n셋\n' > a.txt && git add a.txt && git commit -qm base
git switch -qc other && printf '하나\n둘 (그쪽)\n셋\n' > a.txt && git commit -qam theirs
git switch -q main && printf '하나\n둘 (내 것)\n셋\n' > a.txt && git commit -qam ours
git merge other     # 충돌로 멈춘다 → 앱에서 이 폴더를 열고 a.txt 의 [병합…]
```

연습 저장소 `[연습]`(15 ~ 18 · 21 ~ 23) — 임시 폴더에 만들어 프로젝트로 열고, 신뢰를 물으면 **신뢰한다**(훅 · blame 의 git 은 신뢰한 프로젝트에서만 돈다):

```bash
d=$(mktemp -d)/practice && git init -q -b main "$d" && cd "$d"
seq 1 40 | sed 's/^/줄 /' > a.txt && printf 'b\n' > b.txt && printf 'c\n' > c.txt
git add . && git commit -qm base
sed -i '' -e 's/^줄 5$/줄 5 (고침)/' -e 's/^줄 30$/줄 30 (고침)/' a.txt   # 16: 떨어진 두 묶음
printf 'b 고침\n' > b.txt && printf 'c 고침\n' > c.txt && printf 'new\n' > new.txt
printf '#!/bin/sh\necho 훅이 거절했다 >&2\nexit 1\n' > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit   # 17
echo "$d"
```

17 의 성공하는 훅: `printf '#!/bin/sh\necho 훅 통과\nexit 0\n' > "$d/.git/hooks/pre-commit"`. 확인이 끝나면 `rm -rf "$(dirname "$d")"`.

파일 히스토리 준비 `[히스토리]`(25) — 이름이 두 번 바뀐 파일:

```bash
d=$(mktemp -d)/history && git init -q -b main "$d" && cd "$d"
printf '1\n' > a.txt && git add a.txt && git commit -qm 'add a'
git mv a.txt b.txt && git commit -qm 'a → b'
printf '2\n' >> b.txt && git commit -qam 'edit b'
git mv b.txt c.txt && git commit -qm 'b → c'
git log --follow --oneline c.txt   # 앱의 목록과 견줄 것
```

자식 프로세스 세기(24) — 이 워크트리에서 `mise run dev` 로 띄운 앱의 pid 로 센다(이름으로 고르지 않는다 — `AGENTS.md`). 0.2초마다 그 pid 를 부모로 둔 `git … blame` 수를 찍는다(Ctrl+C 로 멈춘다):

