# 16. M5 (MCP · 에이전트 연동) 작업 분할

M5 목표: **「에이전트가 IDE 만 아는 것을 묻고, 사람이 본 것만 바뀐다」 — Pitwall 이 아는 것(DB 스키마 · 쿼리 결과 · git 상태 · 진단 · 심볼 · 설정)을 MCP 툴과 같은 이름의 명령줄(`pitwall tool`)로 내놓고, 쓰기는 사람의 승인을 지난 것만 돈다.** 코드 편집은 에이전트가 파일 시스템에서 직접 하므로 툴은 「IDE 만 아는 정보와 설정」 에 머문다(05-mcp.md 머리말). 앱에 AI 를 넣지 않고 에이전트에 맡기는 길이 이 단계다(06-roadmap.md 「결정 기록」 D19). 사람이 이 단계에서 직접 물은 것 — DB 스키마 조회, 쿼리와 SQL 파일 실행, 그리고 그 전부를 명령줄로 — 이 중심이고 순서에서 뒤로 밀리지 않는다(결정 M5-D20).

이 문서는 **확정판**이다(2026-11-13 — 사람에게 물은 결정 열하나(M5-D1 ~ D11)를 모두 사람이 정했고, 메인 판정도 모두 확정이다). 미정 결정은 없다 — 각 행은 자기 선행이 병합되면 바로 시작할 수 있다(「2. 순서」).

완료 시 할 수 있는 것(사람이 손으로 확인하는 시나리오 — 1 ~ 4 는 「MVP 선」 까지, 5 ~ 10 은 그 뒤):

1. 앱에서 프로젝트를 연 채, 그 프로젝트의 Orca 워크트리 안 터미널에서 `pitwall tool list` 를 치면 툴의 이름 · 등급 · 설명이 한 줄씩 나온다. `pitwall tool git_status` 는 **그 워크트리**의 상태를 JSON 으로 stdout 에 쓰고 `echo $?` 는 0 이다(M5-03 · M5-04 · M5-05).
2. DB 탐색기에서 로컬 PG 연결을 한 번 펼친 뒤 `pitwall tool db_schema --connection-id local-pg` 로 테이블 목록을, `--object public.users` 로 열 · 인덱스 · FK 를 본다. `pitwall tool db_query --connection-id local-pg --sql 'select …'` 는 행을, `--file queries/report.sql` 은 문장마다 결과 하나를 돌려준다. 사람이 연 적 없는 연결이면 「Pitwall 에서 이 연결을 먼저 열어라」 와 종료 코드 3 이다(결정 M5-D2 · M5-06 · M5-07).
3. Claude Code 에 `pitwall mcp` 를 등록하고 「이 프로젝트의 오류를 보여 줘」 라고 하면 `diagnostics` 가 언어 서버의 진단을, `symbol_search` 가 심볼을 돌려준다(M5-08).
4. 앱을 끄고 `pitwall tool project_list` 를 치면 된다. `pitwall tool db_schema …` 는 「Pitwall 앱을 실행한 뒤 다시」 와 종료 코드 3 이다(결정 M5-D3).
5. 에이전트가 `db_execute` 로 `UPDATE` 를 보내면 그 프로젝트 창에 승인 다이얼로그(에이전트 · 문장 · 등급 · 연결)와 OS 알림이 뜨고, [이번만 허용] 을 눌러야 돈다. 프로덕션 태그 연결이면 묻지 않고 막는다(M5-12 · M5-14 · M5-18).
6. 에이전트가 `db_connection_upsert` 로 연결을 더하면 `.pitwall/db/<id>.toml` 의 diff 를 보고 승인한다. 비밀번호는 에이전트가 넘기지 못하고 사람이 창에서 넣는다(M5-17).
7. 「에이전트 활동」 패널에 호출이 시각 · 에이전트 · 툴 · 결과로 쌓이고 CLI 호출은 `pitwall-cli` 로 보인다. 상태바에 「MCP 2」(M5-10 · M5-13).
8. 설정 > MCP 에서 DB 그룹을 끄면 연결된 에이전트의 툴 목록에서 DB 툴이 곧바로 사라지고 `pitwall tool list` 에도 없다(M5-01 · M5-15).
9. Claude Code 를 앱보다 먼저 켰어도 앱을 띄우면 그 세션의 툴 목록이 늘어난다(M5-20).
10. 탐색기에서 Redis 연결을 한 번 연 뒤 `pitwall tool db_kv_scan --connection-id cache --match 'user:*'` 로 키를, `db_kv_get` 으로 값을 본다(결정 M5-D7 · M5-19).

**「MVP 선」**: 06-roadmap.md 「마일스톤」 아래의 「MVP = M0~M3 + M5 일부(조회 툴)」 은 **M5-01 ~ 09** 가 병합된 때다(조회 툴과 그 CLI). 그 뒤가 상태 표시 · 감사 · 승인 · 쓰기 툴 · 화면 · Redis 조회 · 앱으로 넘겨 붙기 · 툴팁 층이다(M5-10 ~ 21) — 결정 M5-D1.

M5 가 끝났을 때 툴은 22개다: 지금 2(`project_list` · `project_info`) + 조회 13(`settings_get` · `open_with_list` · `project_open` · `db_connection_list` · `db_schema` · `db_query` · `git_status` · `git_log` · `git_diff` · `git_blame` · `git_branch_list` · `diagnostics` · `symbol_search`) + 쓰기 · 연결 5(`project_register` · `open_with_upsert` · `db_connection_upsert` · `db_connection_test` · `db_execute`) + Redis 조회 2(`db_kv_scan` · `db_kv_get`). 05-mcp.md 「툴 목록」 의 프로젝트 · DB · Git · 코드 인텔리전스 · 외부 도구 표가 적은 25개에서 M5 밖으로 둔 셋(`find_references` · `goto_definition` — 결정 M5-D6, `settings_set` — 결정 M5-D9)을 뺀 것이다.

대상 플랫폼: macOS(개발 · 검증), Linux/Windows 는 CI 빌드 · 시험(06-roadmap.md 「결정 기록」 D38). 로컬 소켓은 unix 뿐이라 Windows 의 `pitwall mcp` · `pitwall tool` 은 언제나 헤드리스다(05-mcp.md 「로컬 소켓과 헤드리스」) — Windows 소켓은 이 단계에 없다(「3. M5 에서 하지 않는 것」).

## 1. 작업 목록

「결정 M5-Dn」 은 아래 「4. 착수 전 준비물 · 결정」 의 결정이다. 행의 내용은 그 결정을 따르고, 결정을 바꾸면 그 결정을 가리키는 행을 함께 고친다. 결정은 모두 확정이다(2026-11-13). 새 파일 · 타입 · 메서드 · 툴 이름에 「가칭」 을 붙인 것은 그 행이 정한다. 모든 행은 자기가 바꾼 것의 05-mcp.md 「지금 구현」 · 「아직 없다」 문장과 03-architecture.md 의 「아직 없다」 문장을 같은 PR 에서 고친다.

웹뷰 시험(Vitest)은 0개가 돌아도 실패하지 않는다 — 완료를 보고할 때 `Tests  N passed` 줄의 수를 읽어 적는다(CONTRIBUTING.md 「명령」 의 「테스트가 몇 개 실행됐는지 확인한다」). Rust 쪽은 태스크가 0개면 실패한다.

| `block`(기본) | 거절 | 거절 | 거절 | 거절 |
| `ask` | 매번 승인 | 매번 승인 | 거절 | 거절 |

- 연 적 없는 프로덕션 연결은 「이 연결 열기」 승인으로도 열리지 않는다(결정 M5-D21) — `ask` 여도 사람이 먼저 열어야 한다
- `ask` 의 승인에는 「이 세션 동안 허용」 도 `auto_approve` 도 없다. 조회 툴(`db_schema` · `db_query` · Redis 조회)도 그 연결에는 매번 묻는다
- 승인 경로가 생기기 전(M5-12 가 병합되기 전)에는 `ask` 여도 넷 다 거절이다
- **`ask` 는 사람의 설정에서만 켠다**(결정 M5-D31 — 메인 판정): `[mcp.policy]` 표 전체를 사람의 설정(전역 · `.pitwall/*.local.toml` · 개인 전용 `project.toml`)에서만 읽는다. 커밋되는 공유 설정(`.pitwall/project.toml`)의 `[mcp.policy]` 는 효과가 없고 경고를 남긴다 — 공유 `project.toml` 의 `production = "ask"` 로는 이 표의 `block` 줄이 바뀌지 않는다
- **표지는 조여지기만 하고 대상에만 묶인다**(결정 M5-D37 — 메인 판정): 이 표의 「프로덕션 태그 연결」 은 이번 앱 실행 중 **그 대상**(같은 푼 대상 — 연결 id 와 무관하다)에서 본 표지 가운데 가장 엄한 것으로 판정한다. 「본 것」 은 사람이 열 때만이 아니다 — Host 가 그 프로젝트의 연결 설정을 읽을 때마다(목록 · 열기 · 툴 호출 — 어느 워크트리의 것이든) 더하고, 에이전트의 DB 툴 호출 때는 그 저장소의 메인 체크아웃(연결 워크트리를 따로 등록한 프로젝트면 신뢰가 따르는 메인 저장소 프로젝트의 주 루트 — 메인 판정 2026-11-14)의 연결 설정도 함께 읽어 더한다. 그 연결의 설정에서 `production` 을 지워도, 자기 워크트리에서 표지 있는 연결을 지우고 표지 없는 새 연결(다른 id)로 가리켜도, 메인 체크아웃의 설정이 그 대상을 프로덕션이라고 적고 있으면 프로덕션 연결이다 — 조회 길과 「이 연결 열기」 승인 길 둘 다. read-only 표지도 같다. 표지를 더하는 쪽은 곧바로 따른다
- 표의 열 「사람이 연 연결」 은 그대로 연결 id 와 대상 둘에 묶인다(M5-06 ①). 대상에만 묶이는 것은 표지다
- **표지의 열쇠**(메인 판정 2026-11-14 — M5-06 리뷰): 한 연결로 다른 DB 를 읽을 수 있는 드라이버(MySQL · MariaDB)는 표지의 열쇠에서 DB 이름을 뺀다 — 열쇠는 드라이버 · 호스트 · 포트 · 사용자 · 터널 목적지다. 그 서버의 어느 DB 가 프로덕션이면 그 서버 · 사용자로 가는 에이전트 호출은 모두 프로덕션이다(`db_query` 가 SQL 글 안의 다른 DB 를 지킬 수 없다). Redis 도 DB 번호를 뺀다(메인 판정 2026-11-17 — M5-19): 한 연결이 `SELECT` 로 다른 번호로 옮겨 가고 번호 사이에 권한 경계가 없으며, 번호를 열쇠에 두면 같은 번호의 다른 표기(`database` 입력 `"00"`, 번호를 뺀 설정과 `"0"`)로 표지를 비껴간다. PG 는 DB 이름을 열쇠에 둔다(한 연결이 다른 DB 를 읽지 못한다). SQLite 는 파일이 열쇠다(`ATTACH` 는 M5-07 의 실행 분류가 다룬다). 「사람이 연 연결」 의 열쇠는 그대로 푼 대상 전체다
- 남는 한계: 그 프로젝트의 어느 연결 설정도 표지를 단 적 없는 대상은 기억한 표지가 없어 지금 설정의 표지를 따른다 — 같은 서버의 다른 사용자 · PG 의 다른 DB 이름은 다른 대상이다. 그 자리의 방어는 「이 연결 열기」 승인 다이얼로그가 대상(호스트 · DB)을 보인다는 것이다

### 준비물

- **MCP 규격과 rmcp 확인**: rmcp 3.9.0 의 소스로 둘을 확인했다(2026-11-13) — 호출 결과에 `_meta` 칸이 있고(`CallToolResult`), 취소 알림이 오면 그 호출의 `RequestContext` 의 취소 토큰이 걸린다. 클라이언트 쪽 API(M5-04)와 2026-07-28 판에서의 `tools/list_changed` 전달(M5-20)은 열어 보지 않았다 — 그 행이 먼저 본다

- **새 의존과 라이선스**(CONTRIBUTING.md 「의존성과 라이선스」): rmcp 의 `client` 기능(M5-04 가 고르면 — 이미 dev-dependency 로 받는 크레이트다), `tauri-plugin-notification`(M5-14 — 라이선스 미확인, 그 행이 들이기 전에 본다)
