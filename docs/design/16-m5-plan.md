# 16. M5 (MCP · 에이전트 연동) 작업 분할

M5 목표: **「에이전트가 IDE 만 아는 것을 묻고, 사람이 본 것만 바뀐다」 — Pitwall 이 아는 것(DB 스키마 · 쿼리 결과 · git 상태 · 진단 · 심볼 · 설정)을 MCP 툴과 같은 이름의 명령줄(`pitwall tool`)로 내놓고, 쓰기는 사람의 승인을 지난 것만 돈다.** 코드 편집은 에이전트가 파일 시스템에서 직접 하므로 툴은 「IDE 만 아는 정보와 설정」 에 머문다(05-mcp.md 머리말). 앱에 AI 를 넣지 않고 에이전트에 맡기는 길이 이 단계다(06-roadmap.md 「결정 기록」 D19). 사람이 이 단계에서 직접 물은 것 — DB 스키마 조회, 쿼리와 SQL 파일 실행, 그리고 그 전부를 명령줄로 — 이 중심이고 순서에서 뒤로 밀리지 않는다(결정 M5-D17).

이 문서는 **초안**이다(2026-11-13). 「4. 착수 전 준비물 · 결정」 의 「결정 필요」 여덟(M5-D1 ~ D8)이 정해지면 그 결정을 가리키는 행을 고친 뒤 착수한다 — 행은 모두 권고안으로 적었다. M5-01 은 어느 답에도 걸리지 않아 바로 시작할 수 있다(「2. 순서」).

완료 시 할 수 있는 것(사람이 손으로 확인하는 시나리오 — 1 ~ 4 는 「MVP 선」 까지, 5 ~ 8 은 그 뒤):

1. 앱에서 프로젝트를 연 채, 그 프로젝트의 Orca 워크트리 안 터미널에서 `pitwall tool list` 를 치면 툴의 이름 · 등급 · 설명이 한 줄씩 나온다. `pitwall tool git_status` 는 **그 워크트리**의 상태를 JSON 으로 stdout 에 쓰고 `echo $?` 는 0 이다(M5-01 · M5-02 · M5-04).
2. DB 탐색기에서 로컬 PG 연결을 한 번 펼친 뒤 `pitwall tool db_schema --connection-id local-pg` 로 테이블 목록을, `--object public.users` 로 열 · 인덱스 · FK 를 본다. `pitwall tool db_query --connection-id local-pg --sql 'select …'` 는 행을, `--file queries/report.sql` 은 문장마다 결과 하나를 돌려준다. 사람이 연 적 없는 연결이면 「Pitwall 에서 이 연결을 먼저 열어라」 와 종료 코드 3 이다(결정 M5-D2 · M5-05 · M5-06).
3. Claude Code 에 `pitwall mcp` 를 등록하고 「이 프로젝트의 오류를 보여 줘」 라고 하면 `diagnostics` 가 언어 서버의 진단을, `symbol_search` 가 심볼을 돌려준다(M5-07).
4. 앱을 끄고 `pitwall tool project_list` 를 치면 된다. `pitwall tool db_schema …` 는 「Pitwall 앱을 실행한 뒤 다시」 와 종료 코드 3 이다(결정 M5-D3).
5. 에이전트가 `db_query` 로 `UPDATE` 를 보내면 그 프로젝트 창에 승인 다이얼로그(에이전트 · 문장 · 등급 · 연결)와 OS 알림이 뜨고, [이번만 허용] 을 눌러야 돈다. 프로덕션 태그 연결이면 묻지 않고 막는다(M5-09 · M5-10 · M5-15).
6. 에이전트가 `db_connection_upsert` 로 연결을 더하면 `.pitwall/db/<id>.toml` 의 diff 를 보고 승인한다. 비밀번호는 에이전트가 넘기지 못하고 사람이 창에서 넣는다(M5-14).
7. 「에이전트 활동」 패널에 호출이 시각 · 에이전트 · 툴 · 결과로 쌓이고 CLI 호출은 `pitwall-cli` 로 보인다. 상태바에 「MCP 2」(M5-03 · M5-11).
8. 설정 > MCP 에서 `db_query` 를 끄면 연결된 에이전트의 툴 목록에서 곧바로 사라지고 `pitwall tool list` 에도 없다(M5-12).

**「MVP 선」**: 06-roadmap.md 「마일스톤」 아래의 「MVP = M0~M3 + M5 일부(조회 툴)」 은 M5-01 · 02 · 04 · 05 · 06 · 07 · 08 이 병합된 때다(조회 툴과 그 CLI). 승인 · 쓰기 툴 · 화면(M5-03 · 09 ~ 15)은 그 뒤다 — 결정 M5-D1.

권고대로면 M5 가 끝났을 때 툴은 19개다: 지금 2(`project_list` · `project_info`) + 조회 13(`settings_get` · `open_with_list` · `project_open` · `db_connection_list` · `db_schema` · `db_query` · `git_status` · `git_log` · `git_diff` · `git_blame` · `git_branch_list` · `diagnostics` · `symbol_search`) + 쓰기 · 연결 4(`project_register` · `open_with_upsert` · `db_connection_upsert` · `db_connection_test`). 05-mcp.md 「툴 목록」 에서 실행 구성 · 디버그 · 체크아웃을 뺀 22개 가운데 `find_references` · `goto_definition`(결정 M5-D5)과 `settings_set`(결정 M5-D7)이 빠진 수다.

대상 플랫폼: macOS(개발 · 검증), Linux/Windows 는 CI 빌드 · 시험(06-roadmap.md 「결정 기록」 D38). 로컬 소켓은 unix 뿐이라 Windows 의 `pitwall mcp` · `pitwall tool` 은 언제나 헤드리스다(05-mcp.md 「로컬 소켓과 헤드리스」) — Windows 소켓은 이 단계에 없다(「3. M5 에서 하지 않는 것」).

M4 까지 된 것은 다시 계획하지 않는다 — MCP 골격(11-m0-plan.md M0-17: `crates/pw-mcp` 의 `catalog` · `exposure` · `policy` · `audit` · `server` · `socket` · `proxy`, `apps/desktop/src-tauri/src/mcp.rs`), 로컬 소켓과 헤드리스 · 핸드셰이크 · 워크트리 격리(05-mcp.md 「로컬 소켓과 헤드리스」), RPC 선언에서 툴을 만드는 카탈로그와 `mcp: true` 규칙 · 툴 목록 시험 `mcp_tools_are_exactly_these`(`apps/desktop/src-tauri/src/main.rs`), 노출 설정의 프리셋 · `[mcp.tools]` · 「공유 설정은 좁히기만」 · `tools/list_changed`(`pw_mcp::exposure`), 감사 로그 파일과 인자 요약(`pw_mcp::audit`), 툴 둘(`project_list` · `project_info`), 연결 범위 판정(`pw_core::registry::state::scope_may_write` — 03-architecture.md 「RPC 설계」), DB 의 실행 관문 · 신뢰 게이트 · 분류기 · 스키마 캐시(`pw_db::gate` · `pw_db::trust` · `pw_db_sql` · `pw_db::schema`), git 읽기와 쪽 단위 로그(`git.logPage`), 진단 저장(`pw_lsp::diagnostics`), 심볼 인덱스(`pw-index`), 설정 한 키 쓰기(`pw_core::config::write`), 툴 윈도우 자리 `agent`(`apps/desktop/src/layout/project-layout.ts` — 지금은 빈 자리), 설정 창, 알림, 상태바 자리 표(`STATUS_SLOTS`). 아래 표는 그 위에 얹는 것이다.

## 1. 작업 목록

## 4. 착수 전 준비물 · 결정

### 준비물

- **MCP 규격과 rmcp 확인**: 결과 표지(`_meta`) · `structuredContent` · 호출 취소 · 2026-07-28 판의 구독(`pw_mcp::server` 가 이미 다룬다)을 rmcp 의 문서와 소스에서 확인한다. 이 초안은 rmcp 의 클라이언트 쪽 API 를 열어 보지 않았다 — M5-02 가 먼저 본다
