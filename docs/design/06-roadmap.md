- **MVP = M0~M3 + M5 일부(조회 툴)** — 탐색 · Git · DB. M5 의 몫은 조회 툴과 그 CLI 까지다(16-m5-plan M5-01 ~ 09 — D58)
- 실행 · 디버그는 후순위 결정에 따라 M6로 이동. 단, **내장 터미널(F7-9)은 M1에 포함** (실행 구성 없이도 터미널에서 직접 실행 가능하도록)
- 주력 언어 미정 → LSP/DAP는 특정 언어에 맞춘 작업 없이 **범용 구조(확장 정의 기반)**로 만든다. 기본 번들 LSP 언어는 M4 시작 시점에 **Rust · TypeScript/JavaScript · Python · Java/Kotlin** 넷으로 정했다(D51 — 2026-11-02, 사용자). 기본 번들 디버거 언어는 M6 전에 정한다
- **모바일은 보류** (D13) — 로드맵에서 제외
- 원격 · 확장은 뒤 단계지만 **M0에서 구조를 먼저 깔아둔다**: Host 추상 + 전송 독립 RPC + 메서드별 role 메타데이터 + 확장 레지스트리
- 플랫폼: M0~M6는 macOS에서 개발 · 검증, Linux/Windows는 CI 빌드 유지. Relay는 Linux도 1급

## 2. 성능 목표 (검증 기준)

| 항목 | 목표 |
|---|---|
| 콜드 스타트 → 프로젝트 창 표시 | < 1.5s |
| 유휴 메모리 (LSP 제외, 프로젝트 1개) | < 300MB |
| git 그래프 첫 화면 (10만 커밋 저장소) | < 500ms, 스크롤 60fps |
| 파일 퍼지 검색 (10만 파일) | 키 입력당 < 30ms |
| 쿼리 결과 10만 행 그리드 | 스크롤 60fps, 스트리밍 표시 |
| 쿼리 결과 첫 화면 (로컬 DB, 10만 행 결과) | 실행 → 첫 행이 그려진 프레임 < 500ms |
| 스키마 탐색기 첫 화면 (테이블 1만 개 스키마) | 펼치기 → 첫 화면 < 500ms |
| Redis 키 브라우저 첫 화면 (키 100만 개) | < 500ms, 스크롤 60fps |
| 자동완성 (LSP — Pitwall 쪽) | 키 입력 → 팝업이 그려진 프레임 < 50ms (서버가 곧바로 답할 때) |
| 진단 표시 (LSP — Pitwall 쪽) | 서버 발행 → 밑줄이 그려진 프레임 < 50ms |
| 정의로 이동 (LSP — Pitwall 쪽) | 응답 → 대상 위치 프레임 < 100ms (다른 파일을 여는 것 포함) |
| 타이핑 지연 (LSP 켬) | 키 입력 → 글자 프레임이 LSP 를 끈 상태보다 p95 +2ms 이내 |
| 심볼 인덱스 (파일 2만 · 심볼 50만) | 첫 색인 < 15s (8 코어) · 메모리 +120MB 이하 · 질의 키 입력당 < 30ms |
| 문제 툴 윈도우 (진단 1만 개) | 첫 화면 < 200ms, 스크롤 60fps |

DB 행 넷(14-m3-plan.md 결정 M3-D17 — 사람 승인)은 release 번들에서 재고, 「첫 화면」 은 git 그래프와 같이 액션부터 첫 행들이 그려진 프레임까지다. 데이터 쪽(Rust 몫 — 첫 청크 · 첫 쪽)의 수치는 14 의 M3-05 · M3-06 · M3-09 완료 기준, 화면 쪽은 M3-13 · M3-16 · M3-18 완료 기준, 모아 재는 것은 M3-21.

LSP · 편집 행 여섯(15-m4-plan.md 결정 M4-D19 — 2026-11-02, 사용자)은 Pitwall 쪽 왕복만 목표다 — 서버 자체의 시간 · 메모리는 목표에 넣지 않고 M4-18 · M4-19 가 잰 값을 보고한다. release 번들에서 가짜 서버로 재고(심볼 인덱스는 합성 저장소), 모아 재는 것은 M4-19 다. 단위 시험(jsdom)은 프레임을 재지 않는다.

「스크롤 60fps」 의 판정: 끝까지 연속 스크롤할 때 화면 갱신을 놓치지 않은 프레임(간격 ≤ 1.5 × 간격 중앙값)이 95% 이상이고 간격 중앙값이 17 ms 이하(60 fps 이상)다. WKWebView 의 rAF 시각이 1 ms 로 잘려 60 Hz 의 정상 간격이 16 · 17 ms 로 갈리므로 「16.7 ms 안 몫」 은 렌더와 상관없이 0.5 언저리가 위끝이다(2026-10-30 실기 · 모의, 사람 승인) — 그 몫은 참고로 싣는다. 재는 방법은 `CONTRIBUTING.md` 「성능 기준선」 의 git 시나리오.

콜드 스타트 · 유휴 메모리는 `mise run perf`(macOS release 번들)로 잰다. 시작점 · 끝점 · 메모리 지표 · 반복 방법은 `CONTRIBUTING.md` 「성능 기준선」 절, 잰 기준선은 그때의 커밋 · 기기와 함께 `docs/superpowers/reports/*-perf-baseline-report.md` 에 남는다.

| 리스크 | 영향 | 대응 |
|---|---|---|
| Linux WebKitGTK 렌더링 성능/버그 | UI 끊김 | canvas 렌더링 + 가상화, Linux 실기 벤치마크(Linux 출시 준비 때 — D38. 원래는 M1 이었다). 최악엔 UI만 Electron 교체(코어 헤드리스라 가능) |

| LSP 서버 메모리 (jdtls, kotlin) | "가벼움" 훼손 | 언어 서버 지연 기동, 유휴 종료, 프로젝트별 on/off |
| Relay 배포 복잡도 (OS/arch/glibc) | 원격 실패 | musl 정적 빌드, Desktop과 버전 정확히 일치(Zed 방식) · 해시 검증, 업로드 설치 옵션 |

| Tailscale 없는 환경의 외부 접속 | 직접 연결 불가 | SSH 대체 경로, 필요 시 `Transport` 추상 위에 Hub 추가 |
| 확장 API 조기 고착 | 하위 호환 부담 | 공개 전까지 내부 전용, WIT 인터페이스 버전 관리 |
| Mason registry 형식 변경 · 체크섬 없는 패키지 | 설치 실패 · 공급망 위험 | registry 버전 고정, 스키마 버전 확인 후 미지원 항목 건너뜀, 설치 전 출처 · 라이선스 확인, 사용자 지정 경로 대체 |
| 외부 런타임 도구(mise 등) 동작 차이 · 호출 비용 | 잘못된 버전 · 느린 기동 | 디렉터리별 캐시, 실패 시 로그인 셸로 대체 + 상태바 경고, mise 버전별 출력 형식 테스트 |
| 범위 팽창 (IntelliJ 재구현 유혹) | 일정 | 01-product 비목표 목록을 기준으로 리뷰 |

| D60 | 에이전트의 DB | **에이전트(MCP · CLI)의 DB 툴은 사람이 그 프로젝트 창에서 이번 앱 실행 중에 같은 대상으로 연 연결만 쓴다** — D48 「연결은 사람이 누를 때만」 의 에이전트 쪽이다. 툴은 사람의 연결을 빌리지 않고 호출마다 자기 연결을 새로 연다(사람이 DB 탭을 닫은 뒤에도 앱을 끌 때까지 된다). 연 적 없는 연결은 거절하고, `db_connection_test` 만 「이 연결 열기」 승인(그 세션 · 그 연결, 자동 승인 없음)을 청한다(어느 툴이 청하는지 · 자동 승인 없음은 메인 판정 — 16 결정 M5-D21). 프로덕션 태그 연결은 막는다(`[mcp.policy] production` 의 기본 `block`). 그 풀이 둘은 메인 판정이다(16 결정 M5-D31 · D37) — ① `ask` 로 바꾸면 사람이 연 프로덕션 연결을 매번 승인으로 하되, `[mcp.policy]` 표 전체는 사람의 설정(전역 · `.pitwall/*.local.toml` · 개인 전용 `project.toml`)에서만 읽고 커밋되는 공유 설정(`.pitwall/project.toml`)의 그 표는 효과 없이 경고만 남긴다 ② 프로덕션 · read-only 표지는 조여지기만 한다 — 에이전트에게 적용하는 표지는 이번 앱 실행 중 그 연결(같은 대상)에서 본 것 가운데 가장 엄한 것이라, 설정에서 표지를 지워도 앱을 끌 때까지 그대로다(사람이 이번 실행에서 한 번도 열지 않은 연결은 지금 설정의 표지를 따른다). **DB 쓰기는 조회와 다른 툴이다 — `db_query`(조회만, `read`)와 `db_execute`(쓰기 포함, `dangerous`, 매번 승인)**, 둘 다 `sql` · `file` 을 받는다(D55). **Redis 는 조회 둘(쪽 단위 키 스캔 · 값 읽기)만 넣고 명령 실행 툴은 없다**(2026-11-13, 사용자). 대안: ① 처음부터 승인으로만 연다 — DB 툴이 승인 화면 뒤로 밀려 MVP 에서 빠진다 ② 신뢰한 프로젝트의 비프로덕션 연결은 묻지 않고 연다 — D48 을 에이전트에게는 푸는 것이고, 커밋된 연결 설정에 사람이 본 적 없이 사람의 비밀로 붙는다 ③ 사람이 지금 열어 둔 연결만 — 탐색기의 연결은 쉬면 저절로 닫혀 에이전트가 일하는 도중에 끊긴다 ④ 한 툴 `db_query` 가 쓰기까지 — DB 쓰기만 따로 끌 수 없고 프리셋 `full` 에 딸려 온다 ⑤ Redis 툴 없음 — 에이전트가 `redis-cli` 를 쓰게 되고 그 길은 연결 설정 · 비밀 · 프로덕션 표지를 지나지 않는다 | 04 F6-14 · F10-3, 05 「DB」 · 「권한 모델」, 03 「보안」, 16 결정 M5-D2 · D4 · D7 · D21 · D31 · D37 |
