- **MVP = M0~M3 + M5 일부(조회 툴)** — 탐색 · Git · DB
- 실행 · 디버그는 후순위 결정에 따라 M6로 이동. 단, **내장 터미널(F7-9)은 M1에 포함** (실행 구성 없이도 터미널에서 직접 실행 가능하도록)
- 주력 언어 미정 → LSP/DAP는 특정 언어에 맞춘 작업 없이 **범용 구조(확장 정의 기반)**로 만들고, 기본 번들 언어는 M4 시작 시점에 선정
- **모바일은 보류** (D13) — 로드맵에서 제외
- 원격 · 확장은 뒤 단계지만 **M0에서 구조를 먼저 깔아둔다**: Host 추상 + 전송 독립 RPC + 메서드별 role 메타데이터 + 확장 레지스트리
- 플랫폼: M0~M6는 macOS에서 개발 · 검증, Linux/Windows는 CI 빌드 유지. Relay는 Linux도 1급

## 2. 성능 목표 (검증 기준)

| 항목 | 목표 |
|---|---|
| 콜드 스타트 → 프로젝트 창 표시 | < 1.5s |
| 유휴 메모리 (LSP 제외, 프로젝트 1개) | < 300MB |
| git 그래프 첫 화면 (10만 커밋 저장소) | < 500ms, 스크롤 60fps |
| 파일 퍼지 검색 (10만 파일) | 키 입력당 < 30ms |
| 쿼리 결과 10만 행 그리드 | 스크롤 60fps, 스트리밍 표시 |
| 쿼리 결과 첫 화면 (로컬 DB, 10만 행 결과) | 실행 → 첫 행이 그려진 프레임 < 500ms |
| 스키마 탐색기 첫 화면 (테이블 1만 개 스키마) | 펼치기 → 첫 화면 < 500ms |
| Redis 키 브라우저 첫 화면 (키 100만 개) | < 500ms, 스크롤 60fps |

DB 행 넷(14-m3-plan.md 결정 M3-D17)은 release 번들에서 재고, 「첫 화면」 은 git 그래프와 같이 액션부터 첫 행들이 그려진 프레임까지다. 데이터 쪽(Rust 몫 — 첫 청크 · 첫 쪽)의 수치와 재는 방법은 14 의 M3-05 · M3-06 · M3-09 · M3-13 · M3-16 · M3-18 완료 기준, 모아 재는 것은 M3-21.

「스크롤 60fps」 의 판정: 끝까지 연속 스크롤할 때 화면 갱신을 놓치지 않은 프레임(간격 ≤ 1.5 × 간격 중앙값)이 95% 이상이고 간격 중앙값이 17 ms 이하(60 fps 이상)다. WKWebView 의 rAF 시각이 1 ms 로 잘려 60 Hz 의 정상 간격이 16 · 17 ms 로 갈리므로 「16.7 ms 안 몫」 은 렌더와 상관없이 0.5 언저리가 위끝이다(2026-10-30 실기 · 모의, 사람 승인) — 그 몫은 참고로 싣는다. 재는 방법은 `CONTRIBUTING.md` 「성능 기준선」 의 git 시나리오.

콜드 스타트 · 유휴 메모리는 `mise run perf`(macOS release 번들)로 잰다. 시작점 · 끝점 · 메모리 지표 · 반복 방법은 `CONTRIBUTING.md` 「성능 기준선」 절, 잰 기준선은 그때의 커밋 · 기기와 함께 `docs/superpowers/reports/*-perf-baseline-report.md` 에 남는다.

|---|---|---|

| 확장 API 조기 고착 | 하위 호환 부담 | 공개 전까지 내부 전용, WIT 인터페이스 버전 관리 |

| 외부 런타임 도구(mise 등) 동작 차이 · 호출 비용 | 잘못된 버전 · 느린 기동 | 디렉터리별 캐시, 실패 시 로그인 셸로 대체 + 상태바 경고, mise 버전별 출력 형식 테스트 |
| 범위 팽창 (IntelliJ 재구현 유혹) | 일정 | 01-product 비목표 목록을 기준으로 리뷰 |
