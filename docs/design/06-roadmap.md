# 06. 로드맵 · 리스크 · 결정 기록

## 1. 마일스톤

| 단계 | 목표 | 포함 기능 |
|---|---|---|
| **M0. 기반** | 뼈대 | cargo/pnpm 워크스페이스, Tauri 셸(macOS), RPC + 타입 생성(+role 메타데이터), Host 추상, 이벤트 버스, 프로젝트 레지스트리, 단일 인스턴스/CLI, **확장 레지스트리 구조 · 테마 토큰 · i18n 기반** |
| **M1. 탐색** | "열어서 본다" | F2 파일→프로젝트, F3 파일 트리/검색, F4-1·2 에디터, F8 다른 도구로 열기(Orca 포함), F7-9 내장 터미널, F11 레이아웃/팔레트/키맵 |
| **M2. Git** | IntelliJ git 대체 | F5 그래프·필터·커밋·스테이징·체크아웃·머지·충돌 해결·blame·파일 히스토리, 에디터 거터 |
| **M3. DB** | DataGrip 대체 (기본) | F6 PG/MySQL/SQLite/**Redis**, 스키마 탐색, 콘솔, 그리드, 안전장치(SQL 위험도 분류), SSH 터널 — 시작 전 DBX 코드 검토 |
| **M4. LSP · 편집** | 코드 탐색 + L2 편집 | F4-3 LSP 핵심, F4-4 자동완성/포맷/rename, 멀티 커서, 서버 관리자, 심볼 인덱스 |
| **M5. MCP** | 에이전트 연동 | F10 (실행 관련 툴 제외), 툴별 on/off · 프리셋 |
| **M6. 실행 · 디버그** | IntelliJ 실행 대체 | F7 실행 구성 · 태스크 감지 · 콘솔, DAP, MCP 실행 툴 |
| **M7. 원격** | Relay | F9 — `pw-link`, Relay 데몬 · Zed 방식 SSH 설치(버전 일치) · 프록시 재연결 · 미저장 편집 보관 · 포트 포워딩, 직접(LAN/Tailscale) 연결 |
| **M8. 확장 공개** | 외부 확장 | F13 — 테마/언어 팩/코드 언어 확장 설치, VS Code 테마 import, 이후 WASM 플러그인 |
| v1.0 | 안정화 | P1 항목, 자동 업데이트. macOS 정식 출시 → Linux/Windows 순차 |

- **MVP = M0~M3 + M5 일부(조회 툴)** — 탐색 · Git · DB
- 실행 · 디버그는 후순위 결정에 따라 M6로 이동. 단, **내장 터미널(F7-9)은 M1에 포함** (실행 구성 없이도 터미널에서 직접 실행 가능하도록)
- 주력 언어 미정 → LSP/DAP는 특정 언어에 맞춘 작업 없이 **범용 구조(확장 정의 기반)**로 만들고, 기본 번들 언어는 M4 시작 시점에 선정
- **모바일은 보류** (D13) — 로드맵에서 제외
- 원격 · 확장은 뒤 단계지만 **M0에서 구조를 먼저 깔아둔다**: Host 추상 + 전송 독립 RPC + 메서드별 role 메타데이터 + 확장 레지스트리
- 플랫폼: M0~M6는 macOS에서 개발 · 검증, Linux/Windows는 CI 빌드 유지. Relay는 Linux도 1급

## 2. 성능 목표 (검증 기준)

| 항목 | 목표 |
|---|---|
| 콜드 스타트 → 프로젝트 창 표시 | < 1.5s |
| 유휴 메모리 (LSP 제외, 프로젝트 1개) | < 300MB |
| git 그래프 첫 화면 (10만 커밋 저장소) | < 500ms, 스크롤 60fps |
| 파일 퍼지 검색 (10만 파일) | 키 입력당 < 30ms |
| 쿼리 결과 10만 행 그리드 | 스크롤 60fps, 스트리밍 표시 |

## 3. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| Linux WebKitGTK 렌더링 성능/버그 | UI 끊김 | canvas 렌더링 + 가상화, 조기 벤치마크(M1). 최악엔 UI만 Electron 교체(코어 헤드리스라 가능) |
| DAP 어댑터별 편차 (특히 Java) | 디버깅 품질 | JVM은 우선 attach 모드(JDWP)만 보장 |
| LSP 서버 메모리 (jdtls, kotlin) | "가벼움" 훼손 | 언어 서버 지연 기동, 유휴 종료, 프로젝트별 on/off |
| Relay 배포 복잡도 (OS/arch/glibc) | 원격 실패 | musl 정적 빌드, Desktop과 버전 정확히 일치(Zed 방식) · 해시 검증, 업로드 설치 옵션 |
| 서드파티 코드 차용(DBX 등) 라이선스 | 고지 누락 | Apache-2.0 코드 차용 시 `THIRD_PARTY_NOTICES` · 원본 라이선스 · 변경 사실 표기, 파일 헤더 유지 |
| Tailscale 없는 환경의 외부 접속 | 직접 연결 불가 | SSH 대체 경로, 필요 시 `Transport` 추상 위에 Hub 추가 |
| 확장 API 조기 고착 | 하위 호환 부담 | 공개 전까지 내부 전용, WIT 인터페이스 버전 관리 |
| 범위 팽창 (IntelliJ 재구현 유혹) | 일정 | 01-product 비목표 목록을 기준으로 리뷰 |

## 5. 남은 미결정 사항

1. **기본 번들 언어** (M4 시작 전) — 주력 언어가 정해지면 LSP/DAP 기본 번들과 테스트 대상 선정
2. **Orca → Pitwall 인자 형식** — Orca가 "Terminal 명령" 뒤에 경로만 붙이는지, 파일/라인도 넘기는지 확인 → `pitwall` CLI 인자 파싱은 경로 · `path:line[:col]` 모두 수용하도록 이미 설계(F2-2)
3. **모바일 재개 여부** — 확인하고 싶은 정보가 구체화되면 재검토 (iOS 포함 시 푸시 경로도 함께 결정)
