# 14. M3 (DB) 작업 분할

M3 목표: **「DataGrip 을 기본 범위에서 대체한다」 — 프로젝트의 DB(PostgreSQL · MySQL/MariaDB · SQLite · Redis)에 붙어 스키마를 보고, 콘솔에서 SQL 을 돌려 결과를 그리드로 보고, 키가 있는 테이블은 그리드에서 고친다.** 실수로 프로덕션을 망가뜨리지 않는 것 — 파서 기반 위험도 분류 하나를 Host 에 두고 UI · MCP 가 함께 쓰며, read-only 는 분류와 DB 수준 읽기 전용 둘로 강제하는 것 — 이 이 단계의 중심이다.

완료 시 할 수 있는 것(사람이 손으로 확인하는 시나리오):

1. `⌘8` DB 탐색기에서 「연결 추가」 → 일반 · SSH 터널 · SSL · 옵션 탭을 채우고 [연결 테스트] 가 성공한다. 비밀번호는 키체인에 들어가고 `.pitwall/db/<id>.toml` 에는 `secret_ref` 만 남는다. `~/.ssh/config` 의 별칭 하나로 바스티언 너머 PG 에 붙는다.
2. 탐색기에서 연결 → DB → 스키마 → 테이블을 펼치고(테이블 1만 개 스키마에서도 첫 화면 0.5초 안), 열 · 인덱스 · FK 를 보고, `⌘B` 로 DDL 을 연다. 테이블을 더블클릭하면 테이블 데이터가 열린다.
3. `⌘⇧L` SQL 콘솔에서 커서가 있는 문장을 `⌘↩` 로 돌리면 결과가 곧바로 그리드에 흘러 들어오고(10만 행 결과도 첫 화면 0.5초 안, 스크롤이 끊기지 않는다), 여러 문장을 고르면 문장마다 결과 탭이 생긴다. `⌘F2` 로 30초짜리 쿼리를 취소하면 1초 안에 서버에서도 멈춘다. 실행 계획을 본다.
4. WHERE 없는 `DELETE` 를 돌리면 등급과 함께 확인을 묻고, 프로덕션 태그 연결에서는 조회가 아닌 모든 문장이 확인을 거친다. read-only 연결에서는 `SELECT setval(…)` · `SELECT pg_terminate_backend(…)` 도 막힌다(분류가 놓쳐도 DB 가 거절한다). 수동 커밋 탭에서는 [커밋] · [롤백] 전까지 바뀐 것이 다른 세션에 보이지 않고, 그 탭에서 큰 `SELECT` 가 행 상한에 닿아도 트랜잭션은 그대로다.
5. 키가 있는 테이블을 열어 WHERE · ORDER BY 를 넣고, 셀 몇 개를 고치고 행을 하나 지운 뒤 [제출] → 생성될 SQL 미리보기 → 한 트랜잭션으로 반영된다.
6. Redis 연결에서 `session:*` 를 패턴으로 찾아 `:` 로 묶인 키 트리를 펼치고, 타입별 뷰어(string · hash · list · set · zset · stream · JSON)로 값과 크기를 보고 TTL 을 고친다. 명령 콘솔에서 `KEYS *` · `FLUSHALL` 은 막히고 `DEL` 은 확인을 묻는다. DB 번호를 바꾼다.
7. 클론한 저장소를 신뢰하지 않은 채 열면 탐색기에 연결 목록만 있고, 어떤 연결 · 터널도 저절로 열리지 않는다. 신뢰한 뒤에도, 콘솔 탭이 열린 채 앱을 다시 시작해도 연결은 사람이 누를 때만 열린다.

**M3 의 완료 조건에는 CI 의 실 DB 시험이 들어간다**: ubuntu 의 DB 시험 잡 `db-live`(틀은 M3-01)가 PG · MySQL · MariaDB · Redis 각각의 실 DB 시험과 SSH 터널 시험을 따로 돌리고, 하나라도 실행 개수가 0 이면 그 잡이 실패한다(결정 M3-D16). 각 드라이버 행의 완료 기준이 그 DB 의 하한을 정한다.

대상 플랫폼: macOS(개발 · 검증), Linux/Windows 는 CI 빌드 · 시험(06-roadmap.md 「결정 기록」 D38). 실 DB 시험(PG · MySQL · MariaDB · Redis)은 CI 의 ubuntu 잡에서만 돈다 — GitHub 호스팅 macOS · Windows 러너에서는 서비스 컨테이너를 쓸 수 없다. 로컬 macOS 는 환경 변수를 준 사람만 같은 시험을 돌린다(결정 M3-D16). SQLite 와 DB 없이 도는 시험은 세 OS 에서 돈다.

M2 까지 된 것은 다시 계획하지 않는다 — 툴 윈도우 자리 `database` 와 그 키 `⌘8`(M0-13 · `apps/desktop/src/layout/project-layout.ts`), SQL 문법 강조(`extensions/lang-sql`, tree-sitter — M1-17), 상태바 슬롯 · 작업 진행률 · 알림(M1-04), 신뢰 플래그와 확인(M1-05 · M1-16), 프로젝트 창 상태(D36), 위험 작업 확인 부품과 askpass(M2-20 · M2-06), 레이아웃 프리셋 틀(M2-21), 연결 범위 판정(`pw_core::registry::state::scope_may_write`, 03-architecture.md 「RPC 설계」 의 연결 범위 세 절), MCP 노출 규칙(`rpc_method!` 의 `mcp: true` 를 단 것만 툴, 05-mcp.md 「툴 레지스트리」 — 툴 목록은 데스크톱 크레이트의 `mcp_tools_are_exactly_these` 시험이 고정한다). 아래 표는 그 위에 얹는 것이다.

13-m2-plan.md 「M2 에서 하지 않는 것」 에서 M3 로 넘어온 것은 DB 레이아웃 프리셋 `⌃⌥3` 하나이고 M3-20 에 있다.

TS 쪽은 생성된 타입(`packages/rpc-client`)을 그대로 쓴다. **시험 도우미**(이후 행이 모두 쓴다): 가짜 드라이버(행 수 · 지연 · 오류 · 취소 · 커서 버리기 동작을 정하고, 불린 메서드를 기록한다 — 실행 파이프라인 · 그리드가 실 DB 없이 시험한다), 실 DB 시험 표지(환경 변수 `PW_TEST_PG_URL` · `PW_TEST_MYSQL_URL` · `PW_TEST_MARIADB_URL` · `PW_TEST_REDIS_URL` 이 없으면 그 시험을 건너뛰지 않고 **목록에서 빼는** 방식 — 시험 이름에 `live_pg` · `live_mysql`(MariaDB 도 같은 시험을 두 URL 로) · `live_redis` 를 넣어 nextest 필터로 고른다), SQLite 임시 파일 · 인메모리 픽스처와 그 시험(세 OS). **CI 잡 틀**: `.github/workflows/ci.yml` 에 ubuntu 전용 잡 `db-live` 를 따로 둔다(행렬 잡에는 `services:` 를 걸 수 없다 — macOS · Windows 러너는 서비스 컨테이너를 돌리지 못한다). 서비스 컨테이너 PG · MySQL · MariaDB · Redis(이미지 판 고정), URL 을 넘기고 DB 마다 `cargo nextest run --release -E 'test(/live_pg/)' --no-tests=fail` 처럼 **따로** 돈다. **실행 개수 하한 검사**도 이 행이 만든다 — 단계마다 nextest 가 실행한 시험 수를 세어 DB 별 하한(한 파일 `scripts/db-live.toml` 에 DB 마다 한 줄, 처음 값은 0 — 준비 확인 시험만 있는 동안 「0개면 실패」 는 `--no-tests=fail` 이 따로 지킨다)과 견주고 모자라면 실패한다. 하한은 각 드라이버 행이 자기 줄을 올리고(M3-06 · 07 · 09 · 11 · 22 의 「≥ N」), 아래 준비 확인 시험(이름 `live_<db>_ready`)은 하한 계산에서 뺀다. 이 행의 live 시험은 드라이버 크레이트 없이 `std::net` 으로 서버가 떴는지만 본다(준비 확인 — PG `SSLRequest` 의 1바이트 응답, MySQL · MariaDB 핸드셰이크 패킷의 판본 바이트, Redis `PING` → `+PONG`) — 서비스 준비 대기로도 쓰고, 드라이버 행이 각자의 live 시험을 더한다. 로컬은 `mise run test-db`(같은 명령, 환경 변수가 없는 DB 는 건너뛴다고 알린다 — 건너뛴 것을 통과로 적지 않는다) | — | Rust 시험: ① `DbValue` 직렬화 스냅숏 — 2^53 은 문자열, 2^53−1 은 수, `u64::MAX` 는 문자열, 5 는 수, decimal `0.1` 은 문자열, 바이트는 `0x` hex, 셀 상한 + 1 바이트는 `truncated` 와 원래 크기 ② 가짜 드라이버를 trait 객체(`Box<dyn SqlConnection>`)로 불러 1,000행이 순서대로 오고, 취소하면 그 드라이버의 인터럽트가 1회 기록된다 ③ `pw-db` 가 드라이버 크레이트에 의존하지 않는다(`cargo tree -p pw-db -e normal` 을 보는 시험) ④ `mise run gen` 뒤 TS 타입에 `DbValue` 가 있다 ⑤ SQLite 픽스처 시험이 세 OS 에서 돈다. - 병렬 묶음: (M3-01) → (M3-02 · 03 · 04 · 06 · 07 · 08 · 09) → (M3-05) → (M3-10 · 11 · 16 · 19 · 22) → (M3-12 · 13 · 14 · 15 · 18) → (M3-17 · 20) → (M3-21). 묶음은 「앞 묶음이 다 끝나야 시작」 이 아니다 — 각 행은 자기 선행이 병합되면 바로 시작한다. 묶음 1 이 한 행뿐인 것은 크레이트 골격 · trait · 값 타입 · 가짜 드라이버 · CI 의 `db-live` 잡 틀을 이후 행이 모두 공유하기 때문이다. - 드라이버 넷(M3-06 ~ M3-09)은 M3-01 의 trait 만 보고 실행 파이프라인(M3-05)과 나란히 돈다. 연결을 열거나 실행하는 RPC 는 모두 M3-05 뒤에 있다(M3-10 · 11 · 12 · 22) — 관문 없이 RPC 를 여는 길이 순서상 생기지 않는다. 파이프라인 · 그리드 · 탐색기는 가짜 드라이버로 시험하고, 실 DB 끝에서 끝 확인은 드라이버 · 편집 · Redis RPC 행의 live 시험과 M3-21 이 한다
- 결정 M3-D1 ~ M3-D21 은 모두 확정이다(§4) — 묶음 1 을 바로 시작할 수 있다
- 워크트리 단위로 나누기 좋은 경계: Rust 바탕(01 · 02 · 05 · 10) / SQL 언어(03 · 04 · 12) / 드라이버(06 · 07 · 08 · 09 · 11 · 22) / 화면(13 · 14 · 15 · 16 · 17 · 18 · 19 · 20) / 측정(21)

### 공유 부품의 주인

같은 파일을 크게 건드리는 행은 같은 묶음에 두지 않았다. 여럿이 한 줄씩 더하는 곳은 아래 주인이 틀을 만들고 나머지는 그 틀에 한 줄씩 끼운다.

| 부품 | 주인 | 나머지 행이 하는 것 |
|---|---|---|
| 공통 trait · 지원 플래그(`pw-db-driver`) · 값 타입(`pw-db-types`) | M3-01 | 드라이버 행은 구현만 한다. trait 에 메서드나 플래그를 더해야 하면 그 행이 M3-01 의 가짜 드라이버와 trait 시험을 함께 고친다 — 다른 드라이버 행과 겹치므로 더하는 메서드는 기본 구현(「지원하지 않음」)을 둔다 |
| 크레이트 골격(`pw-db*` 여덟 개) · `pw-rpc-gen` 등록(타입 · 메서드를 내는 셋 — `pw-db-types`(`rpc_type!` 로 `DbValue` 등) · `pw-db-sql` · `pw-db`) | M3-01 | 이후 행은 모듈을 채우기만 한다 — `Cargo.toml` 의 `[package]` · `pw-rpc-gen` 의 `use … as _;` 를 다시 만들지 않는다. 드라이버 크레이트(`pw-db-driver` · `-pg` · `-mysql` · `-sqlite` · `-redis`)는 RPC 를 선언하지 않아 등록하지 않았다 — 선언하게 되는 행(M3-09 · M3-22 등)이 그때 등록한다 |
| 드라이버 등록부(데스크톱 크레이트에서 드라이버를 `pw-db` 에 넣는 자리) | M3-01 의 틀 | M3-06 ~ M3-09 가 한 줄씩 더한다 |

| `pw-db-sql` 의 모듈 | M3-03(`risk`) · M3-04(`split`) · M3-12(`edit`) | 모듈을 나눠 겹치지 않게 한다. 분류를 부르는 곳(M3-05 · M3-12 · M3-15 · M5)은 `classify_statement` 나 `db.sql.classify` 만 쓴다 — 다른 분류기를 두지 않는다(결정 M3-D5) |
| 실행 관문(연결 범위 `DbGrant` · 신뢰 게이트 · 세션 id 범위 · 등급 정책 · `confirmed` 해시 · read-only) | M3-05 | 연결을 열거나 실행하는 새 길(M3-10 의 메타데이터, M3-11 의 터널, M3-12 의 적용, M3-22 의 키 쓰기 · 명령)은 관문을 지난 값만 받는다. 정책을 바꾸려면 M3-05 의 시험과 함께 고친다 |
| `licenses/vendored.md` 의 DBX 항목 | M3-03 · M3-09 중 먼저 병합되는 행 | 다른 행은 같은 항목(같은 원본 · 커밋)에 옮긴 파일을 한 줄 더한다 |
| `deny.toml` · `about.toml` 의 M3 예외 | M3-07(`webpki-roots`) · M3-09(`xxhash-rust`) | 각 행이 자기 의존성을 들일 때 넣는다. 예외 주석에 「그 크레이트가 배포 바이너리에 들어가는 까닭과 조건」 을 적는다(기존 예외 주석의 꼴) |

## 4. 착수 전 준비물 · 결정

### 준비물

- **DBX 원본(커밋 `c5e7e0430653aaef198800a48f9dec46a7cfed5e`)** — 차용 행(M3-03 · M3-09)이 옮길 파일: `crates/dbx-sql-core/src/sql_risk.rs`(AST 분류 · 항진식 분석 · 잠금 토큰 검사 · 시험 34개), `crates/dbx-driver-redis/src/lib.rs` 의 `classify_command` · `parse_command_argv`. 받은 코드는 미신뢰로 다룬다 — 빈 폴더에 `git -c core.hooksPath=/dev/null clone --no-recurse-submodules` 로 받아 읽기만 하고 그 폴더에서 빌드 · 스크립트를 돌리지 않는다. 옮길 때마다 그 커밋의 `NOTICE` 를 다시 보고 옮긴 부분에 해당하는 고지가 있으면 함께 싣는다(Apache-2.0 4(d))
- **라이선스 예외 두 건**(결정 M3-D14) — `xxhash-rust`(BSL-1.0, M3-09)와 `webpki-roots`(CDLA-Permissive-2.0, M3-07)를 `deny.toml` 의 `[[licenses.exceptions]]` 와 `about.toml` 의 `accepted` 두 곳에. 다른 예외는 없다 — 공개판 크레이트만(포크 git 은 `[sources]` 의 `unknown-git = "deny"` 가 거절한다), TLS 공급자는 이미 쓰는 `ring` 하나(`aws-lc-rs` 를 들이지 않는다 — 각 드라이버의 기능을 `ring` 쪽으로 고른다), SSH 는 시스템 ssh 라 `russh` 와 RUSTSEC-2023-0071 이 없다. 들일 때마다 `cargo tree -e features -i <크레이트>` 로 무엇이 끌어오는지 보고, `mise run licenses` · `mise run advisories` 를 돌린다
- **CI 의 `db-live` 잡**(틀은 M3-01) — ubuntu 러너의 서비스 컨테이너 PG · MySQL · MariaDB · Redis, 이미지 판 고정. 서비스 이미지의 라이선스는 배포물이 아니라 따지지 않지만, Redis 는 판에 따라 서버 라이선스가 다르므로 고른 판을 잡 주석에 적는다. TLS 시험 서버는 checkout 뒤 `docker run` 단계(M3-06 · M3-09)
- **`db-live` 를 필수 검사로** — 저장소의 branch protection 에서 `db-live` 를 병합에 필요한 검사로 더하는 것은 사람이 한다(저장소 설정이라 워커가 못 한다). 더하기 전에는 「완료 조건」 이 병합을 막지 않는다
- **Glide Data Grid 확인**(M3-16 착수 전) — `@glideapps/glide-data-grid` 의 라이선스(MIT)와 전이 의존성을 `scripts/licenses.mjs` 로, React 19 와의 호환(peer 범위 · 실제 렌더)을 작은 페이지로 확인한다. 맞지 않으면 M3-16 이 멈추고 묻는다(10-ui.md 「UI 스택」 의 선택을 바꾸는 일이다)
- **로컬 실 DB**(선택) — macOS 개발자는 Homebrew 나 컨테이너로 PG · MySQL · MariaDB · Redis 를 띄우고 `PW_TEST_*_URL` 을 주면 `mise run test-db` 가 CI 와 같은 시험을 돈다. 없으면 그 DB 의 시험은 목록에서 빠진다고 알린다 — 「통과」 로 보고하지 않는다
- **사람 확인 한 번** — 실제 원격 DB 에 `~/.ssh/config` 의 바스티언(ProxyJump · 에이전트)을 거쳐 `verify-full` TLS 로 붙고, 프로덕션 태그 연결에서 시나리오 4 를 해 본다. 자동 시험은 로컬 sshd · 자체 서명 CA 로만 한다

| M3-D19 | DB RPC 의 MCP 노출 | **M3 에서는 어느 DB RPC 에도 `mcp: true` 를 달지 않는다**(`mcp_tools_are_exactly_these` 가 지킨다). M5 가 05-mcp.md 「DB」 표의 툴을 켠다. 그래서 M3 는 툴로 켤 수 있는 꼴로 만든다 — 입력은 struct(`projectId` 포함), 쿼리는 스트림 `db.query.execute` 옆에 쪽 단위 `db.query.page`(늘 읽기 전용 트랜잭션 + 행 제한), 스키마 · Redis 는 쪽 단위 RPC. 분류 · read-only 강제는 M3 의 것을 M5 가 그대로 쓴다. MCP 경로는 `confirmed` 를 받지 않고 05 「권한 모델」 의 승인을 쓴다 | 06 의 순서(MCP 는 M5)이고 M1 · M2 가 같은 규칙(결정 M2-D7)으로 툴을 미뤘다. 쓰기 툴의 승인 화면(05 「권한 모델」 의 `dangerous`)이 아직 없다. `confirmed` 는 창의 확인 다이얼로그를 거친 증거일 뿐이라 에이전트가 실을 수 있게 두면 승인이 사라진다 | ① 조회 툴(`db_connection_list` · `db_schema`)만 M3 에서 — 요약 형식 · `detail` 옵션(05 「설계 메모」)을 M5 에서 다시 정해야 한다 | — |
| M3-D20 | 등급별 확인 · 차단 | 콘솔 · 그리드 편집 · Redis 명령의 정책: **조회**는 그대로, **쓰기**는 자동 커밋 탭에서 그대로(프로덕션이면 확인), **범위 없는 쓰기 · DDL** 은 확인, **파괴**(파싱 실패 포함)는 확인 + 프로덕션이면 연결 이름을 쳐야 실행. **read-only 연결**은 조회 밖을 모두 거절, **프로덕션 연결**은 조회 밖을 모두 확인. Redis 는 `Confirm` = 확인, `Blocked` = 거절. 확인은 Host 가 강제한다 — 확인이 필요하면 `3001` 이 문장 해시를 돌려주고, 다시 부를 때의 `confirmed { grade, statementsHash, name? }` 를 Host 가 지금 실행할 문장들(세션 · 방언 · 원문)의 해시 · 등급 · 연결 이름과 견준다 | 04 F6-9 의 「등급별 확인 · 차단」 을 구체화한 것이다. 확인을 창에만 두면 창의 버그(편집기 내용이 바뀐 뒤 옛 확인을 다시 보내는 것)를 Host 가 못 막는다 — 해시에 묶으면 확인한 그 SQL · 그 세션에만 쓰인다. `confirmed` 를 실을 수 있는 것은 그 프로젝트 창뿐이고(D18), MCP 는 그것을 받지 않는다(D19) | ① 쓰기마다 확인 — 개발 DB 에서 피로 ② 설정으로 끌 수 있는 확인 — 프로덕션 실수를 막는 마지막 자리를 끌 수 있게 된다 ③ 등급만 실은 확인(`confirmedGrade`) — 다른 SQL 에 재사용된다 | D45 |
| M3-D21 | 수동 커밋 세션 | 콘솔 탭 하나 = 고정 연결 하나, **열린 트랜잭션은 쉬어도 저절로 롤백하지 않는다** — 상태바에 열린 시간을 보이고, 탭 닫기 · 창 닫기 · 앱 종료 때 [커밋] [롤백] [취소] 를 묻는다(주인 M3-15). 행 상한 끊기 · 그리드 편집 실패도 그 트랜잭션을 끝내지 않는다(D7 · D9). 연결이 끊기면 DB 가 롤백하고 탭이 그것을 알린다 | 사람이 고친 것을 사람 모르게 버리지 않는다(M2 의 「사람 내용을 덮을 때 확인」 과 같은 방향). 열린 트랜잭션이 잡은 잠금은 상태바 표시로 사람이 본다 | ① DBX 식 300 s 유휴 롤백 — 잠금은 풀리지만 커피 한 잔에 작업이 사라진다 ② 유휴 경고 알림만 | — |
