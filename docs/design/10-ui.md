# 10. UI 설계 — 화면 · UI 스택 · 마우스/키보드

## 1. 원칙

1. **IntelliJ 사용자가 바로 쓸 수 있게** — 기본 키맵과 툴 윈도우 배치는 IntelliJ와 같게, 단축키 근육 기억 유지
2. **키보드만으로 모든 작업 가능** — 모든 기능은 액션으로 등록되어 "액션 찾기"(`⌘⇧A`)로 실행 가능
3. **마우스는 직접 조작** — 드래그(탭 · 패널 · 파일 · 브랜치), ⌘+클릭 이동, 거터 클릭, 우클릭 메뉴
4. **밀도 높은 화면** — 개발 도구다운 compact 기본(행 높이 22px, UI 폰트 13px), comfortable 모드 선택 가능
5. **무거운 뷰는 canvas** — 커밋 그래프 · DB 그리드 · 터미널은 canvas/WebGL 렌더링, 리스트 · 트리는 가상화

### 2.1 S1. 웰컴 / 프로젝트 런처

```
┌──────────────────────────────────────────────────────────────┐
│  Pitwall                                          ⌕ 프로젝트 검색 │
├────────────┬─────────────────────────────────────────────────┤
│ ▸ 프로젝트   │  ★ billing-api        ~/work/billing-api    main │
│   원격 호스트 │    web-console        ~/work/web-console   feat/x│
│   확장       │    infra (원격)       build-server:~/infra  main │
│            │    ...                                            │
│            │                                                   │
│            │  [새 프로젝트…]  [폴더 열기…]  [원격 호스트 추가…]        │
├────────────┴─────────────────────────────────────────────────┤
│ CLI: pitwall 설치됨 ✓   MCP: 연결 2   업데이트: 최신                │
└──────────────────────────────────────────────────────────────┘
```
- 행 표시: 이름, 경로, 현재 브랜치, 원격 여부, 즐겨찾기, 태그. 순서는 즐겨찾기 → 최근에 연 것 → 연 적 없는 것(이름순). 브랜치는 레지스트리에 없어 아직 보이지 않는다(git 상태를 읽는 기능이 생기면 채운다)
- 동작: Enter/더블클릭 열기(클릭은 고르기만), `⌘⌫` 목록에서 제거, 우클릭 메뉴(열기 · Finder · 외부 도구로 열기 · 제거). `⌘⌫` 는 검색 칸이 비어 있을 때만 제거한다 — 검색어를 지우려던 `⌘⌫` 가 프로젝트를 지우지 않게. 우클릭 메뉴 항목은 모두 액션이라 액션 찾기 · 키로도 닿는다. 우클릭 메뉴에는 단축키를 적지 않는다(§4.3 의 예외) — 메뉴가 열린 동안은 창 단축키가 꺼진다(팝업이 열리면 키는 팝업이 받는다)
- 폴더를 창에 드롭 → S3로. 파일을 드롭하면 `pitwall <파일>`(F2)과 같다 — 등록된 프로젝트 안이면 그 파일과 함께 열고, 아니면 그 파일로 S2. 「폴더 열기…」 · 드롭한 폴더가 이미 등록된 루트(또는 그 프로젝트의 미등록 워크트리에서 루트에 대응하는 폴더)면 S3 대신 그 프로젝트를 연다. 하위 폴더는 새 프로젝트다
- 레지스트리 파일이 정상이 아니면(`project.storage`) 그 이유를 배너로 보이고, 쓰기를 거절하는 상태(읽기 전용 · 메모리)면 새 프로젝트 · 제거를 끈다

### 2.2 S2. 프로젝트 찾기 팝업

```
┌──────────── src/main/kotlin/App.kt 를 열 프로젝트 ────────────┐
│ ⌕                                                          │
│ ▸ ~/work/billing-api          .git · build.gradle.kts  (추천) │
│   ~/work/billing-api/module-a  build.gradle.kts              │
│   ─────────────                                              │
│   폴더 직접 선택…                                               │
│   프로젝트 없이 파일만 열기                                         │
└────────────────────────────────────────────────────────────┘
```
- 화면 상단 중앙 팝업(검색 팝업과 같은 컴포넌트), ↑↓ 선택 · Enter 확정 · Esc 취소
- 후보 · 직접 고른 폴더 → S3. S3 에서 만들면 처음 경로를 다시 해석해, **만든 프로젝트가 그 경로를 담을 때만** 활성 워크트리(F2-5)와 그 파일 · 줄 · 열을 프로젝트 창에 넘긴다. 담지 않으면 프로젝트 창만 열고 그렇다고 알린다. 경로가 폴더(프로젝트 루트 · 워크트리)면 파일로 넘기지 않는다
- 한글 조합 중 Esc 는 조합만 취소하고 팝업을 닫지 않는다(S2 · S3 · 액션 찾기 공통)
- 「프로젝트 없이 파일만 열기」는 그 파일(실제 경로)의 단일 파일 뷰어 창(S4f)을 연다. 파일이 아니면(폴더 · 없는 경로) 열지 않고 S2 로 돌아가 이유를 보인다
- **S4f 단일 파일 뷰어 창**(M1-24): 프로젝트 창의 에디터 그대로(뷰어 · 편집 · `⌘S` 저장 · 외부 변경 · 강조 · 미저장 닫기 확인)이고 툴 윈도우(파일 트리 · 검색 · 터미널 등)가 없다 — 그 액션이 등록되지 않아 그 단축키는 이 창에서 아무것도 하지 않는다. 창 제목은 파일 이름. 같은 파일(실제 경로 — 링크로 와도 같다)의 창은 하나이고, 등록된 프로젝트에 없는 그 파일로 `pitwall <파일>[:줄[:열]]` 을 다시 하면 새 창 · S2 없이 그 창이 앞으로 오고 커서가 옮겨진다. 마지막 탭을 닫으면 창이 닫힌다. 상태바 왼쪽의 「프로젝트로 열기」(액션 `file.openAsProject`)는 그 파일을 다시 해석한다 — 그새 그 파일을 담는 프로젝트가 생겼으면 그 프로젝트 창을, 아니면 S2 를 연다. 단일 파일 창은 그대로 둔다(미저장 편집이 있을 수 있다)

**구역별 구성**

| 구역 | 내용 |
|---|---|
| 타이틀바/툴바 | macOS: 신호등 버튼 + 툴바 통합(overlay 타이틀바). 프로젝트 스위처, 브랜치 팝업, 검색 필드(클릭 시 Search Everywhere), 실행 구성 선택 · 실행 · 디버그 · 중지, "외부 도구로 열기" |
| 왼쪽 툴 윈도우 바 | 프로젝트(파일 트리) · 커밋(변경 목록) · DB 탐색기 · 검색 · 구조(아웃라인) |
| 하단 툴 윈도우 | 실행 · 디버그 · 문제 · 터미널 · Git(로그) · 쿼리 결과 · 검색 결과 |
| 오른쪽 툴 윈도우 바 | 알림 · 에이전트 활동(MCP 호출 로그/승인 대기) · (확장 패널) |
| 에디터 영역 | 탭 + 분할(가로/세로, 다중). 문서 타입은 아래 표 |
| 상태바 | 브랜치/ahead-behind, 문제 수, LSP 상태, 백그라운드 작업, **런타임(`node 22 · java 21 (mise)`)**, 원격 연결, MCP 연결 수, 인코딩/줄바꿈/커서 위치 — 각 항목 클릭 시 해당 팝업. 항목은 왼쪽 · 오른쪽 슬롯에 순서대로 놓이고, 자리(쪽 · 순서)는 `apps/desktop/src/status-bar/status-bar.tsx` 의 `STATUS_SLOTS` 한곳에서 정한다 — 기능이 그 자리로 항목 컴포넌트를 등록한다. 백그라운드 작업은 가장 최근 작업의 이름 · 진행 막대(전체 양을 모르면 불확정) · 취소 버튼과 나머지 수(누르면 모두 펼침) |

- 툴 윈도우는 IntelliJ와 같이 **도킹 위치 변경(드래그), 고정/플로팅/분리 창, 최대화**, 창 크기는 프로젝트별 기억
- 레이아웃 프리셋: 기본 / Git 리뷰(로그 + diff 넓게) / DB(탐색기 + 콘솔 + 결과) — 액션 또는 `⌃⌥1~3`

**에디터 영역 문서 타입**

| 문서 | 구성 |
|---|---|
| 코드 에디터 | 거터(줄번호 · git 변경 마커 · 브레이크포인트 · blame 주석 토글), 브레드크럼, 인라인 진단, 미니 툴바(읽기 전용 표시 · 리비전 표시) |
| Diff | side-by-side / unified 토글, 변경 간 이동, hunk 되돌리기/스테이징, 공백 무시 |
| 3-way 머지 | 좌(ours) · 중앙(결과) · 우(theirs), 충돌별 `≫ ≪ ✕` 버튼, 모두 적용 |
| Git 로그 | 2.5 참고 |
| 커밋 상세 / 파일 히스토리 / 선택 영역 히스토리 | 커밋 목록 + 변경 파일 + diff |
| SQL 콘솔 | 연결/스키마 선택 바, 에디터, 실행 버튼, 결과는 하단 "쿼리 결과" 또는 에디터 내 분할 |
| 테이블 데이터 | 필터(WHERE) · 정렬(ORDER BY) 입력 바 + 그리드 + 변경 대기 표시 + 제출/취소 |
| Redis 키 | 왼쪽 키 트리(패턴/구분자 `:` 그룹) + 오른쪽 타입별 뷰어(TTL · 크기) |
| 설정 / 확장 | 폼(JSON Schema 기반 자동 생성) + "파일로 편집" |

### 2.5 주요 툴 윈도우 상세

**전체에서 찾기 · 검색 결과** (`⌘⇧F` 팝업 → 하단 「검색 결과」)

M1-20 에서 정한 동작(`apps/desktop/src/search/`):

- 팝업은 상단 중앙(S5)이고 위에서부터 찾을 글자 + 토글(대소문자 · 단어 · 정규식), 범위(프로젝트 / 폴더 — 폴더 칸은 프로젝트 루트 기준 상대 경로) · 파일 마스크(쉼표로 나눈 글롭, `!` 로 시작하면 뺀다 — `*.rs, !*_test.rs`) · 벤더/생성 파일 빼기, 결과 목록(가상화, 한 줄 = 일치한 줄), 고른 결과의 읽기 전용 미리보기(파일 앞 1 MiB 를 읽어 그 파일의 일치를 모두 칠한다), 바닥 줄(찾는 중 · 줄 · 파일 수 · 「더 있음」 · 멈추기 · 툴 윈도우에서 열기)이다. 찾는 곳은 파일 트리의 루트(활성 워크트리 안의 프로젝트 루트)이고 ignore 는 늘 존중하고 숨김 파일은 찾지 않는다(`rg` 의 기본과 같다 — 옵션이 같으면 결과가 `rg` 와 같다)
- 칸이나 옵션을 바꾸면 도는 검색을 곧바로 닫고(Host 의 `search.text` 스트림이 끝난다) 120 ms 멈춘 뒤 새로 찾는다. 팝업을 닫아도 그 검색을 멈춘다. 다시 열면 마지막 옵션으로 다시 찾는다
- 키: `↑` `↓` `PageUp` `PageDown` 은 입력 칸에 포커스가 있어도 결과를 고르고, `Enter` 는 고른 결과를 그 줄 · 첫 일치 열에서 고정 탭으로 연다(검색한 워크트리를 함께 싣는다), `⌘Enter`(Win/Linux `Ctrl+Enter`)는 툴 윈도우로 고정, `Esc` 는 닫는다. 한글 조합 중의 `Enter` · `Esc` 는 조합에 쓴다
- 결과 상한은 Host 의 기본값(1만 줄)이고 넘으면 「더 있음」 을 단다
- 「툴 윈도우에서 열기」 는 도는 검색을 멈추지 않고 그대로 「검색 결과」 로 넘긴다. 툴 윈도우는 고정한 결과 **하나**를 파일별 트리(가상화)로 보이고, 다시 고정하면 앞의 것을 멈추고 바꾼다. 키: `↑` `↓` 이동, `→` 펼침, `←` 접음 · 줄에서 그 파일로, `Enter` · 더블클릭은 줄을 연다
- 파일 트리 우클릭 「이 폴더에서 찾기」 는 그 폴더(파일이면 그 파일의 폴더)를 범위로 팝업을 연다

**Search Everywhere · 파일로 이동 · 최근 파일 · 프로젝트 스위처** (`⇧⇧` · `⌘⇧O` · `⌘E` · `⌘⇧P`)

M1-19 에서 정한 동작(`apps/desktop/src/search-everywhere/`, 탭 범위는 결정 M1-D18):

- 상단 중앙(S5)의 팝업 **하나**에 탭 넷(전체 · 파일 · 액션 · 프로젝트)을 둔다. 액션 찾기(`⌘⇧A`) · 파일로 이동(`⌘⇧O`) · 프로젝트 스위처(`⌘⇧P`)는 이 팝업을 그 탭으로 연 것이고, `Tab` · `⇧Tab` 이 탭을 돈다. 한 창에 검색 팝업이 둘 뜨지 않는다 — 열린 동안 다른 검색 키는 돌지 않는다(창 단축키가 꺼진다). 파일 · 프로젝트 탭은 프로젝트 창에만 있고, 웰컴 · 설정 창에서는 탭 줄 없이 액션만 보인다(예전 액션 찾기와 같다)
- 전체 탭은 파일 · 액션 · 프로젝트를 그룹으로 6개씩 보이고, 더 있으면 그 탭으로 가는 「더 보기」 줄을 둔다
- 파일: Host 의 `search.files`(결정 M1-D5)로 창의 활성 워크트리(파일 트리의 루트)를 찾는다. 결과는 50개, 일치 글자를 칠하고 파일 이름 옆에 폴더를 흐리게 둔다. 요청은 한 번에 하나만 보낸다 — 응답을 기다리는 동안 친 글자는 마지막 것만 이어 보내고, Host 가 「바쁨」 이면 결과를 그대로 둔 채 250 ms 뒤 다시 보낸다. 팝업을 닫거나 · 파일을 보이지 않는 탭으로 가거나 · 질의를 비우면 재시도를 멈추고 도는 요청을 취소한다. 새 질의의 결과가 오면 첫 줄을 고른다(같은 질의의 결과가 다시 오면 고른 줄을 둔다). 이 창에서 최근에 본 파일이 질의에 맞으면 맨 위에 「최근」 을 달아 둔다. 빈 질의는 최근 파일만 보인다. `이름:줄[:열]`(`main.rs:12`)이면 줄 · 열을 떼고 찾아, 고르면 그 줄 · 열로 연다. 여는 워크트리는 그 행의 것이다 — Host 결과는 찾을 때의 워크트리, 최근 파일은 그 탭을 연 워크트리(없으면 메인 체크아웃)이고, 고를 때의 트리가 아니다. 그 워크트리가 사라졌으면 Host 가 열기를 거절하고 창이 「열지 못했다」 를 알린다
- 최근 파일(`⌘E`)은 탭 줄 없이 이 창에서 활성이 됐던 에디터 파일을 최근 순서로 보이고(닫은 탭의 파일도 남는다, 50개), 바로 전 파일을 고른 채 연다 — Enter 한 번으로 앞뒤 파일을 오간다. 고르면 그 탭을 연 워크트리로 연다. 목록은 창의 메모리에만 있다 — 다시 시작한 뒤의 복원은 상태 복원(M1-25)이 정한다
- 프로젝트: 등록된 프로젝트를 웰컴 창과 같은 순서로 보이고 이 창의 것에 「이 창」 을 단다. 고르면 그 프로젝트의 창을 열거나, 이미 열려 있으면 앞으로 가져온다(`open_project_window`). 이 창의 것을 고르면 팝업만 닫는다

**실행 / 디버그**
- 실행: 구성별 탭, 콘솔(xterm.js) + 툴바(재실행 · 중지 · 스크롤 고정 · 지우기 · 검색), 포트 표시
- 디버그: 왼쪽 프레임(스레드/콜스택) · 가운데 변수/워치 · 콘솔 탭, 상단 스텝 툴바

### 2.8 빈 상태 · 오류 상태
- 각 툴 윈도우는 빈 상태에 다음 행동을 제시 (예: DB 탐색기 비어 있음 → "연결 추가", "감지된 연결 3개 가져오기")
- 오류는 토스트(일시) + 알림 툴 윈도우(기록), 백그라운드 작업 실패는 상태바 아이콘 강조
  - 토스트는 sonner(MIT), 상태바 위 오른쪽 아래. 알림 기록은 창마다 메모리에 둔다(최근 200개, 창을 닫으면 사라진다)
  - 토스트는 폭주해도 쌓이지 않는다: 같은 등급 · 같은 제목은 떠 있는 토스트 하나를 덮어쓰며 「(×N)」 을 붙이고, 동시에 떠 있는 토스트는 3개까지다 — 넘는 알림은 기록에만 남는다
  - 강조는 알림 툴 윈도우를 볼 때까지 남는 「보지 않은 오류」 수다. 알림 툴 윈도우가 화면에 보이는 동안(탭이 앞이고 dock 이 펼쳐짐) 온 오류는 본 것으로 친다. 상태바의 알림 아이콘을 누르면 알림 툴 윈도우를 연다(열려 있으면 접는다)
  - 작업 취소는 실패가 아니므로 알리지 않는다

## 4. 키보드

### 4.1 키맵 정책 — 기본 키맵 1개 + 사용자 커스텀

- **내장 프리셋은 제공하지 않는다** (VS Code · Zed 등 다른 키맵 프리셋을 앱에 넣지 않음)
- 단, **키맵 확장은 가능** — 확장(07, L1 선언형)으로 다른 키맵이나 단축키 묶음을 배포 · 설치할 수 있다 (4.6)
- 제공하는 것은 **Pitwall 기본 키맵 하나** — IntelliJ 기본 키맵을 기준으로 구성
  - 같은 키맵의 OS별 표기만 다름 (macOS는 IntelliJ macOS, Windows/Linux는 IntelliJ Windows 키 배치)
- 사용자는 **개별 단축키를 자유롭게 변경 · 추가 · 제거** 가능 (4.5)
  - 에디터의 실행 취소 · 실행 복귀도 키맵 액션(`editor.undo` · `editor.redo`)이라 바꿀 수 있다. 단 macOS 는 Edit 메뉴의 OS 기본 항목(`undo:` · `redo:`)이 `⌘Z` · `⌘⇧Z` 를 늘 갖는다 — 웰컴 · 설정 창의 입력 칸이 그것으로 되돌린다. 그래서 macOS 에서 이 두 키를 키맵에서 지워도 에디터에서는 메뉴를 거쳐 여전히 되돌린다(Win/Linux 는 메뉴 항목도 키맵 액션이라 지우면 키가 빠진다)
- 기본 키맵은 앱 버전과 함께 관리. 사용자 변경분은 기본 키맵 위에 덮어쓰는 차이(diff)로만 저장 → 앱 업데이트로 기본 키맵이 바뀌어도 사용자 변경은 유지

### 4.4 키맵 엔진 설계 (`packages/keymap`)

| 요구 | 설계 |
|---|---|
| 컨텍스트별 바인딩 | VS Code식 `when` 조건: `editorFocus`, `editorReadonly`, `diffFocus`, `gitLogFocus`, `dbGridFocus`, `sqlConsoleFocus`, `terminalFocus`, `debugging`, `popupOpen` 등. 우선순위: 포커스된 컴포넌트 → 툴 윈도우 → 전역 |
| 키 조합 | 단일, **더블 탭**(`⇧⇧`, `⌥⌥` 유지 + 방향키), 연속 키(chord: `⌘K ⌘S` 등 — 기본 키맵에선 미사용, 사용자 커스텀용) |
| 물리 키 기준 | `KeyboardEvent.code` 기반 매칭 → 한글 IME 상태에서도 단축키 동작 (`event.key`가 'ㅠ' 등으로 들어오는 문제 회피), 표시용 라벨은 레이아웃 기준 |
| IME 조합 중 | `isComposing` 중에는 에디터 입력 우선, 단축키 무시 (Enter로 한글 조합 확정 시 실행되는 문제 방지) |
| 터미널 | 터미널 포커스 시 대부분 키를 셸로 전달. 터미널은 `terminalFocus` 컨텍스트를 내고, 그동안 앱이 받는 키는 ① `when` 이 `terminalFocus` 를 읽는 바인딩(터미널 새 탭 `⌘T` · 탭 닫기 `⌘W` · Win/Linux 복사 `Ctrl+Shift+C` · 붙여넣기 `Ctrl+Shift+V`, 사용자가 keymap.toml 에 `when = "terminalFocus"` 로 더한 키) ② 창 단위 액션(액션 찾기 · Search Everywhere 와 그 탭(파일로 이동 · 최근 파일 · 프로젝트 스위처) · 툴 윈도우 열기 `toolWindow.*` · 설정 · 외부 도구 · 탭 전환기)뿐이다. 단 ②의 키여도 Shift · Alt 없는 `Ctrl+글자`는 셸의 제어 문자라 셸로 간다 — Win/Linux 의 최근 파일 `Ctrl+E`(readline 줄 끝)가 그렇고, `Ctrl+Shift+N` · `Ctrl+Shift+P` 는 앱이 받되 `Ctrl+N` · `Ctrl+P` 는 셸로 간다 — 나머지(`Ctrl+C` · `Ctrl+W` · 에디터 액션)는 셸로 간다. macOS 복사 · 붙여넣기는 네이티브 Edit 메뉴의 `⌘C` · `⌘V`. 규칙은 `apps/desktop/src/terminal/terminal-keys.ts`(M1-15). `Esc` 두 번 → 에디터는 아직 없다 |
| OS 예약 키 | macOS `⌘H/⌘M/⌘Q/⌘Tab/⌃↑`(Mission Control) 등은 배정 불가로 표시. F키는 "F1~F12를 표준 기능 키로 사용" 안내 |
| 정의 형식 | 기본 키맵은 앱 내장(`keymaps/default.toml`, OS별 키 표기 포함) → 확장 키맵(선택 시) → 사용자 덮어쓰기 `~/.config/pitwall/keymap.toml` 순으로 병합 |
| 네이티브 메뉴 동기화 | 메뉴 항목의 accelerator를 키맵에서 생성, 키맵 변경 시 메뉴 재구성. 웹뷰의 키맵 키와 겹치는 메뉴 항목은 OS 기본 항목(예: macOS `performClose:`)이 아니라 키맵 액션 항목으로 둔다 — OS 기본 항목은 웹뷰를 거치지 않아 같은 눌림이 두 동작을 일으킨다. 파일 메뉴의 「닫기」(`window.close`)와 「저장」(`editor.save`), Win/Linux Edit 메뉴의 「실행 취소」 · 「실행 복귀」(`editor.undo` · `editor.redo`)가 그렇다. OS 기본 항목(muda `PredefinedMenuItem`)의 단축키는 키맵이 바꿀 수 없고, Windows 의 기본 실행 취소 · 다시 실행 · 잘라내기 · 복사 · 붙여넣기 · 모두 선택은 고르면 그 키(Ctrl+Z · Ctrl+Y · Ctrl+X · Ctrl+C · Ctrl+V · Ctrl+A)를 `SendInput` 으로 다시 보낸다 — 기본 키맵이 그 키를 다른 액션에 주면 그 항목은 키맵 액션 항목으로 바꾼다(Ctrl+Y 는 줄 삭제라 기본 「다시 실행」 이 줄을 지웠다). 메뉴의 accelerator 는 `when` 없는 바인딩에서만 오므로 키맵 액션 항목의 키는 `when` 을 두지 않고, 액션이 `enabled` 로 범위를 가린다(`editor.undo` 는 포커스가 에디터 밖의 입력 칸이면 꺼진다). 「종료」(⌘Q)도 OS 기본 항목(`terminate:`)이 아니라 모든 창에 닫기를 요청하는 항목이다 — 창마다 미저장 확인을 지난다(§5.2) |

### 4.5 키맵 커스텀

**설정 > 키맵 화면**

```
┌ 키맵 ─────────────────────────────────────────────────────────┐
│ ⌕ 액션 이름 검색        [⌨ 키로 검색]   [ ] 변경한 것만 보기          │
├───────────────────────────────────────────────────────────────┤
│ ▾ Git                                                         │
│    blame 주석 토글            ⌃⌥A                               │
│    푸시                       ⌘⇧K                               │
│  • 파일 히스토리               ⌃⌥H → ⌘⌥H   (변경됨)              │
│ ▾ DB                                                          │
│    쿼리 실행                  ⌘↩      [SQL 콘솔]                  │
│ ...                                                           │
├───────────────────────────────────────────────────────────────┤
│ [단축키 추가] [제거] [기본값으로]          [가져오기] [내보내기] [전체 초기화] │
└───────────────────────────────────────────────────────────────┘
```

| 기능 | 설계 |
|---|---|
| 단축키 지정 | 액션 선택 → 키 입력 캡처(더블 탭 · 연속 키 포함) → 저장. 한 액션에 여러 단축키 허용 |
| 마우스 단축키 | `⌘+클릭`, `⌥⇧+클릭`, 마우스 4/5 버튼 등도 같은 화면에서 재지정 가능 |
| 적용 범위 | 액션별 컨텍스트(`when`) 표시, 고급 옵션에서 범위 변경 (예: SQL 콘솔에서만) |
| 충돌 처리 | 같은 컨텍스트에 이미 할당된 키면 경고 → [다른 액션에서 제거하고 할당] / [둘 다 유지] / [취소] |
| 금지 키 | OS 예약 키는 할당 불가 표시 |
| 키로 검색 | 키 조합을 눌러 그 키가 할당된 액션 찾기 |
| 변경 표시 | 기본값과 다른 항목 강조, 항목별 "기본값으로" |
| 빠른 재할당 | 액션 찾기(`⌘⇧A`) 결과에서 바로 단축키 지정, 툴팁/메뉴의 단축키 우클릭 → "단축키 변경" |
| 가져오기/내보내기 | `keymap.toml` 파일로 내보내기 · 가져오기 (다른 기기와 공유) |
| 파일 편집 | `~/.config/pitwall/keymap.toml` 직접 편집 가능, 저장 즉시 반영(파일 감시), 오류는 알림으로. `schema` 줄이 없으면 처음 읽을 때 앱이 `schema = 1` 을 맨 위에 넣어 다시 쓰고 원본을 `$STATE/backup/` 에 둔다(03 §5) |

```toml
# ~/.config/pitwall/keymap.toml — 기본 키맵과의 차이만 저장
schema = 1

[[bindings]]                         # 변경
action = "git.file_history"
key = "cmd+alt+h"

[[bindings]]                         # 추가 (기존 키 유지 + 하나 더)
action = "search.everywhere"
key = "cmd+shift+space"
mode = "add"

[[bindings]]                         # 컨텍스트 지정
action = "db.query.execute"
key = "cmd+enter"
when = "sqlConsoleFocus"

[[unbind]]                           # 기본 단축키 제거
action = "vcs.popup"
key = "ctrl+v"
```

- 키 표기: `cmd`/`ctrl`/`alt`/`shift`, 더블 탭 `"shift shift"`, 연속 키 `"cmd+k cmd+s"`, 마우스 `"cmd+click"`
- 프로젝트별 키맵은 두지 않음 (전역 하나)

### 4.6 키맵 확장

앱에는 기본 키맵만 넣고, 다른 키맵은 확장으로 제공받는다.

| 확장 유형 | 내용 | 적용 방식 |
|---|---|---|
| **베이스 키맵** | 전체 키맵 (예: 누군가 만든 "VS Code 스타일" 키맵) | 설정 > 키맵에서 베이스로 선택 → 기본 키맵 대신 사용. 하나만 선택 가능 |
| **바인딩 묶음** | 일부 단축키 추가/변경 (예: "Vim 스타일 이동", 특정 확장 기능용 단축키) | 켜면 베이스 위에 병합. 여러 개 동시 사용 가능, 순서 지정 |

```toml
# extension.toml (키맵 확장 예)
[contributes.keymaps.vscode-style]
kind = "base"                       # base | bindings
file = "keymaps/vscode-style.toml"  # 기본 키맵과 같은 형식, OS별 키 표기 포함
```

- 병합 순서: 베이스(기본 또는 확장) → 바인딩 묶음(사용자 지정 순서) → 사용자 `keymap.toml`
- 사용자 변경분은 베이스가 바뀌어도 유지되며, 베이스를 바꿀 때 사용자 변경과 충돌하는 항목을 미리 보여줌
- 확장 키맵에 없는 액션은 기본 키맵 값으로 채움 (액션이 추가돼도 단축키가 비지 않도록)
- 키맵 화면에 각 단축키의 출처(기본 / 확장명 / 사용자) 표시
- WASM 플러그인(L2)이 등록한 액션도 확장 매니페스트에서 기본 단축키를 선언 가능

탭의 뜻(M1-09, 결정 M1-D1 — `apps/desktop/src/editor/editor-tabs.ts`):

- 탭 하나 = 파일 하나. 같은 파일을 다시 열면 새 탭 없이 그 탭이 활성이 된다(지금 그룹의 것을 먼저). 키는 정규화한 실제 경로라 심링크로 열어도 같은 탭이다. `⌘\` 로 나눈 그룹은 같은 파일을 보여도 커서 · 스크롤이 따로다
- 미리보기 탭은 **그룹마다 하나**다. 고정으로 다시 열거나 고정(pin)하면 보통 탭이 된다
- 고정(pin)한 탭은 「다른 탭 닫기」(`⌘⌥W`)가 닫지 않는다. ×(가운데 클릭)로는 닫힌다
- 탭 단축키(`⌘W` · `⌘⌥W` · `⌘\` · `⌃Tab`)와 우클릭 메뉴는 **활성 탭**에 한다 — 활성 패널이 에디터 탭이면 그것, 툴 윈도우를 보는 중이면 마지막으로 쓴 에디터 탭이다. 외부 도구 문맥(`⌘⌥E` 의 워크트리 · 파일 · 줄 · 열)도 같다
- 탭은 자기를 연 워크트리를 기억한다. 그 탭의 파일 읽기와 외부 도구(`⌘⌥E` · Finder 에서 보기)는 창의 지금 활성 워크트리가 아니라 그 워크트리로 나간다
- macOS `⌘W`(액션 `window.close`)는 **에디터 탭이 있으면 활성 탭을, 없으면 창을** 닫는다(VS Code 와 같다). 파일 메뉴의 「닫기」 항목이 같은 액션이다 — 키와 메뉴 accelerator 가 한 액션으로 모이고, 같은 눌림이 둘로 와도 한 번만 돈다(§4.4 「네이티브 메뉴 동기화」). 경우별 동작:
  - 한글 조합 중: 키맵은 키를 보지 않는다. 메뉴로 오면 위 규칙대로(탭이 있으면 탭) 닫는다 — 탭이 있는 창이 통째로 닫히지 않는다
  - 창의 팝업(우클릭 메뉴 · 전환기 등)이 열린 동안: 키도 메뉴도 아무것도 닫지 않는다. 액션 찾기가 열린 채 메뉴에서 고르면 팝업을 닫고 실행한다(다른 메뉴 액션과 같다)
  - 웰컴 · 설정 창: 창을 닫는다
  - Windows · Linux: 탭 닫기는 `Ctrl+F4`, 창 닫기는 OS 의 `Alt+F4` 다. 메뉴 「닫기」는 키 없이 같은 액션이다
- 편집 · 저장(M1-13, `apps/desktop/src/editor/documents.ts` · `live-text.ts`):
  - 텍스트 뷰어는 기본으로 편집할 수 있다. 읽기 전용은 이 앱이 고칠 수 없는 문서뿐이다 — 5 MiB 초과(결정 M1-D9) · UTF-8 이 아님(결정 M1-D12) · 쓰기 권한 없음
  - 편집 중인 텍스트 · undo 기록 · 미저장 여부는 탭이 아니라 **문서**가 갖는다. 같은 파일을 보는 두 그룹은 한쪽에서 고친 것이 곧바로 다른 쪽에 보이고, undo 도 한 기록이다. 탭을 다른 그룹으로 옮기거나 뷰를 다시 만들어도 편집 · undo · 선택이 남는다
  - 저장은 `⌘S`(액션 `editor.save`, 파일 메뉴 「저장」)로만 한다 — 자동 저장 없음(결정 M1-D13). 활성 탭의 문서를 저장한다. 「모두 저장」(`editor.saveAll`)은 기본 키 없이 액션 찾기에 있다. 저장은 늘 읽을 때(또는 마지막 저장)의 `version` 을 기대 값으로 넘긴다 — 그사이 디스크가 바뀌었으면 덮지 않고 아래 「디스크에서 바뀜」 배너를 띄운다
  - 줄바꿈 · BOM 은 읽은 대로 돌려 쓴다. 줄바꿈이 섞인 파일은 줄을 `\n` 으로만 나눠 `\r` 을 글자로 보인다 — 고치지 않은 줄의 바이트가 그대로 남는다. 줄 끝의 `\r` 은 줄바꿈의 일부로 본다 — 그 뒤(End 키 자리)에 치거나 붙여 넣은 글자는 `\r` 앞에 들어가 `\r\n` 이 갈라지지 않는다. 지우기는 옮기지 않는다(줄 끝에서 Backspace 는 `\r` 을 지운다)
  - 미저장 표시: 탭 이름 앞의 `●`. 미리보기 탭의 문서에 미저장 편집이 생기면 보통 탭이 된다(§5.4 「편집 시작」)
  - 그 문서를 보는 **마지막** 탭을 닫을 때 미저장 편집이 있으면 [저장] [저장 안 함] [취소] 를 묻는다(`⌘W` · 탭 닫기 · 다른 탭 닫기 · 탭의 × · 가운데 클릭). 같은 파일을 다른 그룹이 아직 보이면 묻지 않는다. 창을 닫을 때(닫기 단추 · `⌘W`)와 앱을 끝낼 때(`⌘Q` — 모든 창에 닫기를 요청한다)는 그 창의 미저장 문서를 모아 한 번 묻는다. [저장] 이 충돌 · 실패로 끝나면 닫지 않는다. 한 창에서 [취소] 하면 앱 종료도 멈춘다(그 전에 닫힌 창은 닫힌 채다)
  - 앱이 끝나는 길은 `⌘Q`(창 닫기 요청) · Dock · 로그아웃(`terminate:`) · 업데이트 재시작 · perf 측정 종료(`app.exit`)다. 미저장 확인은 창 닫기 요청을 지나는 길만 묻는다 — 새 종료 길을 더하면 창 닫기 요청을 지나게 한다. 업데이트를 설치하면 곧바로 다시 시작하지 않고 `⌘Q` 와 같이 모든 창에 닫기를 요청해, 다 닫히면 다시 시작한다. 한 창이 [취소] 하면 다시 시작하지 않고 「다음에 시작할 때 새 버전이 뜬다」 고 알린다. Dock 메뉴 · 로그아웃의 종료는 묻지 않는다(12-m1-plan.md 「M1 에서 하지 않는 것」)
- 외부 변경(F3-6 · F4-2, M1-13): 창의 파일 감시(`fs.changed`)가 열린 문서를 건드리면 디스크와 맞춘다. 자기 저장이 돌아온 이벤트는 크기 · 수정 시각 · `version` 으로 걸러 배너가 뜨지 않는다
  - 미저장 편집이 없으면: 바뀐 곳만 새 내용으로 바꾼다 — 커서 · 선택 · 스크롤이 제자리다. 이것도 undo 로 되돌릴 수 있다
  - 미저장 편집이 있으면: 받지 않고 탭 위에 배너 「디스크에서 바뀜」 + [디스크 것 받기] [내 것 유지] [비교]. [비교] 는 뷰어 자리에 내 것(왼쪽)과 디스크(오른쪽)를 나란히 보인다(`@codemirror/merge`). [내 것 유지] 뒤의 저장은 지금 디스크를 덮는다
  - 내용이 그대로이고 수정 시각만 바뀌었으면(`touch` · 같은 내용을 다시 쓴 포매터 · `git checkout`) 배너 없이 아는 `version` 만 바꾼다
  - 줄 구분이 바뀌면(LF 파일에 CRLF 줄이 생기는 등) 문서를 통째로 다시 읽는다 — 커서는 남지 않고 undo 로 되돌릴 수 없다. 다시 읽는 동안 친 글자가 있으면 바꾸지 않고 「디스크에서 바뀜」 배너로 둔다. 미저장 편집은 사람이 [디스크 것 받기] · [저장 안 함] 을 고르지 않으면 버리지 않는다
  - 지워졌으면 「디스크에서 지워졌다」 배너 — 내용은 남고, 저장하면 다시 만든다. 같은 때 같은 내용(`version`)의 파일이 생겼거나 바뀌었으면(새 경로는 감시 백엔드 · 원자 쓰기에 따라 `created` 로도 `modified` 로도 온다) 「다른 이름으로 옮겨진 것 같다」 + [새 이름으로 열기]
  - 창의 파일 감시는 활성 워크트리만 본다 — 다른 워크트리에서 연 탭의 외부 변경은 저절로 보이지 않는다(저장은 여전히 덮지 않는다)
- 미리보기(M1-22, 결정 M1-D11 — `apps/desktop/src/editor/image-viewer.tsx` · `markdown-viewer.tsx` · `markdown.ts`):
  - 이미지(png · jpg · gif · webp · bmp · ico · svg): 위 막대에 [맞춤] [실제 크기] 와 해상도(그린 뒤) · 파일 크기. 맞춤은 창보다 큰 이미지만 줄인다. 바이트는 `fs.read` 범위 읽기를 이은 Blob URL 이다(asset 프로토콜을 쓰지 않는다). svg 도 `<img>` 로만 그려 그 안의 스크립트가 돌지 않는다. 50 MiB 를 넘으면 열지 않는다(결정 M1-D9)
  - Markdown: 위 막대에 [에디터] [나란히] [미리보기]. 처음 열면 미리보기이고, 고른 모드는 탭마다 남는다. 에디터 쪽은 텍스트 뷰어 그대로다(편집 · 저장 · 디스크 배너). 미리보기는 `markdown-it`(raw HTML 끔 — 문서 안의 HTML 은 글자로 보인다, GFM 표 · 취소선 · 읽기 전용 체크박스)이고, 문서가 바뀌면(편집 · undo · 디스크에서 받음) 바뀜이 멈추고 150 ms 뒤에 다시 그린다
  - Markdown 안의 이미지: 그 파일 폴더 기준 상대 경로이고 탭의 루트 안일 때만 이미지와 같은 길(범위 읽기 → Blob URL)로 그린다. 절대 경로 · 루트 밖(`../`) · 원격(`https:`) 이미지는 읽지 않고 대체 글자(점선 상자)로 보인다. 루트 안이지만 루트 밖을 가리키는 심링크는 Host 가 거절해 같은 대체 글자다
  - Markdown 안의 링크: 누름을 모두 가로채 앱 창은 이동하지 않는다. http(s) · mailto 는 외부 브라우저(메일 앱)로, 루트 안 상대 경로는 앱의 탭으로, `#제목` 은 미리보기 안 그 제목으로 간다. 그 밖(`javascript:` · `file:` · `data:` · 루트 밖)은 아무것도 하지 않는다. 가운데 클릭도 아무것도 열지 않는다
  - 열린 이미지는 디스크에서 바뀌어도 저절로 다시 읽지 않는다(탭을 닫았다 다시 열면 새것)
- 대용량 · 바이너리 · 인코딩(M1-23, 결정 M1-D9 · M1-D10 · M1-D12 — `apps/desktop/src/editor/viewers.tsx` · `hex-viewer.tsx` · `raw-text-viewer.tsx`). 기준값은 `crates/pw-fs/src/limits.rs` 한 곳이고 에디터는 같은 값을 `apps/desktop/src/editor/limits.ts` 에 둔다(시험이 둘을 맞춘다). 판정 · 텍스트 검색 · 구문 강조가 같은 상수를 쓴다
  - 크기 등급은 `fs.stat` 의 크기로만 정한다: 5 MiB 이하는 편집 + 강조, 50 MiB 이하는 읽기 전용(강조 · 줄바꿈 끔, 위 막대에 까닭), 넘으면 **한 바이트도 읽지 않고** 「열지 않음」 + [앞부분 1 MiB 보기] [hex 로 보기] [다음에서 열기…]
  - 일반 파일이 아닌 것(FIFO · 장치 · 소켓, 그것을 가리키는 링크 · 깨진 링크)은 읽지 않고 「일반 파일이 아니어서 열지 않는다」 + [다음에서 열기…] 만
  - 1만 자를 넘는 줄이 하나라도 있으면 강조 · 줄바꿈을 끈다(편집은 된다). 에디터는 지금 줄바꿈(soft wrap)을 켜는 설정이 없어 늘 끈 채다
  - 바이너리(앞 8 KiB 에 NUL)는 hex 뷰어로 연다: 읽기 전용, 한 줄 = 오프셋 · 16바이트(8바이트마다 한 칸 더) · ASCII(출력할 수 없는 바이트는 `.`). 보이는 줄만 그리고, 바이트는 보이는 줄이 걸친 64 KiB 페이지만 `fs.readBytes` 로 읽는다 — 1 GB 파일 끝으로 가면 그 페이지만 읽는다. 요청 중인 페이지는 다시 요청하지 않고 그 응답은 화면이 옮겨 갔어도 받아 둔다(느린 Host 에서 스크롤마다 요청이 쌓이지 않게). 스크롤 · ↑↓ · PageUp/PageDown · Home/End(`⌘↑` · `⌘↓`). `⌘L`(Windows · Linux `Ctrl+G`)은 hex 뷰어에 포커스가 있을 때 오프셋으로 이동이다 — 10진수(`4096`)나 16진수(`0x1000` · `1000h`), 끝을 넘으면 마지막 바이트. 고른 바이트는 hex · ASCII 두 칸에서 강조한다
  - 탭 우클릭 · 액션 찾기의 「텍스트로 열기」 · 「hex 로 열기」 는 **그 탭의** 뷰어만 바꾼다(같은 파일의 다른 탭은 그대로). 텍스트로 읽지 않은 문서(바이너리 · 이미지)를 텍스트로 열면 그 탭이 앞에서 50 MiB 까지 읽어 읽기 전용으로 보인다(UTF-8 로 읽을 수 없는 바이트는 �). 열지 않은 큰 파일의 [앞부분 1 MiB 보기] 도 같은 읽기 전용 텍스트다. 「기본 뷰어로 열기」 는 덮어쓴 뷰어를 걷는다. 이 텍스트는 문서 모델 밖이라 저장 · 미저장 확인 · 디스크 맞추기 대상이 아니다
  - UTF-8 이 아닌 텍스트는 Host 가 `chardetng` 로 인코딩을 짐작해 `encoding_rs` 로 풀어 보낸다(UTF-16 은 BOM 으로). 에디터는 그 텍스트를 읽기 전용으로 보이고 위 막대에 「EUC-KR 로 읽었다 · UTF-8 이 아니라 읽기 전용으로 연다」, 상태바의 인코딩 항목에 그 이름이 나온다. 편집 키 · `⌘S` · 닫기 확인 어느 길로도 디스크에 쓰지 않는다
  - 거의 UTF-8 인 텍스트(쓰는 중인 로그 · 끝이 잘린 파일처럼 깨진 바이트가 조금 섞인 것)는 짐작하지 않고 UTF-8 로 풀어 깨진 바이트만 � 로 보인다. 기준은 유효한 멀티바이트 글자가 유효하지 않은 시퀀스의 16배 이상인가다(`crates/pw-fs/src/judge.rs` `MOSTLY_UTF8_RATIO` — 다른 인코딩의 텍스트를 UTF-8 로 읽었을 때 그 비율은 1 에 못 미친다). 판정의 `lossy` 가 켜지고 읽기 전용이다(저장하면 깨진 바이트가 � 로 바뀐다). 위 막대는 「UTF-8 로 읽었다 · 깨진 바이트가 있어(�) 읽기 전용으로 연다」, 상태바는 「UTF-8(깨진 바이트 있음)」. 에디터는 Host 판정의 `editable` 과 따로 인코딩이 `UTF-8` 이 아니거나 `lossy` 면 읽기 전용으로 연다
  - 미저장 편집이 있는 문서가 읽기 전용이 되면(편집하는 사이 디스크의 파일이 같은 글자의 다른 인코딩으로 다시 저장됨 · 쓰기 권한이 없어짐) `⌘S` · 「모두 저장」 · 닫기 확인의 「저장」 은 쓰지 않고 「저장하지 못했다」 알림(이제 읽기 전용이라 쓰지 않았다, 편집은 탭에 남아 있다)을 띄운다. 닫기 확인의 「저장」 은 창 · 탭을 닫지 않는다
- 구문 강조(M1-17, `apps/desktop/src/editor/extensions/highlight.ts` · `syntax-sessions.ts`): Host 의 구문 분석 서비스(`syntax.*`, 07-extensibility.md §4.2)가 낸 구간을 decoration 으로 칠한다
  - 문서(와 그 언어)마다 서비스 문서 하나다 — 같은 파일을 두 그룹이 보여도 하나이고, 그 문서를 보는 마지막 탭이 닫히면 닫는다. 편집은 문서 모델의 바뀜에서 받아 `syntax.edit` 으로 보낸다
  - 뷰마다 화면 범위(CodeMirror 가 그리는 줄)만 묻고, 스크롤해 받은 범위를 벗어나면 다시 묻는다. 편집하면 옛 강조를 바뀜에 맞춰 옮겨 둔 채 다시 묻는다 — 응답 전에는 옛 강조가 남는다. 그사이 또 고쳤으면 지난 버전의 응답을 지금 위치로 옮겨 칠하고 다시 묻는다(버리기만 하면 왕복이 타자 간격보다 길 때 강조가 따라오지 못한다). 지난 버전의 빈 응답은 칠하지 않고 다시 묻는다 — 서비스는 새 편집이 와서 그만둔 파싱을 빈 구간으로 답하므로, 칠하면 화면 강조가 한 왕복 동안 지워진다
  - 서비스 호출이 실패하면(연결이 끊김 등) 옛 강조를 둔 채 물러섰다가 지금 텍스트로 다시 연다. 물러서는 시간은 0.25초에서 실패마다 두 배, 30초에서 멈추고, 강조를 받으면 처음으로 돌아간다. 네 번 이어 실패하면 UI 로그에 한 번 남긴다
  - 언어는 문서 언어 상태(`apps/desktop/src/editor/language.ts`)의 쓰는 언어다: 사람이 고른 것(상태바, M1-18) ?? 문서를 열 때의 `lang.detect` ?? Plain Text(`"Text"`). 고른 값은 문서 단위이고 그 문서를 보는 마지막 탭을 닫으면 잊는다
  - 강조하지 않는 문서: Plain Text, 문법이 없는 언어(결정 M1-D3 의 19개 밖), 대용량 기준 밖(5 MiB 초과 · 1만 자 넘는 줄, 결정 M1-D9 — 위 「대용량 · 바이너리 · 인코딩」 의 기준값), 서버가 끈 문서(`off`). 편집으로 기준을 넘어 서버가 끄면 다시 읽을 때까지 꺼진 채다
  - 색은 테마의 `syntax.<토큰>`(07-extensibility.md §3)을 CSS 변수로 읽는다 — 테마 · 외관을 바꾸면 다시 묻지 않고 색만 바뀐다
- 탭 더블클릭의 최대화는 펼쳐 있던 툴 윈도우 dock 만 접고, 다시 하면 그것만 편다
- 탭이 하나도 없으면 가운데는 빈 영역 표시(열린 파일 없음 + 쓸 수 있는 액션의 단축키)다. 「에디터 영역」 자리 패널은 없다
- 열린 탭은 레이아웃 저장본(localStorage, 프로젝트 공용)으로 복원하지 않는다 — 프로젝트 · 워크트리별 상태(결정 M1-D19)가 M1-25 에서 복원한다
- 「창 밖으로 → 새 창」 드래그는 아직 없다

M1-14 에서 정한 동작(`apps/desktop/src/file-tree/`):

- 키보드는 IntelliJ 와 같다: `↑` `↓` 이동, `→` 펼침 · 첫 자식, `←` 접음 · 부모, `Home` `End` `PageUp` `PageDown`, `Enter` 는 파일이면 고정 탭 · 폴더면 펼침/접음. 키보드로 고르는 것만으로는 미리보기 탭을 열지 않는다. 클릭으로 연 미리보기는 포커스를 트리에 남기고, 고정 탭으로 열면 다음 프레임에 그 탭의 뷰가 있으면 에디터로 포커스를 옮긴다(처음 여는 파일은 읽기가 끝나기 전이라 트리에 남는다 — M1-25 「에디터로 포커스」 와 함께 다시 본다)
- speed search 는 지금 보이는(펼쳐진) 행의 이름에서 대소문자 없이 부분 일치로 찾는다. 첫 글자는 트리가 받고 그 뒤는 위에 뜨는 입력 칸이 받는다(두 번째 글자부터 IME 조합이 된다). `↑` `↓` 앞뒤 일치, `Enter` 열기, `Esc` 닫기
- `.gitignore` 로 무시된 항목은 기본이 흐림(기울임)이고, 툴 윈도우 머리의 토글(액션 `fileTree.toggleIgnored`)로 숨긴다. 숨김 중에도 고른 항목과 그 조상은 보인다 — 「프로젝트 뷰에서 선택」 한 무시된 파일이 숨은 채로 남지 않게
- 벤더 · 생성 · 문서 흐림(M1-02)은 **파일만**, 경로 규칙과 `.gitattributes` 로만 정한다(`lang.detect` 에 파일 앞부분을 넘기지 않는다 — 폴더를 펼칠 때마다 그 안 파일을 읽지 않게). 앞부분을 봐야 하는 생성 파일 규칙은 트리에서 흐려지지 않는다
- 루트 밖을 가리키는 심링크(결정 M1-D8)는 「루트 밖을 가리킴」 을 달고 펼치거나 열지 않는다. 우클릭의 경로 복사는 되고 Finder · 외부 도구는 꺼진다
- `⌥F1` 「다음에서 선택/열기」 팝업의 첫 항목이 「프로젝트 뷰」 다: 활성 탭의 파일까지 조상을 펼쳐 고르고 화면 안으로 굴리고 트리에 포커스를 준다. 열린 파일이 없거나 트리 루트 밖이면 이유를 단 채 고를 수 없다. 같은 동작이 툴 윈도우 머리의 버튼과 액션 `fileTree.selectIn`(기본 키 없음)이다
- 5만 행 스크롤 프레임은 `apps/desktop/perf/file-tree-bench.tsx` 하네스로 잰다(만들기 · 실행 · 값의 뜻은 그 머리 주석)

M1-21 에서 정한 파일 조작(`apps/desktop/src/file-tree/file-ops.ts`, Host 는 03-architecture.md 「보안」 의 파일 조작 항목):

- 우클릭 메뉴: 새 파일… · 새 폴더… · 이름 바꾸기… · 삭제… 다음에 읽기 항목과 「터미널에서 열기」(그 폴더를 cwd 로 터미널 툴 윈도우에 새 탭, `terminal.create` 의 `cwd`). 새 항목은 고른 폴더(파일이면 그 부모, 빈 자리면 루트) 안에 만들고, 새 파일은 고정 탭으로 연다. 같은 동작이 액션 `fileTree.newFile` · `newFolder` · `rename`(`⇧F6`) · `delete`(macOS `⌫` · `⌦`, Win/Linux `Delete`) · `openInTerminal` 이고 키는 트리에 포커스가 있을 때만(`when = "fileTree"`) 돈다
- 이름은 대화상자로 묻는다(IntelliJ 와 같다 — 인라인 편집이 아니다). 이름 바꾸기는 확장자 앞까지 골라 둔다. `/` · `\` · `.` · `..` · 빈 이름은 받지 않는다. 같은 이름이 있으면 Host 가 아무것도 바꾸지 않고 오류 알림 「이미 있다」
- 삭제는 늘 확인을 받는다. 지울 것 아래에 미저장 탭이 있으면 확인에 그 이름을 함께 보이고, 지운 뒤 미저장이 없는 탭은 닫고 미저장 탭은 「지워짐」 배너로 남긴다(M1-13 — 저장하면 다시 만든다). 휴지통에 넣지 못한 항목(휴지통이 없는 볼륨 등)은 이유를 보이고 「영구 삭제」 를 한 번 더 확인한 뒤에만 지운다. 권한이 없어 못 지운 것은 그대로 알린다. 조작 실행 취소(`⌘Z`)는 없다(12-m1-plan §3)
- 행을 끌어 폴더 위(파일 위면 그 부모, 빈 자리면 루트)에 놓으면 옮기고, `⌥` 를 누른 채 놓으면 복사한다(떼는 순간의 `⌥` 가 정한다). 4px 넘게 움직여야 끌기가 시작되고, 놓을 폴더의 행에 테두리가 보이며 커서가 이동 · 복사를 보인다. 트리의 위 · 아래 가장자리에서는 굴린다. `Esc` · 트리 밖(창 밖)에서 떼기는 취소다. 끄는 항목 자신과 그 안에는 놓을 수 없다. 한 번에 한 항목이다(다중 선택은 아직 없다). HTML5 드래그가 아니라 포인터 이벤트로 끈다 — Finder 드롭을 받는 Tauri 드래그 드롭 처리기가 웹뷰의 HTML5 드래그 이벤트를 가로챈다(`apps/desktop/src/file-tree/tree-drag.ts` 머리 주석)
- 이름 바꾸기 · 이동은 열린 탭이 따라간다: 문서가 새 경로로 옮겨 가 미저장 편집 · undo 기록이 남고(`documents.ts` `move`), 탭 이름이 바뀐다. 옮긴 폴더는 펼친 채로 새 자리에 나온다. 트리 · 탭은 감시 이벤트를 기다리지 않고 조작이 끝나면 곧바로 맞춘다
- Finder 에서 트리로 드롭하면 놓은 폴더로 복사한다(같은 이름은 건너뛰고 알린다, 특수 파일은 건너뛴다, 링크는 링크로). 복사는 그 프로젝트의 백그라운드 작업(상태바의 진행 · 취소)이다

| 로그 | 더블클릭 | 커밋 상세를 에디터 탭으로 |
| 로그 | 우클릭 | 체크아웃 · 브랜치/태그 생성 · cherry-pick · revert · 이 커밋으로 reset · 해시 복사 · 외부 도구로 이 리비전 열기 |
| 로그 | 그래프 레인 호버 | 해당 브랜치 경로 강조 |
| 로그 | 브랜치 라벨을 다른 브랜치 라벨/행으로 **드래그 앤 드롭** | 메뉴: 머지 · 리베이스 · 비교 (Fork/GitButler 방식) |
| 브랜치 패널 | 더블클릭 | 체크아웃 |
| 브랜치 패널 | 클릭 | 로그를 해당 브랜치로 필터 (`⌘+클릭` 다중) |

### 5.7 실행 · 터미널
- 콘솔 출력의 `파일:줄` · URL · 스택 트레이스는 클릭 가능 (`⌘+클릭` 필요 여부는 설정)
- 터미널: 선택 즉시 복사(옵션), `⌥+클릭` 커서 이동, 파일을 터미널로 드롭 → 경로 붙여넣기(그 터미널 셸의 따옴표 규칙으로 감싼다 — POSIX 셸 · fish · PowerShell 이 각각 다르다. 모르는 셸 · 아직 뜨지 않은 셸에는 따옴표가 필요 없는 경로만, 제어 문자가 든 경로는 어느 셸에도 붙이지 않고 알린다. `apps/desktop/src/terminal/terminal-drop.ts`)

## 6. 접근성 · 기타
- 모든 인터랙티브 요소 포커스 가능, 포커스 링 표시, Tab 순서 정의 (Radix 기본 활용)
- 툴 윈도우 간 이동은 키보드로 가능 (`⌘1~9`, `Esc`, `F12`)
- 색만으로 상태 구분하지 않음 (git 상태 = 색 + 문자 `M/A/D`, 프로덕션 DB = 색 + 라벨)
- 최소 창 크기 1024×640, 좁아지면 툴 윈도우 자동 축소
- 애니메이션 최소(150ms 이하), OS "동작 줄이기" 설정 존중
