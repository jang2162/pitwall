# 13. M2 (Git) 작업 분할

M2 목표: **「IntelliJ git 을 대체한다」 — 에이전트가 바꾼 것을 보고(diff · 그래프 · blame · 파일 히스토리), 골라 담아 커밋하고, 브랜치를 옮기고 합치고, 충돌을 앱 안에서 푼다.** 쓰기는 사람의 git 설정(훅 · 서명 · credential helper)을 그대로 따르는 `git` CLI 로 하고(02-tech-stack.md 「Git: gitoxide + git CLI 하이브리드」), 터미널 · 에이전트가 git 을 직접 만져도 화면이 곧바로 따라오는 것이 이 단계의 중심이다.

완료 시 할 수 있는 것(사람이 손으로 확인하는 시나리오):

1. Orca 가 만든 워크트리를 `pitwall <워크트리>` 로 열면 파일 트리 · 탭 이름이 git 상태 색 + 글자(`M` · `A` · `D` · `U` …)로 보이고, `⌘0` 커밋 툴 윈도우에 에이전트가 바꾼 파일과 diff 가 있다.
2. diff 에서 hunk 하나와 다른 hunk 의 줄 몇 개만 스테이징하고 메시지를 써 `⌘↩` 로 커밋한다. pre-commit 훅이 실패하면 그 출력이 보이고 커밋되지 않는다. amend · sign-off 가 된다.
3. `⌘9` Git 로그: 10만 커밋 저장소에서도 첫 화면이 0.5초 안에 그려지고 스크롤이 끊기지 않는다. 브랜치(여럿) · 작성자 · 기간 · 메시지(정규식) · 경로 · 해시로 거른다. 커밋을 고르면 변경 파일 · diff · 메시지 · 부모 · 브랜치/태그가 보이고 lockfile 같은 생성 파일 diff 는 접혀 있다.
4. 상태바 `⎇ main ↑1↓2` 나 `⌃⇧B` 브랜치 팝업에서 체크아웃(원격 추적 브랜치 생성 포함) · 새 브랜치 · 이름 바꾸기 · 삭제 · 머지를 하고, fetch · pull(merge/rebase) · push 를 한다. force push 는 force-with-lease 확인 뒤에만 된다.
5. 머지 · cherry-pick · pull 에서 충돌이 나면 충돌 목록 → 3-way 머지 도구에서 고쳐 해결하고, 진행 중인 작업을 계속하거나 중단한다.
6. 에디터 거터에 추가 · 수정 · 삭제 표시가 있고(저장하지 않은 편집도 따른다) 누르면 인라인 diff 와 되돌리기 · 스테이징이 뜬다. 현재 줄 인라인 blame, `⌃⌥A` blame 주석, `⌃⌥H` 파일 히스토리(이름 바뀜 추적)가 된다.
7. 터미널이나 에이전트가 `git commit` · `git checkout` · `git stash` 를 하면 트리 · 변경 목록 · 로그 · 상태바 · 거터가 곧바로 따라온다.

대상 플랫폼: macOS(개발 · 검증), Linux/Windows 는 CI 빌드 · 시험(06-roadmap.md 「결정 기록」 D38 — macOS 앱 기능을 먼저 만들고, Linux 실기 벤치마크와 Linux 전용 대응은 Linux 출시 준비로 미룬다). Linux 에서만 갈리는 동작(inotify 로 git 디렉터리 감시 등)의 실기 확인도 그때 한다.

M1 에서 된 것은 다시 계획하지 않는다 — 파일 감시 · `fs.changed`(M1-06, `.git/` 안은 걸러 「M2 몫」 으로 남겼다), 파일 트리(M1-14), 살아 있는 텍스트를 가진 문서 모델 · 외부 변경 배너(M1-13), CodeMirror 확장 조립 지점(M1-09 `apps/desktop/src/editor/extensions/index.ts`), 상태바 슬롯 · 작업 진행률 · 알림(M1-04), 툴 윈도우 자리 `commit` · `git` 과 그 키 `⌘0` · `⌘9`(M0-13 · `apps/desktop/src/layout/project-layout.ts`), 런타임 환경 · 신뢰(M1-03 · M1-05 · M1-16), 워크트리 전환 · 워크트리별 상태(M1-25), 외부 도구의 `{branch}`(git 을 실행하지 않고 `HEAD` 를 읽는다, `pw_open_with::context::read_branch`), `.gitattributes` · 생성 파일 판정(M1-02, 결정 M1-D20 — `gix-attributes`), 대용량 기준(결정 M1-D9). MCP 노출 규칙(`rpc_method!` 의 `mcp: true` 를 단 것만 툴, 05-mcp.md 「툴 레지스트리」)도 그대로다. 아래 표는 그 위에 얹는 것이다.

12-m1-plan.md 「M1 에서 하지 않는 것」 표에서 M2 로 넘어온 것은 모두 아래 행에 있다: 트리의 git 상태 색 · 거터 변경 표시 · blame(M2-12 · M2-17), 레이아웃 프리셋 `⌃⌥1~3` 의 Git 리뷰(M2-21), Search Everywhere 의 브랜치 탭(결정 M1-D18 → M2-13), `.git/` 안 변경(M2-02). 10-ui.md 「S1. 웰컴 / 프로젝트 런처」 의 「브랜치는 … git 상태를 읽는 기능이 생기면 채운다」 도 M2-13 이 채운다.

### 공유 부품의 주인
