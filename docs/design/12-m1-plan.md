# 12. M1 (탐색) 작업 분할

M1 목표: **「열어서 본다」 — 프로젝트의 파일을 찾고 · 읽고 · 조금 고치고, 프로젝트 런타임 환경이 적용된 터미널에서 명령을 돌리고, 필요하면 다른 도구로 넘긴다.** Git · LSP 없이 이 흐름이 한 창에서 끝나는 상태다. 에이전트가 디스크에서 바꾼 파일이 트리 · 에디터 · 검색에 곧바로 보이는 것(F3-6)이 이 단계의 중심이다.

완료 시 할 수 있는 것(사람이 손으로 확인하는 시나리오):

1. Finder 로 띄운 앱이 떠 있을 때 터미널에서 `pitwall crates/pw-core/src/lib.rs:40:5` → 그 프로젝트 창에 탭이 열리고 커서가 40줄 5열, 구문 강조가 된 채 그 줄이 화면 안에 있다.
2. `⌘1` 파일 트리에서 폴더를 펼쳐 파일을 고르고, `⌘⇧O` 로 파일 이름을, `⌘⇧F` 로 텍스트를 찾아 결과를 누르면 그 줄로 간다. `⇧⇧` 은 파일 · 액션 · 프로젝트를 함께 찾는다.
3. 파일을 고치고 `⌘S` 로 저장한다. 다른 프로세스(에이전트)가 같은 파일을 바꾸면 미저장이 없을 때는 커서를 지킨 채 새 내용으로 바뀌고, 미저장이 있으면 배너와 [비교] 가 뜬다. 트리에도 새로 생긴 파일이 곧바로 나타난다.
4. `⌥F12` 터미널이 활성 워크트리 루트에서 열리고, 신뢰한 프로젝트에서는 `mise.toml` 이 고정한 버전이 잡힌다(`node -v` 등) — 앱을 Finder 로 띄웠어도.
5. `⌘⌥E` 가 지금 파일 · 줄을 기본 외부 도구로 연다. 설정 창에 「Orca 에서 Pitwall 열기」 안내가 있다.
6. 이미지 · Markdown 은 미리보기로, 바이너리는 hex 로, 큰 파일은 정한 기준대로(읽기 전용 · 열지 않음) 열린다. 프로젝트 없이 파일 하나만 여는 창도 있다.
7. 앱을 다시 시작하면 프로젝트마다 레이아웃과 열린 탭(워크트리별)이 돌아온다.

대상 플랫폼: macOS(개발 · 검증), Linux/Windows 는 CI 빌드 · 테스트. 단 Linux WebKitGTK 는 이 단계에서 실기로 한 번 잰다(M1-26, 06-roadmap.md 「리스크」 표의 WebKitGTK 행).

M0 에서 된 것은 다시 계획하지 않는다 — CLI · 단일 인스턴스 · 웰컴(M0-10 · M0-12), 외부 도구 레지스트리 · `⌥F1` · `⌘⌥E` · 로그인 셸 PATH 최소판(M0-16), dockview 레이아웃 · 테마(M0-11), 키맵 엔진 · 액션 찾기 · 툴 윈도우 단축키(M0-13). 아래 표는 그 위에 남은 것이다.

## 4. 착수 전 준비물 · 결정

### 준비물

- Linux 실기 한 대(GPU 가 있는 데스크톱, X11 · Wayland 중 하나 이상) — M1-26. CI 러너에는 GPU 가 없어 WebGL 이 소프트웨어로 떨어지므로 WebKitGTK 의 실제 성능을 재지 못한다

- Linguist 데이터 버전(태그) 하나 — M1-02. v9.7.0 으로 정했다(`crates/pw-lang/linguist/VERSION`)
