# 18. M7 (원격) 작업 분할

M7 목표: **「원격 머신의 체크아웃을 로컬처럼 연다」 — Desktop 이 SSH 로 원격 머신에 Desktop 과 판이 같은 Relay(`pitwall-relay`)를 설치하고 붙어, 같은 저장소의 로컬 · 원격 체크아웃을 프로젝트 하나 안에서 고르며(D57), 원격 체크아웃의 파일 · 편집 · git · 터미널 · 실행 · LSP 를 로컬과 같은 화면으로 쓴다. 연결이 끊겨도 원격의 실행 · 터미널은 살아 있고 다시 붙으면 이어 보며, 미저장 편집은 Desktop 에 남는다. 코드는 커밋으로만, origin 을 거치지 않고 체크아웃 사이를 건넌다. 에이전트는 같은 툴에 `checkout` 을 실어 다른 머신을 겨누되 머신마다 세션에 한 번 승인을 지난다.** 원격 기능은 새 기능이 아니라 이미 있는 Host RPC 를 다른 머신의 Host 로 보내는 것이다(03-architecture.md 「전체 구조」 — UI · MCP 는 Host 가 로컬인지 원격인지 모른다). M7 이 새로 만드는 것은 그 길(`pw-link` · Relay), 그 길 위의 수명(끊김 · 다시 붙기), Desktop 만 아는 묶음, 그리고 머신 사이를 건너는 두 가지(커밋 보내기 · 포트 포워딩)다.

이 문서는 **확정판**이다(2026-11-21 — 계획 리뷰(`.superpowers/handoff/reports/m7-plan-review-report.md` — 막는 것 3 · 고쳐야 하는 것 11 · 권고 6)와 재리뷰(`m7-plan-rereview-report.md` — 막는 것 2 · 고쳐야 하는 것 9 · 권고 4)를 반영했고, 사람에게 물은 결정 열셋(M7-D1 ~ D13 — 「4. 착수 전 준비물 · 결정」)을 모두 사람이 권고안대로 정했으며(D10 은 ④, 나머지 ①), 메인 판정 M7-P1 ~ P20 도 리뷰를 지나 확정이다. 앞서 사람이 정한 것(D57 의 ① ~ ⑤ · D59 · D61 · D47 · D42 · D43 · D56, 08-remote-mobile.md 의 Noise XX · 기기 키 · 페어링 코드)은 다시 묻지 않았다). 미정 결정은 없다 — 각 행은 자기 선행이 병합되면 바로 시작할 수 있다(「2. 순서」).

완료 시 할 수 있는 것(사람이 손으로 확인하는 시나리오 — 1 ~ 7 은 「원격 선」 까지, 8 ~ 10 은 「에이전트 선」 까지, 11 · 12 는 그 뒤. 「선」 은 결정 M7-D1):

1. 웰컴 창 「원격 호스트 추가…」 에서 `~/.ssh/config` 의 호스트 `mini` 를 고르면, 처음 붙는 호스트면 ssh 가 묻는 호스트 키 지문이 창의 확인 다이얼로그로 뜨고([취소] 가 처음 포커스), 허용하면 Desktop 이 원격 OS · 아키텍처를 보고 같은 판의 Relay 를 올려 띄운다. 진단 칸에 SSH → 설치 → 데몬 → 핸드셰이크 단계가 차례로 찍힌다. 같은 호스트에 다시 붙으면 설치 단계는 「이미 있음」 이다(M7-05 · M7-06 · M7-08).
2. 원격 호스트에서 `~/work/pitwall` 을 골라 프로젝트를 만들면 원격만 있는 프로젝트의 창이 열린다 — 타이틀바 · 상태바에 `mini`, 파일 트리 · 검색 · git 그래프 · LSP 진단이 원격의 것이다. 처음 열 때 그 머신 기준으로 신뢰를 묻는다(M7-10 · M7-11 · M7-12).
3. 로컬 `~/IdeaProjects/pitwall` 을 「체크아웃 추가」 로 같은 프로젝트에 넣으면 브랜치 팝업의 체크아웃 목록에 「이 Mac」 과 `mini` 가 머신별로 나온다. 로컬 체크아웃을 활성으로 둔 채 `mini` 의 체크아웃을 대상으로 터미널과 실행 구성을 열면 탭 머리에 `mini` 표지가 붙고, 활성 체크아웃을 바꿔도 그 탭이 남는다(M7-11 · M7-14).
4. 로컬에서 커밋 둘을 만들고 「보내기 → mini」 하면 origin 에 아무것도 가지 않고(`git ls-remote origin` 그대로) `mini` 의 체크아웃이 그 브랜치 · 그 커밋이 된다. 알림의 [거기서 실행] 이 그 체크아웃의 실행 선택기를 연다. `mini` 쪽에 따로 커밋을 하나 더 두고 다시 보내면 「갈라짐 — 아무것도 바꾸지 않았다」 와 받은 커밋의 전용 ref 가 보인다(M7-16 · M7-17).
5. `mini` 에서 dev 서버를 띄운 채 Wi-Fi 를 끊으면 그 머신의 탭이 읽기 전용 표시로 바뀌고 미저장 편집은 그대로 남는다. 다시 붙으면 dev 서버의 출력이 끊긴 사이 것까지 이어지고, 원격 파일이 그사이 바뀐 문서는 「디스크에서 바뀜」 배너가 뜬다. 창을 닫을 때 [두고 닫기] 를 고르면 다음에 열 때 그 터미널 · 실행에 다시 붙는다(M7-09 · M7-13).
6. 원격 터미널에서 `git push` 가 암호를 물으면 Desktop 창의 입력 다이얼로그가 뜨고, `pitwall README.md` 를 치면 Desktop 의 그 프로젝트 창에서 활성 체크아웃을 바꾸지 않고 `mini` 의 그 파일 탭이 열린다(M7-15).
7. Desktop 을 다음 판으로 올린 뒤 붙으면 새 판 Relay 가 따로 깔리고 뜬다. 옛 판에 남은 실행이 있으면 「옛 판 Relay 에 실행 1개가 남았다」 와 [옛 판 끝내기] 가 보인다. 원격의 `~/.local/share/pitwall/relay/` 에는 바이너리가 둘까지만 남는다(M7-07).
8. Claude Code 에 「이 커밋을 mini 로 보내고 거기서 테스트 돌려 줘」 라고 하면 `checkout_list` → `checkout_send` → `run_start { checkout: mini … }` → `run_logs` 로 이어지고, 첫 `checkout_send` 에서 「mini 에 쓰기 — 이 세션 동안 이 머신 허용」 이 뜬다. 허용하면 그 세션의 `mini` 쓰기 · 실행은 다시 묻지 않는다. 대상 체크아웃이 미신뢰면 매번 묻는다. 감사 로그 인자 요약에 대상 체크아웃이 든다. `pitwall tool run_start --checkout mini:~/work/pitwall --config test` 도 같다(M7-18 · M7-19).
9. `mini` 에서 도는 에이전트가 `pitwall-relay mcp` 로 붙어 `fs_write` 를 부르면 이 Mac 의 Desktop 창에 승인 다이얼로그가 뜬다(머신 이름 `mini` 와 함께). 그 세션의 `checkout` 에 「이 Mac」 을 주면 거절이다(M7-20).
10. `mini` 의 Node 프로젝트를 원격에서 디버그하면 어댑터 설치 확인 창에 머신 이름이 실리고 `mini` 에 설치된 뒤 그 줄에서 멈춘다. 실행 탭 머리의 `:5173` 을 누르면 「로컬로 포워딩」 이 생겨 이 Mac 의 브라우저로 `127.0.0.1:5173` 이 열린다. 포워딩은 `0.0.0.0` 에 열리지 않는다(`lsof`)(M7-21 · M7-22).
11. 같은 tailnet 에서 `mini` 에 SSH 없이 QUIC 로 붙는다 — SSH 로 설치한 Relay 는 설치 때 페어링이 끝나 있고, 페어링하지 않은 다른 기기는 핸드셰이크에서 거절된다. QUIC 가 막히면 SSH 로 떨어진다(M7-23 · M7-24).
12. Streamable HTTP 를 켜면 설정 창에 `http://127.0.0.1:<port>/mcp` 와 토큰이 보이고, 토큰 없는 요청 · 다른 `Origin` 은 401 · 403 이다(M7-25).

**「원격 선」**(결정 M7-D1): 사람이 SSH 로 원격 체크아웃을 쓰는 데 드는 것(**M7-01 ~ 17**) — 연결 · Relay · 묶음 · 체크아웃 고르기 · 편집 · git · 터미널 · 실행 · LSP · 끊김과 다시 붙기 · 커밋 보내기. **「에이전트 선」**: MCP 가 다른 머신을 겨누는 것과 원격 디버그 · 포트 포워딩(**M7-18 ~ 22**). 그 뒤가 직접 연결(QUIC · Noise · 페어링)과 Streamable HTTP(**M7-23 ~ 25**). 선은 순서를 막지 않는다 — 직접 연결의 틀(M7-23)은 첫 묶음 뒤부터 나란히 돈다.

대상 플랫폼: Desktop 은 macOS(개발 · 검증), Linux/Windows 는 CI 빌드 · 단위 시험(06-roadmap.md 「결정 기록」 D38). **Relay 는 macOS(arm64 · x86_64)와 Linux x86_64 · arm64(musl 정적)** 이고 Windows 원격은 M7 밖이다(결정 M7-D4). Linux Relay 는 실기 대신 CI 의 컨테이너(sshd 를 띄운 Linux 이미지에 SSH 로 설치하고 붙는 `relay-live` 잡 — M7-05)로 시험한다. Windows 는 Desktop 쪽 `pw-link` · SSH 부트스트랩의 빌드 · 단위 시험만 — 시스템 `ssh`(OpenSSH for Windows)로 붙는 실기는 Windows 출시 준비 때다.

M6 까지 된 것은 다시 계획하지 않는다 — Host 추상과 라우터(`pw_core::host` 의 `Host` · `Connection` · `Target`, `pw_core::router::HostRouter` — 연결 단위 라우팅, 「원격 Host 는 같은 메시지를 pw-link 위로 실어 나르는 것으로 같은 trait 를 구현한다」 는 머리 주석이 이미 자리를 적었다), RPC 계약(`pw-rpc` — role 메타 `Role::{Owner, Mobile, Readonly}` · 연결 범위 `ConnectionScope::{Host, Project, File, Agent}` · 스트림 credit · 취소), `Content-Length` 틀(`pw-wire` — 머리 8 KiB · 본문 64 MiB 상한), 프로젝트 레지스트리(`projects.host` 열이 이미 있고 지금은 `LOCAL_HOST` 만 쓴다)와 신뢰(`pw_core::registry::trust` — 프로젝트마다 `state.db` 의 `project_trust`), 연결 범위 판정(`scope_may_write` · `exec_grant` · `agent_grant` · `agent_run_grant`), 실행 관리자(`pw_run::runs` — 실행은 Host 의 것, `run.attach { since }` 로 다시 붙는다, 결정 M6-P1), 터미널 PTY(`pw_run` — 지금은 연결 수명), git 읽기 · 쓰기와 askpass 창 질의(`git.prompts` — Host 가 내는 스트림), 언어 서버 · 디버그 어댑터 · Mason registry 설치기(`pw-lsp` · `pw-dap` · `pw-debug` · `pw-tools`), DB 의 SSH 터널(시스템 `ssh -L` · askpass — 결정 M3-D11), MCP 세션 · 카탈로그 · 노출 · 승인 허브 · 감사(`pw_mcp` — 세션은 Host 하나에 붙는다), 계획 · 승인 해시 · 정책 자동(`pw_core::registry::plan`), CLI `pitwall tool` · 헤드리스 · 넘겨 붙기, 미저장 편집의 자리(웹뷰의 `LiveText` — 웹뷰 문서가 정본, 결정 M4-D10). 아래 표는 그 위에 얹는 것이다.

앞 계획의 「하지 않는 것」 표에서 M7 로 넘어온 것은 모두 아래 행에 있다: 프로젝트 툴의 `checkout` 입력 · `checkout_list` · `checkout_send` · 「이 세션 동안 이 머신 허용」(16-m5-plan.md — M7-18 · M7-19), Relay 의 MCP 엔드포인트 · 원격에서 온 승인 요청 전달 · Host 별 연결 풀(16-m5-plan.md — M7-18 · M7-20), Streamable HTTP(16-m5-plan.md 결정 M5-D8 — M7-25), Desktop 여럿이 붙을 때 승인 요청이 가는 곳(16 · 06 「남은 미결정 사항」 — 결정 M7-D3), 다른 머신 체크아웃의 실행 · 디버그 · 포트 포워딩 F7-11 · 실행 툴의 `checkout` 입력(17-m6-plan.md — M7-14 · M7-18 · M7-21 · M7-22), 정책 자동이 다른 머신에 가는가(17-m6-plan.md 「5」 19 — 결정 M7-D9). 16-m5-plan.md 「5」 의 23 · 28 · 29 는 이미 반영됐고 36(03 머리 그림의 Streamable HTTP)은 끝 모습이라 그대로 둔다.

## 1. 작업 목록

「결정 M7-Dn」 은 아래 「4. 착수 전 준비물 · 결정」 의 결정이다. 행의 내용은 그 결정을 따르고, 결정을 바꾸면 그 결정을 가리키는 행을 함께 고친다. 결정은 모두 확정이다(2026-11-21). 새 파일 · 타입 · 메서드 이름에 「가칭」 을 붙인 것은 그 행이 정한다. 모든 행은 자기가 바꾼 것의 03-architecture.md · 05-mcp.md · 08-remote-mobile.md 「지금 구현」 · 「아직 없다」 문장을 같은 PR 에서 고친다.

**완료 기준의 시험은 「되돌리면 실패하는 시험」 이다** — 그 행의 핵심 판정(경계 · 관문 · 상한 · 거절 · 순서)을 걷어 내거나 뒤집으면 실패하는 시험을 하나 이상 단다. 리뷰는 그 판정을 한 줄 되돌려 시험이 실패하는지 본다(M5 · M6 과 같은 방식). 웹뷰 시험(Vitest)은 0개가 돌아도 실패하지 않는다 — 완료를 보고할 때 `Tests  N passed` 줄의 수를 읽어 적는다(CONTRIBUTING.md 「명령」). 원격이 끼는 Rust 시험은 둘로 나눈다: 같은 프로세스 안의 가짜 전송(in-memory 링크 — M7-03)으로 도는 단위 시험과, 실제 `ssh` · Relay 바이너리 · Linux 컨테이너로 도는 `relay-live`(M7-05). **보안 판정은 단위 시험으로 단다** — `relay-live` 는 CI 에서만 돌아 리뷰의 「한 줄 되돌리기」 가 로컬에서 닿지 않는다.

**감사 · 로그에 원문을 남기지 않는다**(앞 계획과 같은 규칙): 링크 · Relay · 보내기의 로그와 감사 행에는 파일 내용 · 명령 원문 · env 값 · 비밀 · 암호 답 · git 묶음 바이트가 들지 않는다. 경로 · 머신 이름 · 커밋 해시 · 바이트 수 · 단계 이름만이다.

| **M7-24** | QUIC 직접 연결 · 바인딩 · 검색 · 상주 | 결정 M7-D2 권고. ① `Quic` 전송(`quinn`) — 기본 포트 7420, 그 위 Noise(M7-23) ② **바인딩** — Tailscale 인터페이스와 LAN 에만(`relay.toml [listen] interfaces`, 기본 `["tailscale", "lan"]`). 공인 주소에 열지 않는다 — `"all"` 은 명시적으로만, 켜면 Relay 로그 · Desktop 기기 화면에 경고 ③ 검색 — Tailscale 로컬 API 의 기기 목록, LAN 은 mDNS. 없으면 사람이 주소를 친다 ④ **고르기** — 직접 연결이 되면 데이터 길은 QUIC, 안 되면 SSH(08 「연결 방식」 의 순서) ⑤ **상주** — 직접 연결은 데몬이 SSH 없이 살아야 한다. 사람이 「이 머신에 상주시키기」 를 고를 때만 launchd(macOS) · systemd user(Linux) 단위를 쓴다 — 기본은 SSH 로 띄운 데몬이 유휴 규칙(M7-04 ④)까지 사는 것 ⑥ install.sh · Homebrew · apt(F9-1)는 M7 밖 — 수동 배치는 릴리스 자산을 08 의 경로 · 이름 규칙으로 **세션 키**(M7-03 리뷰 권고 3): M7-03 의 채널 바인딩은 「Relay 신원」 바인딩이지 전송 바인딩이 아니다 — 핸드셰이크 뒤 틀에 세션 키 · MAC 이 없어, 처음 붙는 호스트(`Expect::FirstContact`)에서 털린 Relay 가 다른 Relay 의 hello 를 그대로 중계하면 그 링크에 틀을 끼워 넣을 수 있다. QUIC 은 Noise(M7-23) 뒤에, 또는 핸드셰이크 해시로 묶은 세션 키 아래에서만 쓴다 **증명 전 자리**(M7-04 리뷰 권고 1): 데몬의 증명 전 연결 상한(`MAX_UNPROVEN` 16)은 첫 틀 5초 + 핸드셰이크 `dead_after` 30초 동안 자리를 쥐게 둔다 — 증명하지 못하는 상대가 자리를 되풀이해 채우면 링크 · 좁은 명령이 막힌다. QUIC 으로 열기 전에 핸드셰이크 전체 시한을 짧게(출발값 5초) 따로 두고 상대(주소)별 증명 전 자리 상한을 둔다 | M7-23 | Rust 시험: ① 바인딩 주소가 고른 인터페이스의 주소뿐(공인 주소 · `0.0.0.0` 이 기본에서 나오면 실패) ② QUIC 실패 시 SSH 로 떨어진다(가짜 전송) ③ 상주 단위 파일은 사람이 고를 때만 생긴다. `relay-live`: 컨테이너 사이 QUIC 붙기. 새 의존(`quinn` · `mdns-sd`)의 `mise run licenses` · `advisories` 통과와 판 기록 |
| **M7-25** | Streamable HTTP | D59 · 05 「전송 방식」 · 결정 M7-D11 권고. ① `pw-mcp` 에 Streamable HTTP 서버(rmcp 의 HTTP 서버 기능 — 의존 · 라이선스는 착수 때 확인, 추정) — 세션 · 승인 · 감사는 stdio 와 같은 `Session`. Desktop 과 Relay 둘 다 같은 코드 ② **기본 꺼짐**, 설정 창에서 켠다(전역 설정 `[mcp.http] enabled` · `port` — 전역에서만 읽는다) ③ **`127.0.0.1` 에만** 묶는다(`::1` 포함). **Bearer 토큰** — 켤 때 만들어 `$STATE/mcp/http-token`(Relay 는 `$STATE/relay/mcp/http-token` — M7-04 ⑦, 0600)에 두고 앱이 다시 떠도 유지, 「토큰 새로 만들기」 로 바꾼다. 비교는 상수 시간, 틀린 토큰이 잇따르면 응답을 늦춘다(여러 사용자 머신에서는 그 포트에 다른 사용자도 닿는다 — 토큰만이 막는다) ④ **`Origin` 검사** — `Origin` 머리가 있으면 `http://127.0.0.1:<port>` · `http://localhost:<port>` 만 받는다(DNS rebinding — MCP 규격의 전송 보안 권고), `Host` 머리도 같은 둘 ⑤ 설정 창에 주소 · 토큰 복사 · 클라이언트 설정 예. 토큰은 로그 · 감사에 남지 않는다 ⑥ 감사 행의 전송 칸 `http` | M7-18 | Rust 시험: ① 토큰 없음 · 틀린 토큰은 401 이고 툴이 돌지 않는다 ② 다른 `Origin` · 다른 `Host` 는 403 ③ 듣는 주소가 루프백뿐 ④ 꺼져 있으면 포트를 열지 않는다 ⑤ 로그에 토큰이 없다 ⑥ 앱을 다시 띄워도 토큰이 같다 · 새로 만들면 옛 토큰 거절 ⑦ 틀린 토큰이 잇따르면 늦춘다. 새 의존(rmcp HTTP 서버 기능과 그 전이 의존 `axum` · `hyper` · `tower`)의 `mise run licenses` · `advisories` 통과와 판 기록 |
| **M7-26** | 성능 · 가벼움 확인 | 「가벼움」 은 제품 목적이다(D56). ① **원격을 쓰지 않는 Desktop** 의 유휴 메모리 · 콜드 스타트가 M6 끝 측정과 같은 범위(`mise run perf`) — 원격 호스트가 설정돼 있어도 링크 · ssh 프로세스가 없다 ② **Relay** — 유휴 RSS(프로젝트 없음 · 프로젝트 하나 LSP 없이) · 데몬 기동 → 첫 응답 · 원격 디스크(바이너리 2판 + 상태)를 맥미니(macOS arm64)와 `relay-live` 컨테이너(Linux)에서 재서 메인 판정 M7-P13 의 출발값과 견준다 ③ **원격 편집** — 원격 탭의 타이핑 지연이 로컬 탭과 같다(문서가 웹뷰에 있다 — 키 입력이 링크를 기다리지 않는다) ④ **스트림** — 원격 git 그래프 첫 화면(10만 커밋) · 원격 파일 퍼지 검색(10만 파일)을 LAN SSH 에서 재서 보고(목표는 06 「성능 목표」 의 로컬 값 — 원격은 참고로 싣는다) ⑤ 다시 붙기 — 끊김 뒤 다시 붙어 실행 출력이 이어지기까지의 시간 | 원격 선 · 둘째 측정은 에이전트 선 뒤 | 보고서 `docs/superpowers/reports/*-m7-perf-report.md`(그때의 커밋 · 기기). ①의 값이 M6 기준선을 넘으면 실패로 보고 원인을 적는다 |

M7 이 끝났을 때 MCP 툴은 36개다: M6 의 34 + 체크아웃 2(`checkout_list` · `checkout_send`). `checkout` 은 툴이 아니라 기존 툴의 선택 입력이다(M7-18).

### 공유 부품의 주인

앞 단계와 같이 미리 정한다 — 같은 파일을 크게 건드리는 행은 같은 묶음에 두지 않았고, 여럿이 한 줄씩 더하는 곳은 아래 주인이 틀을 만들고 나머지는 그 틀에 끼운다. **표에 없는 공유 부품이 필요해지면 만들기 전에 코디네이터에게 묻는다.**

## 4. 착수 전 준비물 · 결정

### 준비물

- **실기 머신**: 맥미니(Desktop · agent-desktop)와, 맥미니에서 SSH 로 닿는 대상 — 이 MacBook(사람이 원격 로그인을 켜고 맥미니의 키를 `authorized_keys` 에 넣는다) 또는 맥미니 자신의 `ssh localhost`(다른 `PITWALL_*_DIR` — 「6」 머리. 맥미니의 원격 로그인을 켜고 맥미니 자신의 키를 `authorized_keys` 에). Relay 를 둘 폴더(`~/work` 아래)와 Node · Python 샘플 저장소, 같은 저장소의 맥미니 쪽 클론. Linux 실기 기기는 없다 — `relay-live` 로 갈음한다
- **CI**: 새 잡 `relay-live`(M7-05 — ubuntu, sshd 컨테이너 x86_64). musl 교차 빌드(`x86_64-unknown-linux-musl` · `aarch64-unknown-linux-musl`) 툴체인을 `mise.toml` · `rust-toolchain` 에 고정
- **새 의존과 라이선스**(CONTRIBUTING.md 「의존성과 라이선스」): QUIC(`quinn` — MIT/Apache-2.0, 추정), Noise(`snow` — Apache-2.0/MIT, 추정), Ed25519(`ed25519-dalek` — BSD-3-Clause, 추정 — 결정 M7-D13 ① 이면 원격 선(M7-03)에서 본다), mDNS(`mdns-sd` — Apache-2.0/MIT, 추정), Streamable HTTP(rmcp 의 HTTP 서버 기능과 그 전이 의존 `axum` · `hyper` — MIT, 추정). 이 계획은 라이선스를 열어 보지 않았다 — 각 행이 착수 때 `mise run licenses` 로 확인하고 판을 적는다. 시스템 `ssh` 는 의존이 아니다(D47 의 터널과 같다)
- **SSH 동작 확인**: `SSH_ASKPASS_REQUIRE=force` 와 `SSH_ASKPASS_PROMPT=confirm`(호스트 키 확인)의 동작을 macOS 기본 OpenSSH 와 Linux OpenSSH 판에서 M7-06 이 확인하고 판을 적는다(추정 — OpenSSH 8.4 이상의 기능으로 알고 있다)
- **릴리스 서명**: Relay 매니페스트를 updater 운영 키로 서명하는 잡(M7-05)이 02 「배포 · 업데이트」 의 「운영 키 Secret 을 참조하는 잡은 그 하나뿐」 규칙과 맞는지 — 같은 `sign-updater` 잡에 단계를 더하는 것으로 본다(추정). 실기 전에 preview 판 둘이 매니페스트와 함께 나와 있어야 한다
- **사람 확인 한 번씩**: 「6. 실기 확인 시나리오」 — 맥미니의 Desktop 과 대상 머신의 Relay

## 6. 실기 확인 시나리오 (맥미니 Desktop · SSH 로 닿는 대상 머신의 Relay)

계획 끝에 둔다 — 원격 선이 병합된 뒤 1 ~ 8, 에이전트 선 뒤 9 ~ 12, M7 끝에 13 ~ 15 를 확인하고 보고서(`~/pitwall-e2e/m7-e2e-<n>-report.md`)를 남긴다. 각 단계는 화면 · `ps` · 감사 로그 · git 가운데 무엇으로 확인하는지 함께 적는다.

**Desktop 은 맥미니에서 CI 가 낸 preview 릴리스 번들(서명 매니페스트가 있는 판)로 띄우고 agent-desktop 으로 다룬다** — 워크트리에서 만든 release 번들은 운영 키로 서명한 매니페스트가 없어 Relay 를 깔지 못한다(M7-05 ②). 8 의 판 바꾸기는 연속한 preview 판 둘로 한다(pid 로 고른다 — AGENTS.md 「데스크톱 앱은 이름이 아니라 pid 로」, 화면 잠금을 먼저 본다). **원격(Relay) 대상은 맥미니에서 SSH 로 닿는 머신**이고 아래에서 별명은 `target` 이다. 둘 가운데 하나를 쓴다:

- **① 이 MacBook** — 사람이 원격 로그인(시스템 설정 「공유」)을 켜고 맥미니의 키를 이 MacBook 의 `authorized_keys` 에 넣는다. 이 MacBook 의 화면은 건드리지 않는다 — 상태는 맥미니에서 `ssh target` 으로 본다. 실제 원격(다른 머신 · 다른 네트워크 경로)과 가장 같다
- **② 맥미니 자신의 `ssh localhost`** — 다른 `PITWALL_*_DIR` 로 Relay 를 띄운다: `~/.ssh/config` 의 그 호스트 항목에 `SetEnv PITWALL_CONFIG_DIR=… PITWALL_DATA_DIR=… PITWALL_STATE_DIR=… PITWALL_CACHE_DIR=…` 를 두고, sshd 에 `AcceptEnv PITWALL_*` 를 사람이 더한다(macOS 기본 sshd 는 `LANG LC_*` 만 받는다). 다른 macOS 사용자 계정으로 붙는 길도 있다 — 홈과 uid 가 갈라져 실제 원격과 더 같다
  - **B2 를 고친 뒤(M7-04 ⑦) 같은 머신 갈래가 성립한다**: Relay 는 `$CONFIG` · `$DATA` · `$STATE` · `$CACHE` 아래 `relay/` 를 뿌리로 쓰므로 같은 계정의 기본 경로여도 Desktop 과 레지스트리 · 신뢰 · 감사 · MCP 소켓 · 토큰을 나누지 않는다. `PITWALL_*_DIR` 를 주면 뿌리부터 따로라 사람의 실제 Pitwall 데이터(맥미니 Desktop 의 `$DATA`)에도 닿지 않는다. 기기 키도 갈린다(Desktop 은 키체인, Relay 는 `$DATA/relay/device.key`). M7-04 ⑦ 이 병합되기 전에는 이 갈래를 쓰지 않는다
  - **이 갈래로 못 보는 것**: 같은 uid 라 데몬 소켓의 「다른 uid 거절」 은 실기로 보이지 않는다(단위 시험 몫, 다른 계정이면 보인다). 직접 연결(13)의 Tailscale · LAN 바인딩. 같은 체크아웃 폴더를 로컬 · 원격으로 두 번 쓰지 않는다 — 원격 쪽은 다른 클론 폴더다. `~/.local/bin/pitwall` 링크(M7-P12)는 고르지 않는다 — 맥미니 Desktop 의 「Shell 명령 설치」 와 겹친다. 같은 계정이면 Relay 터미널의 `pitwall` 은 Desktop CLI 를 부른다 — 열기 요청은 `pitwall-relay open` 으로 본다. 같은 계정이면 에이전트 설정(`~/.claude.json`)도 Desktop 과 나눈다 — 10 의 에이전트는 아래 꼴로만 Relay 에 붙는다
- **Linux 원격은 실기 기기가 없어 「못 봄」** 이다 — `relay-live` CI(M7-05)의 실행 개수로 갈음해 보고서에 적는다

1. **설치 · 호스트 키 · 페어링**: 맥미니의 `~/.ssh/known_hosts` 에서 `target` 항목을 잠시 뺀 뒤(끝나고 되돌린다) 「원격 호스트 추가」 → 지문 확인 다이얼로그(처음 포커스 [취소]) → 허용 → 진단 단계 넷 → `ssh target ls <Relay $DATA>/relay/` 에 판 하나 · 0700, 페어링 표에 맥미니 Desktop 키 하나(`pitwall-relay status --json`). `target` 에서 `pitwall-relay proxy` 를 손으로 띄워 RPC 를 보내면 role 이 없어 거절된다(결정 M7-D13). 같은 자리에서 `pitwall-relay status --json` 은 답한다(좁은 명령 — RPC · role 없이)(화면 · SSH)
2. **원격만 있는 프로젝트**: `target` 의 `~/work/<샘플>` 로 프로젝트 → 신뢰 질문(머신 이름) → 파일 트리 · 검색 · git 그래프 · LSP 진단 → 타이틀바 · 상태바 머신 표지(화면)
3. **체크아웃 추가 · 탭**: 맥미니의 클론을 더함 → 체크아웃 목록 두 머신 → 맥미니 체크아웃이 활성인 채 `target` 대상 터미널 · 실행 → 탭 머리 표지, 활성을 바꿔도 남음 → 공통 커밋 없는 폴더 · `target` 의 두 번째 클론을 더하면 거절(화면)
4. **보내기 · 멈춤**: 맥미니에서 커밋 둘 → 보내기 → `ssh target git -C … log` · `status`, 맥미니에서 `git ls-remote origin` 이 그대로 → `target` 에 따로 커밋을 두고 다시 보내기 → 「갈라짐」 · `target` 브랜치 · 작업 트리 그대로 · `refs/pitwall/incoming/…` 있음 → [되돌리기](git · 화면)
5. **끊김 · 다시 붙기**: `target` 에서 dev 서버 실행 · 편집 중 미저장 → Desktop 쪽 링크의 `ssh` 프로세스(`pgrep -P <Desktop pid> ssh`)에 `kill -STOP` 30초 → `kill -CONT`(짧은 끊김 — 이어 붙기): 탭 읽기 전용 · 미저장 그대로 → 다시 붙음 → 실행 출력이 끊긴 사이 것까지(줄 번호 찍는 샘플). 그사이 맥미니에서 `ssh target` 으로 그 파일을 고쳐 두면 「디스크에서 바뀜」 배너. 같은 것을 5분(이어 붙기 시한 뒤)에도 — 터미널 · 실행이 이어짐(`ssh target ps`). 끊어 버리는 확인은 그 `ssh` 를 `kill`. 맥미니의 Wi-Fi 는 끊지 않는다 — 워커가 맥미니에 닿는 길도 끊긴다
6. **닫기 · 두고 닫기**: 창을 닫을 때 [두고 닫기] → `ssh target ps` 에 셸 · 실행이 남음 → 다시 열면 그 탭들에 다시 붙음. [끝내기] 면 `ps` 에 없음
7. **askpass · 열기**: Desktop 의 `target` 터미널 탭에서 암호가 필요한 원격으로 `git fetch`(또는 암호 있는 ssh 키) → 맥미니 창의 입력 다이얼로그(머신 이름), 답이 `target` 의 Relay `$STATE/relay/` 로그에 없음(`ssh target grep`) → 같은 터미널에서 `pitwall-relay open README.md` → 맥미니 창에 그 탭, 활성 체크아웃 그대로
8. **판 바꾸기 · 가벼움**: 다음 preview 판 Desktop 으로 붙음 → 새 판 데몬, 옛 판의 실행이 살아 있음 · 「옛 판에 1개 남음」 → [옛 판 끝내기] → `ssh target ps` · 바이너리 둘만. Relay 유휴 RSS(`ps -o rss`) · 디스크(`du`)는 `target` 에서 재서 메인 판정 M7-P13 과 견줌. 원격을 쓰지 않는 창의 Desktop 유휴 메모리는 맥미니에서 잰다 — M6 기준선도 맥미니의 것이라 같은 기기에서 견준다(M7-26)
9. **에이전트 — 다른 머신**: 맥미니(agent-desktop 의 터미널)의 Claude Code 로 「이 커밋을 target 으로 보내고 거기서 테스트 돌려 줘」 → 첫 `checkout_send` 에 머신 허용 다이얼로그 → 허용 → `run_start { checkout }` 은 묻지 않음 → 감사 로그 인자 요약에 대상 체크아웃 · 승인 방식. `auto_approve = ["write","exec"]` 를 켜 둬도 첫 호출은 묻는다. `target` 체크아웃 신뢰를 끄면 매번 묻는다. `pitwall tool run_start --checkout target:… --config test` 의 CLI 허용
10. **에이전트 — 원격 머신의 에이전트**: 맥미니에서 `ssh target 'claude -p --strict-mcp-config --mcp-config <pitwall-relay mcp 만 든 파일> …'` 로(화면 없이 — ② 갈래에서 같은 계정이면 필수) 그 머신의 `pitwall-relay mcp` 에 붙인 에이전트가 `fs_write` → 맥미니 Desktop 창에 「target 의 에이전트」 승인 → 허용 → `target` 의 `$STATE/relay/mcp/audit.db` 에 행 · 맥미니 「에이전트 활동」 의 target 칸에 보임. 그 세션의 `checkout` 에 맥미니를 주면 거절. Desktop 을 끈 채 같은 호출을 하면 `write` 가 거절된다(결정 M7-D10 ④)
11. **원격 디버그**: `target` 의 Node 샘플에 브레이크포인트 → 어댑터 설치 확인(머신 이름) → `target` 에 설치(`ssh target ls` 그 머신의 `$DATA/relay/tools/`) → 멈춤 · 변수 · 콘솔
12. **포트 포워딩**: `target` dev 서버의 `:5173` → 「로컬로 포워딩」 → 맥미니 브라우저 백그라운드 탭(또는 `curl`)으로 `127.0.0.1:5173` → 맥미니 `lsof -nP -iTCP:5173 -sTCP:LISTEN` 이 `127.0.0.1` · `::1` 뿐. 설정에 `local_host = "0.0.0.0"` 을 넣으면 열지 않고 경고. ② 갈래면 원격 dev 서버도 맥미니라 로컬 포트를 다른 수로 고른다
13. **직접 연결**: 대상이 이 MacBook(①)이고 둘이 같은 tailnet 일 때만 — QUIC 로 붙음(연결 진단의 전송 표시) → `ssh target lsof` 로 7420 이 Tailscale · LAN 주소에만 → 맥미니 기기 화면에서 해제 → 곧바로 끊김. QUIC 포트를 막으면 SSH 로 떨어짐. `localhost`(②)이거나 같은 tailnet 이 아니면 「못 봄」
