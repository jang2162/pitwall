## F2. 파일로 앱 실행 → 프로젝트 찾기/생성

**흐름**
```
pitwall <path>[:line[:col]]
   │
   ├─ 레지스트리에 path를 포함하는 프로젝트 존재? ──yes──▶ 해당 창 포커스 + 파일 열기(라인 이동)
   │                                    (여러 개면 가장 깊은 루트 우선)
   └─ no ──▶ 커맨드 팔레트(상단) "프로젝트 찾기" 모드
              ├─ 후보 1: 가장 가까운 VCS 루트 (.git)
              ├─ 후보 2: 빌드 파일이 있는 상위 폴더들 (package.json, Cargo.toml, build.gradle(.kts), pom.xml, go.mod, pyproject.toml ...)
              ├─ 후보 3: 기존 프로젝트에 "폴더 추가"(멀티 루트, P2)
              ├─ "폴더 직접 선택..." (OS 폴더 다이얼로그)
              └─ "프로젝트 없이 파일만 열기" (단일 파일 뷰어 창)
              ▼ 선택
           프로젝트 생성 → F1-4 자동 감지 결과를 체크리스트로 제시 → 파일 열기
```

| ID | 기능 | 우선 |
|---|---|---|
| F2-1 | CLI `pitwall` 설치 (앱 메뉴에서 PATH에 심링크) | P0 |
| F2-2 | 단일 인스턴스 전달 + `path:line:col` 파싱 | P0 |
| F2-3 | OS 파일 연결 (Open With), `pitwall://open?path=` 딥링크 | P1 |
| F2-4 | 루트 후보 추천 + 생성 시 자동 감지 체크리스트 | P0 (추천) / P1 (체크리스트) |


### Orca 연동 범위 (D5)

**양방향 열기, 터미널 명령 방식까지만** 지원한다. worktree 연계 · 에이전트 상태 공유 같은 깊은 연동은 하지 않는다.

| 방향 | 방식 |
|---|---|
| Pitwall → Orca | 외부 도구 레지스트리의 명령 템플릿 실행 (`{project_root}` 등 변수 치환) |
| Orca → Pitwall | Orca 설정 → 앱 추가: 메뉴 라벨 `Pitwall`, Terminal 명령 `pitwall` → Orca가 경로를 넘겨 실행하면 F2 흐름(프로젝트 찾기/생성)으로 처리 |

- `pitwall` CLI는 디렉터리 · 파일 · `path:line[:col]` 인자를 모두 받는다 (F2-2)
- CLI 설치 경로: macOS `/usr/local/bin/pitwall` (앱 메뉴 "Shell 명령 설치"), Orca가 PATH를 못 찾는 경우를 위해 절대 경로도 안내

## F12. 모바일 컴패니언 — **보류**

모바일에서 확인할 정보가 아직 구체적이지 않아 **MVP 및 현재 로드맵에서 제외**한다 (D13).
- 08 §6의 내용은 향후 검토용 초안으로만 유지
- 다만 모바일을 나중에 붙일 수 있도록 다음 구조는 유지: 전송 독립 RPC, 메서드별 role 메타데이터(`readonly` 등), `pw-link` 기기 페어링
- 재검토 시점: M7(원격) 완료 후, 실제로 "자리 비운 동안 확인하고 싶은 정보"가 쌓였을 때
