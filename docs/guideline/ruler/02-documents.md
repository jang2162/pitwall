# 지침 문서를 어디에 두는가

## `.ruler/` 에는 매 턴 필요한 것만 둔다

ruler 는 `.ruler/` 아래 `.md` 를 `skills/`·`agents/` 만 빼고 **전부** 이어붙여 매 세션 주입한다. 파일을 빼는 설정은 없다.

| 언제 필요한가 | 둘 곳 |
| --- | --- |
| 매 턴 | `.ruler/*.md` |
| 특정 작업을 시작할 때의 절차 | `.ruler/skills/` |
| 특정 주제를 다룰 때 | `.ruler/` 밖(`docs/` 등)에 두고 `.ruler/` 에 색인 |
| 특정 디렉터리에서만 | 그 디렉터리의 `.ruler/`(「nested 모드」) |

- **Why:** 한 번 쓰는 참조가 모든 작업의 컨텍스트를 차지하고, 매 턴 지켜야 할 규칙이 그 속에 묻힌다. `.ruler/` 에 README 나 메모를 두어도 똑같이 이어붙여진다.
- **How to apply:** 새 문서를 쓰기 전에 「이 규칙을 모르고 지나쳐 사고가 나는 순간이 아무 작업에서나 오는가」 를 묻는다. 아니면 `.ruler/` 밖에 둔다. apply 뒤 `wc -c AGENTS.md` 로 늘어난 양을 본다.

## 색인은 파일 목록이 아니라 「언제 읽는가」 로 쓴다

`.ruler/` 밖에 둔 문서는 `.ruler/` 의 색인으로만 닿는다.

```markdown
| 언제 | 읽을 파일 |
| --- | --- |
| 결제 모듈의 환불 흐름을 고칠 때 | `docs/payment-refund.md` |
```

- **Why:** 에이전트는 파일 이름만 보고 지금 작업에 필요한지 판단하지 못한다. 목록만 있는 색인은 읽히지 않는다.
- **How to apply:**
  - 「언제」 는 「~할 때」 로 끝나는 작업 시점으로 쓴다. 경로는 저장소 루트 기준.
  - 프로젝트가 직접 쓰는 색인은 `.ruler/90-reference.md` 한 곳에 둔다. `.ruler/<스택>/99-reference.md` 는 `guideline` CLI 가 쓰는 스택 색인이라 섞지 않는다.
  - `docs/guideline/` 은 guideline 사본 자리다. 직접 쓰는 문서를 거기 두지 않는다.
