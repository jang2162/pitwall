# 워크트리를 만들 때

## 워크트리는 저장소 안에 만들고, 하나의 작업이 하나를 갖는다

- **위치**: 저장소 루트 하위의 `.worktrees/<브랜치-슬러그>/`(gitignore). 저장소 바깥이나 임의 경로에 만들지 않는다 — 다른 에이전트가 찾지 못한다.
- **브랜치**: 워크트리를 만들 때 **새 브랜치를 함께 만든다.** 이미 다른 워크트리가 체크아웃한 브랜치는 git 이 거부한다.
  ```bash
  git worktree add -b feat/<작업명> .worktrees/feat-<작업명>
  ```
  기준 브랜치를 명시해야 하면 마지막 인자로 준다. 기본은 현재 `HEAD` 다.
- **하나의 작업 = 하나의 워크트리.** 여러 작업을 한 워크트리에서 브랜치 갈아타며 처리하지 않는다.
- **작업 전 확인**: `git worktree list` 로 같은 작업의 워크트리가 이미 있는지 본다. 있으면 새로 만들지 말고 그것을 쓴다.
- **생성 직후 런타임과 의존성을 맞춘다.** `post-checkout` 훅은 새 워크트리에서 자동으로 돌지 않을 수 있다. 빌드·테스트 전에 워크트리 안에서 직접 실행한다 — **런타임 버전을 먼저** 맞추고 그 다음에 의존성을 설치한다. 순서가 바뀌면 엉뚱한 런타임으로 의존성이 깔린다.
- **정리**: 작업이 끝나 병합·폐기되면 `git worktree remove` 로 지운다. 디렉터리를 `rm -rf` 로 지웠다면 `git worktree prune` 을 함께 돌린다. 컨테이너·볼륨을 띄운 워크트리는 **지우기 전에 그것부터 정리한다** — 컨테이너만 내리는 명령은 named volume 을 남기므로, 워크트리를 지우면 볼륨이 고아로 쌓인다.
