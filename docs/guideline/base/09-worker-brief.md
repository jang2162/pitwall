# 워커에게 브리프를 보낼 때

## 브리프에는 「됐다/안 됐다」가 아니라 진단을 요구한다

- **무엇이 어떤 값으로 관찰됐고 원인이 무엇인지까지 적게 한다.** 현상만 받으면 원인 파악을 메인 세션이 다시 하게 되고, 그러면 위임한 의미가 없다.
- **수정의 구분력(= 그 수정을 되돌리면 새 테스트가 실제로 깨지는가)은 워커가 실증하고 복구한다.** 프로덕션 코드를 되돌려 새 테스트가 *실제로* 실패하는지 확인한 뒤 복구하고, 마지막에 `git status` 로 워크트리가 깨끗한지 확인하게 한다.
- **「실패하지 않으면 덮지 말고 그렇다고 보고하라」를 브리프에 명시한다.** 부정적 결과를 보고해도 된다는 허용이 정직한 보고를 만든다.
- **Why:** 구분력을 메인 세션이 다시 실증하는 방식도 써 봤으나, 재실증이 워커·리뷰어의 보고를 뒤집는 일은 일어나지 않았고 반대로 메인 세션이 최상위와 워크트리를 착각하는 사고가 났다. 브리프에 복구를 명시하면 워커도 작업 트리를 오염시키지 않는다.

## 「보냈다」는 「상대가 받았다」가 아니다 — 눈으로 확인하기 전에 대기로 넘어가지 않는다

브리프를 주입하는 명령이 성공을 반환해도 워커가 실행됐다는 보장은 없다.

- **Why:** 성공 응답은 **터미널에 바이트를 썼다**는 뜻이지 상대 TUI 가 그 입력을 제출했다는 뜻이 아니다. 시작 화면을 그리는 중에 여러 줄 브리프가 들어가면 마지막 Enter 가 제출이 아니라 **줄바꿈으로 흡수된다.** 그러면 브리프는 입력창에 텍스트로 남고 워커는 아무것도 하지 않는데, 코디네이터는 이미 대기에 들어가 있어 **타임아웃이 되어서야** 방치를 알게 된다. 타이밍 레이스라 같은 명령이 어떤 때는 되고 어떤 때는 안 된다.
- **How to apply:**
  - **미제출은 아래 확인으로 막는 것이지 타이밍을 벌려서 막는 것이 아니다.** 「생성과 주입 사이를 벌리면 되겠지」로 도구의 기본 경로를 벗어나 조립하지 않는다 — 벌린 창이 **그 도구의 다른 게이트에 걸려** 붙기 자체가 실패하는 경우가 있다. 어느 경로로 띄우는지는 그 도구의 스택 지침이 정한다.
  - **주입 직후 터미널을 읽고 입력창이 비었는지 확인한다.** 입력창은 아래쪽 구분선 사이에 끼인 프롬프트 줄 하나이고, 실무적으로는 **마지막 프롬프트 줄**을 보면 된다. 비어 있으면 제출된 것이고, 텍스트가 남아 있으면 미제출이다.
  - **빈 입력창 하나만으로 제출됐다고 판정하지 않는다.** 브리프가 **한 번도 들어가지 않은** 터미널도 입력창은 비어 있다 — 주입 자체가 닿지 않았으면 두 상태가 화면에서 똑같다. 에이전트 화면의 작업 표시(진행 중 표시, 컨텍스트 사용량)를 함께 보고, 사용량이 0 이고 작업 표시가 없으면 시작하지 않은 것으로 본다. 도구가 디스패치 상태(주입이 받아들여졌는지)를 돌려주면 그것도 본다.
  - **앞쪽의 프롬프트 줄들은 제출된 히스토리이므로 텍스트가 딸려 있어도 정상이다.** 「텍스트 딸린 프롬프트 줄이 하나라도 있으면 미제출」로 읽으면 스크롤백이 쌓인 터미널마다 거짓 양성이 난다. 같은 이유로 **화면 어딘가에 브리프 문장이 보이는 것도 신호가 아니다.**
  - **끝의 몇 줄만 잘라 보지 않는다** — 입력창 아래에 상태 표시줄이 여러 줄 더 붙어서 프롬프트 줄이 통째로 잘려 나간다.
  - 미제출이면 엔터만 보내 제출시키고, 다시 읽어 확인한 뒤에 대기로 넘어간다.
  - **워커를 여러 개 띄웠으면 하나도 빠짐없이 전부 확인한다** — 앞의 워커가 잘 떴다고 뒤의 워커도 떴다는 근거가 되지 않는다.

## 브리프에 「다른 에이전트를 띄우지 않고 `git stash` 를 쓰지 않는다」를 적는다

워커는 서브에이전트·포크·백그라운드 에이전트를 띄우지 않는다. `git stash` 도 쓰지 않는다.

- **Why:** 둘 다 워커 입장에서는 합리적인 선택이라 금지를 적지 않으면 실제로 일어난다.
  - 워커가 스스로 띄운 리뷰어는 메인 세션이 따로 띄우는 리뷰와 겹쳐 리뷰 자리가 두 번 든다. 워커가 띄운 에이전트의 컨텍스트는 메인 세션에서 보이지 않아 판정 근거로도 쓸 수 없다.
  - stash 스택은 저장소의 모든 워크트리가 함께 쓴다. 워커의 `stash pop` 이 다른 세션이 넣어 둔 변경을 꺼내 오거나, 워커의 변경이 남의 스택에 남는다.
- **How to apply:**
  - 금지를 브리프나 브리프가 가리키는 공통 계약에 적는다. 여러 태스크를 돌릴 때는 공통 계약 한 곳에 두고 브리프마다 그것을 가리킨다.
  - 작업을 잠시 치워야 하면 임시 WIP 커밋을 쓰게 한다.
  - 수정의 구분력을 실증할 때도 stash 로 되돌리지 않는다 — 파일을 직접 되돌리고 복구한 뒤 `git status` 로 깨끗한지 본다.

## 병합 전에 `git diff --name-only` 를 브리프의 파일 목록과 대조한다

- **Why:** 브리프가 「이 파일들만 건드린다」로 경계를 그어도 **워커는 그 경계 밖 파일을 고치고 자기 파일 하나를 빼먹은 채 「목록대로 했다」고 보고한다.** 보고문은 브리프를 그대로 되읊으므로 **보고만 읽어서는 드러나지 않는다.**
- **How to apply:**
  - 판정 전에 메인 세션이 `git diff --name-only <기준>..<워커브랜치>` 를 돌려 **양방향으로** 대조한다 — 목록에 없는데 바뀐 것, 목록에 있는데 안 바뀐 것 **둘 다** 본다.
  - 어긋나면 **병합하지 말고 워커에게 되돌린다.** 메인 세션이 대신 고치면 「누가 무엇을 했는가」가 섞여 다음 배치의 경계도 무너진다.
  - 여럿을 병렬로 돌릴 때는 이 대조가 **충돌을 병합 전에 잡는 유일한 자리**다.
