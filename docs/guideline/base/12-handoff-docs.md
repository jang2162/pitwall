# 전달 문서

## 전달 문서는 쓰는 쪽의 `.superpowers/handoff/` 에 쓰고 절대 경로로 넘긴다

전달 문서는 에이전트 사이에서 파일 경로로 넘기는 문서다. 내려가는 브리프와 올라오는 작업 결과 보고서가 여기 든다. 파일 이름은 `<작업명>-brief.md`, `<작업명>-report.md` 로 쓴다. 쓴 쪽의 체크아웃 안 `.superpowers/handoff/` 에 두고, 받는 쪽에는 **절대 경로**를 준다. 이 디렉터리는 gitignore 다.

- **Why:** 읽으면 끝나는 문서라 커밋·병합에 끼울 이유가 없다. 다만 gitignore 된 파일은 다른 워크트리에 따라오지 않고, 받는 쪽의 작업 디렉터리는 쓴 쪽과 다르다. 상대 경로로 넘기면 받는 쪽에서 없는 파일이 된다.
- **How to apply:**
  - 경로를 넘길 때 그 경로가 누구의 체크아웃 안인지 한 줄 적는다.
  - 받는 쪽은 파일이 실제로 열리는지 먼저 확인한다. 안 열리면 경로를 지어내지 말고 보낸 쪽에 되묻는다.

## 보고서를 받아 읽기 전에는 그 워크트리를 지우지 않는다

워커가 쓴 보고서는 워커의 워크트리 안에 있다. 워크트리를 지우면 보고서도 함께 사라진다.

- **Why:** 받는 쪽이 아직 읽지 않았는데 워크트리를 정리하면 판정에 필요한 내용이 없어진다. gitignore 된 파일이라 git 에서 되살릴 수도 없다.
- **How to apply:** 판정과 병합에 필요한 내용을 읽었는지 확인한 뒤에 워크트리를 정리한다(`base` 스택 「워크트리를 지울 때」).

## 남길 판단 기록만 `docs/superpowers/reports/` 로 옮기고, 전달 문서를 인용하지 않는다

나중에 판단의 근거로 남길 내용(병합 리뷰의 판정, 이월한 결정)은 받는 쪽이 `docs/superpowers/reports/` 로 옮겨 커밋한다. 코드 주석과 다른 문서는 전달 문서를 가리키지 않는다.

- **Why:** 전달 문서는 지워지는 문서라, 가리키는 인용이 조용히 죽는다. 이력으로 남길 가치가 있는 내용만 커밋된 자리에 있어야 나중에 찾을 수 있다.
- **How to apply:** 옮길 때는 전달에 쓴 사정(브리프 문구, 경로 안내)을 걷고 판단과 근거만 남긴다.
