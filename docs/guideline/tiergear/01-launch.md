# `tiergear launch` 로 워커의 모델을 고를 때

플래그는 릴리스마다 바뀔 수 있다. 막히면 `tiergear` 를 인자 없이 실행해 사용법을 보고, tiergear README 의 CLI 절을 읽는다.

## 역할이 tier 범위를 정한다 — review 만 하한을 건다

| 역할 | 범위 | 이유 |
| --- | --- | --- |
| `review` | `--min-tier deep` | 판단이 곧 산출물이라 낮추지 않는다 |
| `implement` | 없음 | 판단기가 정한다 |
| `verify` | `--max-tier standard` | 정해진 검증을 돌리고 보고하는 일이라 비용을 묶는다 |
| `chore` | `--max-tier standard` | 정해진 패턴의 기계적 변경이라 비용을 묶는다 |

- **Why:** 판단기는 브리프 글만 본다. 리뷰 브리프는 짧고 "이 diff 를 봐 줘" 꼴이라 쉬운 일로 읽히기 쉽고, 그러면 리뷰어가 낮은 모델·effort 로 뜬다. 범위는 워커 세션 내내 지켜진다 — 하한 아래로 내려가지 않고, 막혔다고 판단돼도 상한 위로 오르지 않는다.
- **How to apply:**
  - 이 표와 다르게 띄울 때는 명령줄의 범위가 그 예외를 기록하게 둔다. 브리프에 "어렵다" 고 적어 판단기를 움직이려 하지 않는다.
  - `--agent codex` 면 범위는 시작 tier 에만 적용된다(Codex 는 세션 중 조정이 없다).

## `--worktree` 는 워커가 앉을 그 경로로, 붙이기 전에 준다

- **Why:** floor 는 워크트리 경로에 매인다. 워커 세션의 플러그인은 자기 작업 디렉터리의 floor 를 첫 프롬프트 전에 읽는다. 다른 경로를 주거나 붙인 뒤에 부르면 첫 턴이 floor 없이 판단된다.
- **How to apply:** 워크트리를 만들고 생성 직후 세팅까지 끝낸 뒤, 붙이는 명령 바로 앞에서 부른다. floor 는 24시간 유효하므로 같은 워크트리에 다시 붙일 때도 다시 부른다.

## 브리프는 옵션 뒤에 `--` 로 넘긴다

```bash
tiergear launch --worktree "$path" [--min-tier deep] -- "$brief"
```

- **Why:** tiergear 는 인자를 옵션 파서로 읽는다. 브리프가 `-` 로 시작하면(마크다운 목록 `- 항목`, frontmatter `---`) 옵션으로 읽혀 `Unknown option` 으로 실패하고, 스크립트는 경고만 남기고 역할 기본 모델로 간다 — 그 브리프에서는 판단기가 조용히 영영 안 쓰인다.
- **How to apply:** `--` 는 반드시 옵션들 **뒤에** 둔다. 앞에 두면 그 뒤의 `--min-tier` 까지 브리프 글자로 읽힌다.

## stdout 은 명령 한 줄이고, 판단 결과는 stderr 에 있다

```text
stdout: claude --model opus --effort xhigh      # effort 가 없는 모델이면 --effort 가 없다
stderr: tiergear: judged deep, applied deep      # 판단기가 아무것도 정하지 못했으면 judged none
```

- **Why:** 판단기가 실패하거나 확신이 낮아도 `launch` 는 실패하지 않고 standard 로 명령을 낸다(exit 0). 범위를 줬으면 standard 를 그 범위로 자른 값이고 floor 도 쓴다. 범위가 없으면 floor 를 쓰지 않는다. stderr 를 보지 않으면 "판단기가 고른 모델로 떴다" 고 잘못 보고하게 된다.
- **How to apply:**
  - stdout 에서 `--model`·`--effort` 값만 뽑는다. 뽑지 못했거나, 값이 `-` 로 시작하거나(`--model` 뒤 값이 비면 다음 옵션이 잡힌다), 평범한 토큰(영문·숫자·`.`·`_`·`-`·`:`·`[`·`]`)이 아니면 실패로 보고 역할 기본 모델로 간다.
  - 셸에서 출력을 단어로 자를 때는 글롭을 끈다(`set -f`). 모델 값의 `[1m]` 같은 대괄호가 현재 디렉터리의 파일 이름으로 바뀐다.
  - stderr 는 사용자에게 그대로 보이게 둔다. `judged none` 이면 그 사실과 적용된 tier 를 한 줄로 알린다. 판단기 상태는 사용자가 `tiergear stats` 로 본다.
  - 잘못된 tier 나 min > max 는 exit 2 다. 판단기를 부르기 전에 멈춘다.
  - tiergear 가 고른 모델(`fable` 등)은 역할 기본 모델의 허용 목록 검사를 거치지 않는다. 사용자의 tiergear 표에서 온 값이다.

## 스크립트에 끼웠으면 테스트가 진짜 tiergear 를 부르지 않게 한다

- **Why:** 개발자 머신에 tiergear 가 깔려 있으면 테스트가 판단기를 실제로 호출한다. 결과가 판단기에 따라 갈리고, 판단기가 외부 서비스면 테스트가 네트워크에 묶인다.
- **How to apply:**
  - 실행 파일 이름을 환경 변수로 갈아 끼울 수 있게 한다. 테스트 스위트의 기본값은 「tiergear 없음」(없는 경로)이고, tiergear 경로를 재는 테스트만 스텁을 주입한다.
  - 갈래마다 잰다: 없음(지금과 같은 인자), 있음(스텁의 `--model`·`--effort` 가 붙이는 명령에 간다), 역할별 범위 인자, `--model`·`--terminal` 이면 부르지 않음, 실패·빈 출력·이상한 토큰이면 역할 기본값, effort 없는 출력이면 `--effort` 를 넘기지 않음.
