# 훅이 부르는 툴체인

## 훅은 툴체인을 설치본으로 부른다 — `pnpx`·`pnpm dlx` 를 쓰지 않는다

`lefthook.yml` 의 `run` 은 `pnpm exec <도구>` 로 쓴다. 다른 패키지 매니저면 그 매니저의 **설치본 실행** 명령을 쓴다.

- **Why:** pnpm 7+ 에서 `pnpx` 는 `pnpm dlx` 의 별칭이라 `node_modules` 를 무시하고 레지스트리에서 **최신본**을 받아 실행한다. 그러면 훅이 도는 버전이 lockfile 이 고정한 버전과 갈리고, 사람과 시점마다 또 갈린다. pre-commit 이 포맷을 **자동 수정**하고 pre-push 가 저장소 **전체를 검사**하는 구성에서 두 훅이 다른 버전을 잡으면, 한쪽이 고친 것을 다른 쪽이 「포맷 안 됨」으로 판정해 **그 자리에서 무한 왕복**이 난다.
- **How to apply:**
  - `pnpm exec` 는 `node_modules/.bin` 만 본다. lockfile 이 도구 버전의 단일 원천이 되고, 설치가 안 됐으면 조용히 다른 버전을 쓰는 대신 exit 1 로 실패한다.
  - 두 경로가 실제로 다른 버전을 잡는지는 이렇게 잰다.
    ```bash
    pnpm exec <도구> --version   # lockfile 이 고정한 버전
    pnpx <도구> --version        # 레지스트리 최신본
    ```
  - 이 규약을 테스트로 검사한다면 **그 테스트가 훅이나 CI 에서 도는지** 확인한다. 사람이 칠 때만 도는 테스트는 잠금이 아니다.
