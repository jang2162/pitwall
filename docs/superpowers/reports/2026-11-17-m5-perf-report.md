이 문서는 잰 시점의 기록이다. 측정 방법은 `CONTRIBUTING.md` 「성능 기준선」, 목표는 `docs/design/06-roadmap.md` 「성능 목표 (검증 기준)」, 완료 기준은 `docs/design/16-m5-plan.md` 의 M5-22 행(결정 M5-D19 — 가볍게)이 정본이다. 비교 대상 M4 기준선은 [`2026-11-10-m4-perf-report.md`](2026-11-10-m4-perf-report.md) §0 · §3 ①②(빈 프로젝트, 2026-11-11 재측정)다.

**상태: 목표 안 — 넘는 항목이 없어 대응 행을 제안하지 않는다.** 콜드 스타트 442 ms(M4 482 ms 대비 −40 ms), 유휴 메모리 231.5 MB(M4 226.7 MB 대비 +4.8 MB). 다만 **OS 가 M4 와 다르다**(27.2 26B123 → 27.2.1 26B131) — 증감을 코드 차이로만 읽지 않는다(§1).

## 3. 기록만 하는 것 — CLI 벽시계 · MCP 세션 메모리

`pw-perf` 에는 이 둘의 시나리오가 없다. 코드를 고치지 않는 행이라 하네스에 더하지 않고, **스크래치 드라이버**(커밋하지 않음 — `pw-perf` 라이브러리를 링크한 작은 Rust 바이너리)로 쟀다. 드라이버는 `pw-perf` 의 회 준비를 그대로 쓴다: 임시 `PITWALL_*_DIR` 넷, 미신뢰로 등록한 빈 프로젝트(`pw_perf::register_untrusted`), 책임 프로세스를 끊은 띄우기(`pw_perf::macos::spawn_disclaimed`), `first_frame` 표시, 책임 pid 묶음의 `phys_footprint` 합, pid 로 끄기와 그 회의 웹뷰 저장소 지우기. 물려받은 `PITWALL_*` 변수는 지운다.

### ② MCP 세션 하나가 붙어 있을 때의 유휴 메모리

결과 파일: [`2026-11-17-m5-perf-mcp-idle-194120.json`](2026-11-17-m5-perf-mcp-idle-194120.json)(`mem` · `mem_long`).

세션: 번들의 `pitwall mcp --project <그 프로젝트>` 를 띄워 `initialize`(protocolVersion `2025-11-25`) → `notifications/initialized` → `tools/list` 를 보내고 stdin 을 열어 둔 채 둔다. 매번 앱 소켓에 붙었고(`mcp` 로그 `connected to the running app`), 툴 17개가 나왔고, 세션이 준비되기까지 10 – 14 ms 였다. 프록시는 보통으로 띄워 앱의 책임 pid 묶음에 들지 않는다 — 그 자신의 값은 따로 적었다.

**대조를 두었다.** 첫 프레임 10초 뒤(표본 0)에 세션을 붙이고(세션 회) 또는 아무것도 하지 않고(대조 회) 같은 시간 뒤에 다시 잰다. 회마다 앱을 새로 띄우고 둘을 번갈아 돌렸다. 대조가 없으면 아래 「가라앉음」 을 세션의 비용으로 잘못 읽는다.

**`mem` — 붙은 뒤 10초(준비 1 + 세션 5 · 대조 5):**

| | 표본 0(첫 프레임 + 10 s) | 표본 1(+ 10 s) | 회마다 표본 1 − 표본 0 |
| --- | --- | --- | --- |
| 세션 | 229.4 MB (223.9 – 287.6) | **240.3 MB** (223.8 – 244.5) | +12.4 MB (−63.9 – +13.5) |
| 대조 | 228.3 MB (224.3 – 232.1) | **204.9 MB** (200.4 – 207.0) | −23.9 MB (−25.1 – −23.0) |

**`mem_long` — 붙은 뒤 60초까지 10초마다(세션 3 · 대조 3, 준비 없음):**

| 붙은 뒤 | 0 s | 10 s | 20 s | 30 s | 40 s | 50 s | 60 s |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 세션(회 0 · 2 · 4) | 223.6 / 226.1 / 229.6 | 236.8 / 238.9 / 225.8 | 213.5 / 203.1 / 206.0 | 213.3 / 202.9 / 203.1 | 200.8 / 203.0 / 203.1 | 200.7 / 203.1 / 203.0 | **200.7 / 202.8 / 203.0** |
| 대조(회 1 · 3 · 5) | 228.4 / 226.2 / 230.5 | 212.9 / 202.0 / 206.3 | 204.9 / 202.0 / 205.7 | 202.4 / 199.6 / 203.0 | 202.4 / 199.5 / 203.0 | 202.3 / 199.5 / 202.7 | **202.2 / 199.0 / 202.7** |

읽는 법:

- **남는 증가분은 없다.** 붙은 뒤 40초부터 세션 회와 대조 회가 같은 범위다(60초 중앙값 202.8 대 202.2 MB, +0.6 MB). `pitwall` 프로세스는 세션이 붙어도 늘지 않는다 — 한 회 안에서 표본 0 대비 −0.7 – +0.1 MB 이고, 값은 세션 회 58.2 – 59.8, 대조 회 58.5 – 61.5 MB 다(회마다의 차이가 세션의 차이보다 크다). 세션 하나의 상주 비용은 **별도 프로세스인 `pitwall mcp` 프록시의 6.0 MB** 가 전부다.
- **붙은 뒤 10초의 +35 MB 는 WebKit 의 가라앉음이 늦어진 것이다.** 대조 회는 첫 프레임 10 – 20 초 사이에 WebContent 가 약 17 MB(135 → 118), GPU 가 약 6 MB(20.7 → 14.4) 줄어든다. 세션 회는 세션이 붙는 순간 상태바에 「MCP 1」 이 새로 그려져(`mcp.sessionsChanged` → `mcp.sessions` 다시 읽기, `apps/desktop/src/mcp/mcp-status.tsx`) WebContent 가 그대로 남고 GPU 가 한 번 35 – 37 MB 로 오른다(5회 중 4회, 1회는 18.6). 그 뒤 20 – 30 초 안에 대조와 같은 값으로 내려온다. 애니메이션은 없다 — 상태바 항목은 아이콘과 글 하나다.
- **10초 표본은 가라앉기 전이다.** 06 의 유휴 메모리(`pw-perf` 의 첫 프레임 10초 뒤, ①②)는 대조 회 기준으로 30초 뒤보다 약 25 MB 크다(230 → 203 MB). 판정 방법은 M4 와 같게 두었고(기준선과 비교하려면 같은 시점이어야 한다), 이 차이는 보수 쪽이다. 10초 표본이 가라앉는 도중을 잡아 한 회씩 튀는 것(§2 회 5, 이 절 `mem` 회 3)도 같은 까닭으로 본다.

  --app target/release/bundle/macos/Pitwall.app \

`pw-perf` 의 종료 코드는 0 이었다. 결과는 `target/perf/` 에서 이 폴더로 복사했다(이름에 결과 파일을 쓴 시각을 붙였다). 회마다의 표시 파일 · 앱 로그는 `target/perf/m5-22-*/run-*` · `mem-run-*` · `long-run-*` 에 있고 커밋하지 않았다.

## 5. 목표를 넘는 항목 · 대응 행

없다. 두 판정 항목이 목표 안이고, M4 기준선 대비 증가분은 콜드 스타트 −40 ms · 유휴 메모리 +4.8 MB 다. 기록 항목도 대응 행을 부르지 않는다 — MCP 세션은 앱 쪽에 남는 증가분이 없다(§3 ②).

다음 측정(묶음 7 뒤, M5 끝)에 넘기는 것:

- 같은 네 가지를 같은 방법으로 다시 잰다. MCP 세션 메모리는 **붙은 뒤 40초 이후**의 표본으로 견주고 대조 회를 함께 둔다 — 10초 표본은 가라앉기 전의 WebKit 을 잡는다(§3 ② 읽는 법).
- 묶음 7 이 세션이 붙어 있을 때 계속 그리는 화면(예: 진행 표시 · 애니메이션)을 더하면, 10초 표본의 일시적 증가가 남는 증가로 바뀌는지 본다.

## 6. 지침 · 브리프 · 계획에 비었던 곳

- **보고서 자리가 둘이다.** 브리프는 이 보고서(`docs/superpowers/reports/`, 커밋)를, 공통 계약은 `.superpowers/handoff/m5-22-report.md` 를 말한다. 측정 행은 보고서가 산출물이라 여기에 쓰고, 핸드오프 쪽에는 계약의 항목을 이 문서를 가리키며 짧게 적었다. 계약 「보고」 에 「측정 행은 산출물 보고서를 정본으로 하고 핸드오프 보고서는 그것을 가리킨다」 한 줄을 넣자.
- **`pw-perf` 에 MCP 세션 · CLI 시나리오가 없다.** M5-22 행의 기록 항목 둘은 하네스 밖에서 쟀다(§3). 둘째 측정 전에 `pw-perf` 에 `--scenario mcp-session`(세션을 붙이고 대조 회와 번갈아, 붙은 뒤 N초 표본) · `--cli <툴>`(벽시계 N회)을 더하는 행을 두면 같은 방법이 저장소에 남는다 — 이번 드라이버의 꼴이 그 출발점이다. 지금 우선순위(M5-D19)에 맞춰 행으로 둘지는 메인이 정한다.
- **`mise exec -C <폴더>` 는 cargo 의 작업 폴더도 바꾼다.** 워크트리 밖의 스크래치 크레이트를 지을 때 `mise exec -C <워크트리> -- cargo build` 는 그 크레이트가 아니라 워크트리의 작업 공간을 지었다(2.6 GB, 지웠다). `--manifest-path` 를 준다 — 지침에 넣을 만큼 흔한 일은 아니어서 기록만 한다.
